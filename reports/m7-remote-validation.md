## 连接与状态保证的范围

CometBFT → poolapp → poolbridge → 本机 zevune-pool-worker → M6 PoolStore。四个共识节点各有独立 Rust 状态进程和日志；交易及共识输入是公开数据，不向 worker 传递私钥、查看密钥、明文票据或私密见证。

Status/Info 只返回已提交状态。Preview 在副本上验证后丢弃。Finalize 保存带完整有序区块字节摘要的待提交结果，不落盘；重复调用必须字节一致，只有区块 ID 相同不足以复用结果。Commit 必须引用正确候选摘要，Rust 再验证并同步日志，Go 再比较完整返回状态；通信故障或错误确认不能当成普通交易拒绝继续运行，不自动重试未知结果。

继承真正的 Orchard 哈希、单证明及逐个授权签名校验（已锁定 Orchard 0.15.5 / FixedPostNu6_2，Rust 1.98.1，CometBFT v0.38.26）。未增加假证明开关、管理员解密权限、透明支付回退、见证服务器或新密码电路。程序 SHA-256 校验和 IPC 的请求摘要绑定不是操作系统沙箱、代码发行签名或对恶意本机管理员的防御。

## 本轮整合测试的实际含义

公开构造函数仍只支持空创世，没有发行/注资接口；非空初始票据仍仅限 M6 私有测试代码。本轮用真实证明的零金额协议交易进入非空区块，测试不是货币付款，也不是钱包体验。测试中的临时接收密钥仅在内存生成；跨测试程序传递的文件仅包含公开签名交易字节。

三个功能性 Go 整合测试（另有一个子进程辅助入口，不计功能测试）：

1. 实际 Rust 进程接受真实证明，拒绝篡改授权；Finalize 后文件长度和 Info 不变；终止持有待提交结果的 worker，重开仍是旧状态，重放得到相同结果；Commit 后重开保留状态，重复提交/重复交易拒绝，缺失日志不重新创建。
2. 四个 Go 节点进程与四个 Rust 状态进程实际通过 loopback 运行共识。真实 RPC 广播、入块、提交签名和应用状态检查；使用全新 Rust 状态进程独立重放公共块，对照已签名区块头中上一高度 AppHash；整网停止后恢复，所有节点超过停止前各账本最高高度，2 个输出承诺和 2 个已花费标识保留，重复交易拒绝。
3. 提案选择排除无效及重复交易、遵守字节预算；包含一笔有效后接无效/重复交易的区块整体拒绝，不能留下局部状态；错误查询和错误创世拒绝；直接向真实 Rust 进程提交伪造候选摘要被拒绝，随后正确 Commit 仍可成功。

这不是跨地域、独立运营者网络，也不是任意断电、恶意磁盘回滚或所有共识故障的形式化证明。全网重启是正常停止后重新启动；单 worker 中断点在 Finalize 后而非任意写入中途。M6 的同步故障注入与 M3 的其他故障测试属于独立覆盖，不能自动当作全部已在 M7 重现。
