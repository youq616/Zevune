## 已完成的本地检查

- Go 1.23.2 linux/amd64；仅记录本次工具链，不作为生产版本建议。
- 91 个顶层 Test 通过，0 失败；比 M1 增加 19 个。总数含原有 1 个跨进程辅助测试入口，另有子测试与 fuzz 种子。
- go vet、gofmt、完整 go test -race 均通过。
- 原交易解码 fuzz：3 秒配置，3,150 次执行通过；日志解码 fuzz：3 秒配置，28,056 次执行通过。短时检查不是全面漏洞检测。
- Linux 节点构建、真实 HTTP 状态查询、Ctrl+C 停止与重启通过；账本摘要与日志字节保持一致，storage.recovered 从 false 变为 true。
- 新增 -version 命令和 software_version 返回值已实际检查；初始 app hash 仍为 6eacdc87321ba9c78a1bfa9e86c6bccf73b77e6134807f217d9d26eae7b3b735。
- /readyz 仍返回 503，付款与最终确认仍为 false；非 loopback 监听继续被拒绝。

本执行环境直接 git clone 仍遇到 DNS 解析失败。运行源码从已交付快照与已授权连接器读取的 M1 文件恢复，并核对新增恢复文件的 blob 哈希；本次修改的远端哈希须在提交后再核对。最初一些本地命令因执行时限中断，随后分开运行并完成，未把中断当作通过。

## 新增覆盖

预执行不改内存/磁盘、不预占 nullifier、竞争提案、跨历史根窗口与直接 ApplyBlock 一致、无效区块整块拒绝、修改预执行描述的各个字段、修改后重新生成测试证明的交易、完整交易顺序及证明字节绑定、伪造 preview 不能绕过缺失的验证器、提交时再次验证、重复与并发提交、重启前后候选处理、写失败/短写/同步失败、上限与高度溢出、关闭后拒绝、调用方切片不被保留、已知区块摘要向量，以及没有新增 HTTP 提交入口。

接受交易的替身仍仅在测试文件中，公开校验和不被当作真实证明。

## 摘要编码基准

环境：Intel Xeon Platinum 8370C @ 2.80GHz；Linux amd64；-cpu=1；每组 -benchtime=200ms -count=3。下表为三次结果的中位数。

| 合成状态规模 | 编码器 | ns/op | B/op | allocs/op |
|---|---|---:|---:|---:|
| 1,000 个承诺 + 1,000 个 spent 标识 | M1 缓冲编码 | 623,228 | 163,984 | 23 |
| 同上 | 流式编码 | 573,696 | 33,184 | 16 |
| 10,000 个承诺 + 10,000 个 spent 标识 | M1 缓冲编码 | 8,038,345 | 2,424,984 | 27 |
| 同上 | 流式编码 | 6,533,856 | 328,096 | 16 |

在 10,000 规模这组样本中，每次摘要累计内存分配约减少 86.5%，耗时中位数约减少 18.7%。这是本执行环境的小样本观察，不是普遍加速保证。B/op 不是进程峰值内存。本基准没有证明生成、交易传播、磁盘同步、钱包识别或共识，不得换算成链上 TPS 或到账时间。
