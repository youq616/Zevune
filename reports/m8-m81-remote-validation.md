## 2. 合入的 M8 核心

钱包在本地生成种子，通过上游 ZIP32 派生密钥与接收地址。它扫描已重新验证的本地 Orchard 历史，识别自己的收款及内部找零，区分余额和已预留资产，构造真实证明与签名，并保留未确认付款的资产预留。多个已选输入的认证路径共用一次树归约，不为每个输入重复构造整个历史树；本轮没有给这项改动宣称实测加速比例。

已有私有测试完成：收到两笔各 30000 的记录，组合付款 50000、手续费 1000、找零 9000；收款人随后付款 40000；最终相关余额、发行者找零和累计费用满足测试资产总额 100000 的守恒。另测有效期、错误历史祖先、备份恢复及再次扫描。初始非零资产仍只在私有测试代码中构造，没有公开发行或任意注资接口。

原 `ZVWLT001` 快照仍为 620 字节。其固定 Argon2id 参数为 v19、m=65536 KiB、t=3、p=1；密文由上游 XChaCha20-Poly1305 处理。错误口令、修改密文、未知格式、参数及长度越界会被拒绝。未声称口令长度能保证口令强度。

## 3. 本轮新增 WalletStore 与加密待发送队列

新增 `wallet::vault::store::WalletStore`。它持有排他文件锁和只读钱包视图，不暴露内部可修改钱包或口令。`prepare_payment` 先本地构造并验证真实证明，将资产预留与完整签名交易一起写入加密记录，检查文件同步成功后才返回可供调用方广播的 Payment。

这解决了低层内存钱包依赖调用方自行保存的缺口。保证仅适用于新的 WalletStore 调用路径；原内存 Wallet API 本身没有被宣称具备相同持久化顺序。磁盘提交成功也不等于网络已经确认收款。

重开后需重新扫描可信本地历史才能返回余额或待发送交易。`pending_payment` 取回的是保存过的同一组签名交易字节和交易标识，不重新选择输入或生成第二笔付款；没有联网、自动广播、自动重试或基于网络超时释放预留的行为。已记录花费或确认高度超过有效期，才由既有同步逻辑清除相应待发送状态。

新日志 `ZVWJNL01`：72 字节文件头；每个记录 32948 字节；最多 256 条记录，总上限 8434760 字节。固定 32 KiB 加密明文同时包含旧快照及签名交易。日志标识、顺序号和前记录摘要均通过附加认证数据绑定；不是只依赖攻击者可以重算的外层校验和。打开时有界扫描校验链，只对最后记录执行口令派生与认证解密，其认证前驱摘要绑定整个历史前缀。

新 `backup_new` 创建完整加密日志副本，包含待发送交易且不覆盖旧文件。旧快照导入必须创建新文件；旧快照只有资产预留而没有签名交易时，返回明确的 MissingOutbox，不擅自释放预留。原 620 字节备份的认证语义保持兼容。

## 4. 新增真实付款恢复测试

`durable_wallet_outbox_resumes_exact_real_payment_after_lost_acknowledgement` 使用真实 Orchard 证明和签名：

1. 私有测试发行者持有 100000。向 Bob 的 WalletStore 支付 60000、找零 39000、手续费 1000。
2. Bob 构造向 Carol 支付 50000、手续费 1000 的付款。待发送交易和预留先写入加密文件。
3. 创建加密备份，释放钱包，从备份重新打开并扫描；取回的交易标识和全部字节与第一次完全一致。再次构造竞争付款被拒绝。
4. 将保存的交易提交本地真实 PoolStore 后，Bob 余额为 9000，Carol 为 50000。
5. Bob 再向 Carol 付款 4000、手续费 1000，注入“完整写入并同步后确认丢失”。API 返回 Io 错误且不返回 Payment；存储实例停止提供待发送内容或继续操作。
6. 重新打开完整日志并对账，从加密待发送队列恢复该笔交易，提交后 Bob=4000、Carol=54000、发行者找零=39000、费用=3000，总计 100000。重复花费仍被拒绝。

钱包的这一恢复场景是同一测试进程内释放对象并从磁盘重新打开，不是物理断电或任意时刻强杀验收。文件锁测试另外实际启动了独立子进程；原 M7 回归另外实际运行四个 Go 节点与对应 Rust 状态进程，但其网络交易仍为零金额。

## 5. 故障与可信边界

已测试部分写入、完整写入后确认丢失、缺失/非普通文件、长度与填充越界、旧快照导入、拒绝覆盖备份、跨进程抢占、运行中文件变化、完整旧前缀回滚，以及修改历史后重算所有外层校验和仍不能通过最终认证解密。

写入/同步失败使实例不可继续使用；不能把错误解释为磁盘上一定没有完整记录。半条记录拒绝打开，不自动截断、回退或恢复成空钱包。合法旧前缀只能在存在独立可信 StoreReceipt 时识别为回滚；没有独立检查点时，合法旧日志仍可能通过。StoreReceipt 是本地文件祖先检查点，不是区块最终性或身份认证。

文件目录、操作系统和存储设备仍需可信。Unix 创建文件模式为 0600，并检查父目录同步；Windows 检查文件同步，但未实现等效的目录同步或专门 ACL 配置。排他锁不等于恶意管理员防御，不能消除硬链接、目录替换或所有文件系统竞态。多个备份副本的锁相互独立，不是多设备并发钱包方案。

口令缓冲区在解锁对象存活期间保留，以 Zeroizing 管理；没有宣称上游全部中间副本、换页、核心转储或被攻陷设备能被完全擦除。固定记录长度不隐藏文件更新时间或记录数量，不是网络匿名保护。日志容量达到上限后拒绝继续写入，尚无压缩迁移或生产级长期存储。
