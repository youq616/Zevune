## M5：Go 调用真实 Rust 验证

新增 internal/orchardbridge，以及 Rust wire、worker 和本地进程入口。固定实验信封 ZVORLAB1 支持 2–8 个动作，最大 28,102 字节；长度、版本、标志位和重复字段在适当层检查。Go 的结构解析不冒充曲线点或证明验证。

Rust 使用上游规范字段/曲线点解析、逐个 RedPallas 花费与绑定签名验证，以及上游单证明验证器。验证参数在本地进程内复用，没有新增自制电路、假证明放行开关、透明付款回退或全网查看密钥。

Go 检查绝对程序路径与预期 SHA-256，验证握手指纹、单调请求编号及完整交易字节摘要。子进程仅通过 stdin/stdout 通信，不监听网络；请求包含公开交易数据，不包含用户私钥、查看密钥、明文票据或私密见证。程序摘要校验不是发行签名、远程证明或安全沙箱，不能抵抗恶意本机管理员。

格式正常但授权无效是普通拒绝；超时、崩溃、截断回复和编号/摘要错配是执行故障，会关闭会话而不是放行。测试还覆盖并发排队、取消、错误输出和进程回收。模拟子进程仅在 *_test.go，另有真实 Rust 程序联调，两类结果不混淆。

Authorization.CheckCommittedState 仍需调用方提供可信不可变账本快照，检查历史根、过期高度、已花费标识和重复输出；结果绑定基线高度及状态摘要。它不是落盘操作、最终确认凭证或跳过提交校验的权限。

## M6：真正 Orchard 资产树的保存与重放

新增 Rust pool 库，使用 Frontier<MerkleHashOrchard,32>，按动作顺序追加真实承诺，并维护花费标识、输出集合、最近 64 个不同已提交树根、累计费用及高度。没有把旧 Go 原型 SHA-256 树解释成 Orchard 树。

prepare 在副本上检查整个候选区块，不修改已提交状态或日志。交易仅可引用区块开始前已提交的根；同一候选区块中途产生的根不作为可信花费根。commit 检查基线、重新执行真实证明和状态验证、核对结果，再写日志并同步，成功后才推进内存。

公开的创建和打开入口只支持空创世状态，没有任意注资、代币发行或支付入口。非空初始测试承诺由私有测试路径提供，密钥和秘密票据只存在于测试进程。这不是已实现的创世发行或供应量认证。

日志使用 ZVOPOL01，持有独占文件锁，记录公开数据及完整签名交易；新建不覆盖旧文件，打开不重置损坏数据。重开时重新检查每条交易的真实签名和证明，重建 Orchard 树并核对状态转换，而不只是检查外层校验和。

已测试：A→B（含找零）、提交落盘、关闭并重开账本、B 使用实际收到的票据继续付款给 C、再次重开后状态相同；重复花费仍拒绝。也覆盖竞争候选失效、整块中途失败不留下部分更新、篡改预执行结果、损坏证明后重新计算日志校验和仍被拒绝、截断记录和容量限制。

这里 M6 的“重启恢复”具体是同一个测试进程内关闭/释放存储，再重新打开并从磁盘重建；没有声称对 M6 完成了操作系统进程强杀重启或真实断电实验。M3 的四进程故障恢复属于另一模块。

部分写入和同步失败通过 cfg(test) 故障注入验证：实例停止服务且内存不推进；若完整记录已经写出但确认丢失，重开可能恢复出该记录。调用返回失败不表示磁盘肯定没有记录，未来仍须与可信共识状态对账。

完整旧日志前缀也可能有效，校验和无法识别所有回滚。check_checkpoint 只比较调用方提供的独立可信高度/摘要，尚不是完整共识握手或轻客户端证明。容量为每块 16 笔、65,536 个承诺、10,000 条记录、64 MiB 日志；不自动删历史绕过限制。目录持久性、恶意操作系统、文件系统差异和真实断电不在已验证保证中。
