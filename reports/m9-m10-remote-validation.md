## 2. 非零金额四节点支付已经通过

`local-funding-lab` 为默认关闭的构建特性。测试创世分配总额严格为 100000、最多 16 项，校验公开资产开口、地址、金额、顺序、重复标识和固定格式。清单通过独立预期摘要绑定到 Rust 账本、Go worker 连接和 ABCI 初始化。默认 worker 不接受此测试发行路径，创世清单不能作为日后增发交易提交。

创世分配的地址、金额和资产开口是**公开实验数据**。这不是匿名发行、正式币种单位或最终主网经济规则。它没有全网解密钥匙，也不授予持有公开开口的人其他钱包的花费密钥。

`TestFundedWalletFourNodesAndRecovery` 实际执行四个 Go 共识进程和各自的 Rust 状态进程：

1. A 用真实测试资产构造多输入付款，向 B 支付 60000、手续费 1000，A 找零 39000。
2. 先保存加密资产预留及完整签名交易，创建备份，从备份恢复相同的待发送字节。
3. 通过真实节点广播，拒绝篡改交易，并定位区块实际包含情况；不把 mempool 回执当作最终确认。
4. 钱包参考账本先验证真实验证者提交签名、区块数据摘要、前状态与后续已签名头部中的应用摘要，再重放公开交易。
5. 一个验证者离线时，B 向 C 支付 40000、手续费 1000，B 找零 19000；离线节点重新加入并追赶。
6. 全部节点停止后重新启动，保留签名状态及 Orchard 日志；再次提交已花费交易被拒绝。
7. A=39000、B=19000、C=40000、累计手续费=2000，总和仍为 100000。

四个节点仍位于同一台运行器上、使用 loopback。它们不是四个独立运营主体，不是公网匿名网络。该自动化场景不等于控制台已经具备在线同步与付款接口。

## 3. 新增本地钱包控制台

`integration/orchard/src/bin/zevune-wallet-local.rs` 与 `scripts/zevune_wallet.py` 提供 create、address、backup、restore、status、prepare、pending、init-test-ledger。

前端只使用 Python 标准库。口令不回显，不能安全关闭回显时拒绝降级。口令和付款意图经有界私有 stdin 管道传给 Rust，不在后端参数或环境中传递。后端要求显式 `--no-real-funds`，拒绝交互式直接输入、未知操作、字段数量错误、截断、尾随数据和长度越界。

`prepare` 复用真实 WalletStore：加密预留及完整签名交易同步成功后，才创建签名交易输出文件。写入、导出、超时或进程中断不释放预留；pending 在重扫后导出同一组字节，不重签或自动广播。备份/恢复只创建新文件，不覆盖旧钱包。源目录、操作系统及二进制仍须可信。

`zvlab:` 为临时显示格式：上游 43 字节 Orchard 地址加本地校验和。校验和只检测输入错误，不认证交易对手，也不是主网地址协议。用户自主查询的地址、余额及文件检查点可能出现在本人终端；没有声称屏幕、Python 字符串、交换区或系统副本被完整擦除。

本地控制台**不联网、不访问 RPC、不自动广播、不验证远程最终性**。它扫描可信本地账本，不能抢占运行节点的文件锁。没有助记词、图形界面、硬件钱包、多设备协调、密码修改或生产日志压缩功能。

测试包含 3 个真正启动 Rust 操作程序的场景：格式拒绝不生成钱包；加密备份恢复及错误口令；两个真实本地付款、备份恢复相同待发送交易、找零、费用和重复花费拒绝。另有实际 Python 编码/调用真实 Rust 后端的互通测试，不是仅用 mock 代替后端。隐藏输入失败边界在 Python 单元测试中验证；没有声称自动化测试检查了所有真实终端的回显行为。

## 4. 精确授权缓存及速度边界

新增 `wire::cache::VerifiedCache`，最多缓存 64 项已完整通过真实证明及全部授权签名的公开交易。命中同时比较 SHA-256 摘要和全部字节。每次仍先进行规范解码；无导入缓存、持久化缓存、失败缓存、外部成功标记或跳过证明开关。新验证器从空缓存开始。

过期高度、可信历史根、双花、重复输出、费用累计、区块高度及原子提交均继续由状态机检查。缓存**只复用不随账本变化的密码学授权结果，不缓存当前花费许可**。重放或提交在同一验证器内可复用准确字节的成功授权；不能继续宣称所有路径都每次从头重新执行同一份证明。

测试覆盖强制摘要碰撞下仍须精确字节相同、FIFO 淘汰、重复插入、长度上限、8 线程并发；另使用真实证明验证篡改拒绝、冷启动、缓存热状态的双花、过期、错误根和区块原子性。

本地相同源码的一次样本：9166 字节交易，首次授权验证 55344 微秒；32 次相同字节复用共 11625 微秒，即平均约 363.3 微秒/次。这里只度量授权阶段，公开参数初始化不在这项计时内。没有以特定机器速度作为正确性门槛，也没有将它换算为 TPS、端到端 p95 或到账时间。

最终 Windows 四节点测试记录的两个场景样本为 13567、18986 毫秒，包含备份、完整重扫、签名头部验证和独立重放等额外工作。只有两个样本，不能视为正式支付延迟分布；也不能省略这些数字后宣称已达到 5 秒付款目标。钱包证明生成和冷启动成本仍需优化。
