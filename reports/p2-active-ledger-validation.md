## 交付行为

旧单文件在 10000 条记录处停止，离线分段备份只能保存同一份字节。本阶段增加由可信 `ZVTGEN03` 清单固定的 ActiveSegmentsV1：正常提交在下一完整帧无法装入时创建下一个 1 MiB 段，重开逐段核对物理边界与 EOF，并完整执行原有真实授权和状态规则后才返回状态。

| 项目 | LegacyJournal | ActiveSegmentsV1 |
|---|---|---|
| 新清单生成 | `generate()` 默认02，仍读取旧01 | 显式 `generate_active()` 生成03 |
| 账本 | `ZVOPOL01/02` 单文件 | `ZVOPOL03` 头文件及连续段目录 |
| IPC / 网络配置 / AppVersion | 3 / 1 / 2 | 4 / 2 / 3 |
| 记录与逻辑字节上限 | 10000 / 64 MiB | 1000000 / 1 GiB |
| 段规则 | 不适用 | 1 MiB / 最多2048段；记录不跨段 |
| 每块交易 / 累计承诺 | 16 / 65536 | 16 / 65536（不变） |

02 与03的完整清单摘要分别绑定 LAB2 付款域及初始应用状态；不提供profile覆盖、降级或数据迁移。worker/Go/ABCI/网络同步都从独立固定的清单选择匹配规则。容量查询来自同一持锁已提交摘要，含头和完整记录帧，不用目录大小代替账本状态。旧单文件检查点、复制、备份及索引接口明确拒绝活动目录，健康store不会因请求不支持的旧接口被置为不可用。

## 未完成边界与下一步

- P2仍需交易状态增长、内存与完整钱包历史成本验收；承诺/防双花集合与摘要扫描仍在内存，钱包日志256条规则不变。
- 尚无活动归档迁移、增量备份、快照导入或剪枝。旧备份功能仍只处理旧单文件；节点验证者签名状态不属于账本恢复。
- 2048是分段数量上限。当前store保留每段句柄，完整读取器还会克隆整组句柄，并保留各自的目录与genesis句柄；进程峰值可超过2048，主机文件描述符不足会明确失败。需要可信父目录、OS和文件系统；不承诺运行中抵抗绕过锁改写所有密封段。
- Windows目录持久化、真实断电/磁盘满、多机长期运行尚未验收。本机故障注入和CI不能替代这些项目。
- 网络隐私、完整在线Windows钱包、开放验证者/经济规则、签名发布及外部独立安全审计仍未完成。真实资金和公开部署仍未准入；六份历史文档缺口保留。

下一P2优先项应分别固定真实付款/承诺增长与恢复资源目标，再交付活动账本的归档恢复；保持状态验证完整，不用空块计数掩盖这些成本。
