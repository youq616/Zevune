## 已接通的功能

### P1 已有代码的本轮整合验收

`Recipient`、Rust本地后端和Python前端检查独立固定的LAB2网络身份。未知、无域旧地址或不匹配网络在签名之前拒绝；后端独立执行，不能只依靠前端过滤。无效金额、费用、到期条件和不可支付状态不会先构造昂贵的证明参数。单次预检查不成为可复用的花费许可。

网络地址校验和只检测输入错误，不认证交易对手；攻击者重新标注地址并计算校验和、完整克隆相同创世或终端被控制，均不在其防护保证内。正式网络身份与升级治理仍未完成。

### P2 新增显式钱包整理

`WalletStore::compact_copy_new`要求准确的当前源回执；不是任意祖先回执。它保留已认证快照及全部待发送签名字节，重新加密到一个新文件，不覆写、不截断、不删除源文件，不广播或重新签名，不解除付款预留。

目标文件写入、文件同步与支持平台的父目录同步之后，使用已经持有锁的文件句柄重新读取，认证解密并逐字节核对快照和outbox，解析待发送记录时仍执行原有真实授权验证；最后再次核验源文件。只有全部完成才返回新文件、新回执和交接信息。

成功后当前进程的源存储实例停用，新存储实例仍为NotSynced，必须按可信历史重新扫描才能报告余额或付款。旧文件并未被撤销，不能阻止其他副本或进程重新打开它；必须明确只使用一个活动副本。返回的源/目标回执对是本地交接记录，不是独立可验证的跨日志谱系证明。新日志需要独立保存新回执，旧回执在新文件上应被拒绝。

满256条记录的活动日志可整理成1条记录，恢复255条可追加额度；活动文件由8,434,760字节变为新文件的33,020字节。原文件仍保留，所以这不是即时释放磁盘总占用。没有提高256条容量常量，也没有扩容节点账本。

新增本地IPC操作码10与`compact`命令，严格要求两个绝对路径和显式源回执。前端在请求密码之前检查参数及目标不存在，要求明确确认；后端仍以原子仅创建方式拒绝覆盖。响应明确标记未同步，不返回余额、交易确认或新交易ID。密码只通过原隐藏输入与私有stdin传递。

## 自动化验收中的关键反例

| 验收条件 | 检查方式 |
|---|---|
| 旧祖先回执、错误源回执 | 整理被拒绝，目标不创建 |
| 目标已存在、目标为源文件或目录 | 拒绝覆盖，原字节保留 |
| 源文件损坏、实例已失效 | 拒绝整理成看似正常的新文件 |
| 目标半写入 | 返回失败，保留源文件；损坏目标不自动修复 |
| 完整写入同步后丢失确认 | 返回失败；明确允许目标已完整存在，不能假定无副本或自动重试 |
| 整理后用旧回执打开新文件 | 拒绝；新文件须使用新回执 |
| 整理后尚未扫描 | 不报告余额；目标锁有效 |
| 满容量真实待发送交易 | 通过真实加密writer填满256条，关闭重开、整理、恢复完全相同的签名字节 |
| 整理后错误网络历史 | 拒绝，目标回执及字节不变 |
| 整理后继续支付 | 确认第一笔后可产生第二笔真实付款；余额与费用相符，两笔重放均拒绝 |
| 前端绕过或伪造响应 | 直接后端操作和Python严格响应检查分别测试 |

新增5个Rust存储功能测试、1个Rust操作帧测试、6个Python测试，并扩展原真实Python/Rust联调。原`store/tests.rs`相对接续起点保持逐字节不变，已有满日志恢复和故障测试没有删除。合成响应只用于前端边界测试；真实支付流程使用实际Orchard证明、签名与验证器。
