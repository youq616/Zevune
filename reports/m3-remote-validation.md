## 本轮实现

新增 integration/cometbft 独立 Go 模块，版本 0.2.0-consensus-dev，锁定 CometBFT v0.38.26。四个真实操作系统进程在同一测试机通过 loopback TCP 通信并提交空区块。不是隐私支付网络，禁止真实资金。

实现内部 ABCI 适配：InitChain 校验、Info 已保存状态握手、空块 PrepareProposal/ProcessProposal、只暂存不落盘的 FinalizeBlock、重新验证并写日志的 Commit。当前状态查询不返回未提交结果，不声称提供证明；快照与非空投票扩展拒绝。所有交易入口继续关闭。

实现实验网络初始化、四进程启动器与停止流程。验证者密钥运行时生成，不写入源码。已有目录拒绝初始化，签名状态缺失时拒绝启动，不通过重置签名状态恢复。RPC/P2P 固定为数字 loopback 地址，没有公网 ABCI 端口。

M2 根程序继续为 0.1.2-dev，现有运行源码、协议字节与日志格式不变。未接触用户电脑，未迁移、清空其本地数据，未创建公网节点或启用付款。

## 已覆盖的回归场景

1. 应用适配：初始化约束、预执行与落盘分离、FinalizeBlock 后未 Commit 时的重启、幂等/重复请求、交易入口拒绝、当前查询、快照拒绝、并发与关闭。
2. 四进程联调：共同高度的区块哈希与应用哈希一致；按创世验证者集合验证真实提交签名；通过真实 RPC 广播的交易被拒绝。
3. 故障：一个验证者离线时另三个继续推进；两个离线时在观察窗口内停止；恢复投票门槛、滞后节点追赶、强制终止一个进程后恢复。
4. 严格全网重启：关闭所有进程后逐一读取账本，取得最高已保存高度；重新启动后每个节点都必须超过该高度至少三个区块。
5. 缺失防重复签名状态文件时拒绝启动，且不会静默重新生成。

节点测试通过测试辅助进程调用真实 devnet.Start 和 CometBFT，不是伪造的共识返回值。启动器在两平台编译通过；不冒充在用户电脑进行了人工终端 Ctrl+C 验收。

## 发现并修复的问题

首轮编译发现 CometBFT 配置字段名称不兼容，修正为 c.RPC.PprofListenAddress。该失败运行保留：34481893751。随后首次两平台完整联调通过，运行编号 34482255930。

加强整网重启断言，避免仅追到已经达成的旧高度就误判新提交成功。增加缺失签名状态的拒绝测试。

Windows 在 go mod tidy -diff 步骤报告整份 go.sum 文本变化，依赖校验值本身未变化；根 .gitattributes 未固定 go.sum 的换行，core.autocrlf 将其检出为 CRLF。失败运行保留：34483190986。新增 go.mod/go.sum 的 eol=lf 规则。另用独立本地合成文件复现修复前 CRLF、修复后 LF 的检出行为。没有修改实际依赖校验值，也没有跳过一致性检查；修复后的 Windows 完整流程已通过。

## 工具链、来源与环境边界

本执行容器的 Go 为 1.23.2，外部模块下载/原生克隆受 DNS 限制。在本容器仅做源文件语法格式检查和 Git 换行复现实验，不冒充在此编译运行 CometBFT。真正的依赖解析、编译、四进程测试及启动器构建由 GitHub Windows/Ubuntu 运行器完成，共识模块固定 Go 1.27.1。

初始 CI 在双平台测试通过后记录了规范格式的 Go 源码与完整 go.mod/go.sum；随后移除了该临时写入任务。最终共识 CI 仅 contents:read，不持久保存检出凭据，检查锁文件、不修改源码。模块完整性校验不是依赖漏洞审计。
