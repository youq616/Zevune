# Zevune · 澄隐

**开发中，仅限无价值本机测试资产，禁止真实资金。尚未完成生产主网、网络匿名、主网经济规则或独立安全审计。**

## 当前主线：M5 本机支付整合版（0.3.0-dev）

真实钱包、Orchard 证明、规范交易字节、四节点 CometBFT、独立验证进程与持久化账本已经接入同一条开发路径。验收结论必须查看相应源码提交的 `payment-integration-laboratory` 工作流，而不是把源码存在或旧测试成功当作本版本通过。

| 能力 | 实现范围 |
|---|---|
| 本机钱包 | 密码保护的加密种子文件、zvtest 收款地址、加密备份／恢复、验证历史后重扫余额 |
| 真实证明与授权 | 使用锁定的 Orchard 修复电路；逐个验证花费签名、绑定签名和真实证明；没有跳过验证的开关 |
| 测试资产支付 | 初始化固定无价值供应，普通支付／找零、连续再次支付、固定销毁费用、重复花费与无支持发行拒绝 |
| 多节点账本 | 四个共识进程各运行独立的公开状态 Rust 工作进程；提案检查、暂存、同步落盘、重启重放分离 |
| 确认与历史 | 历史精确字节摘要纳入应用哈希；客户端核对原始验证者集合签名和下一高度的 AppHash，再报告测试资产确认 |
| 常驻钱包会话 | 本机 stdin/stdout 会话复用公开证明参数，避免每次命令重建；不增加网络或节点私密输入接口 |
| 操作入口 | 统一 PowerShell 构建、网络启动及钱包操作脚本；不会自动安装工具、删除数据、部署公网或转移真实资产 |

详细范围、容量限制、构建依赖和操作文档见 [M5 支付模块](integration/payment/README.md)，协议字段见 [实验规范](docs/PAYMENT_LAB_SPEC.zh-CN.md)。此规范尚未独立审查，不是最终主网协议或 ZIP-244。

### 隐私与信任边界

没有全网查看密钥，节点工作进程不接收钱包密码、种子、查看密钥、票据明文或成员路径。钱包在用户本机生成证明；创始人身份不附带解密权限。收付款参与者仍掌握自己的记录；初始分配对初始化者不是匿名的。

当前通信仅限 127.0.0.1，没有 IP 匿名或流量关联防护。四个同机进程由同一操作者控制，不是独立去中心化网络。加密文件不保护失陷或已解锁设备，也不证明侧信道安全。完整秘密处理、更新渠道与部署行为仍需独立审查。

钱包核对原始支付创世，并重执行历史；Go 客户端用原始共识创世验证签名检查点。原始文件、可信程序和本机文件系统仍是信任边界。这不是支持动态验证者和互联网对手的完整轻客户端，也没有可移植的离线最终性证书。

### 速度口径

常驻会话把公开参数初始化单独计时，不把这部分冷启动成本隐藏。自动测试分别记录冷／热准备、提交到签名检查点、后续历史导出和收款识别的样本。单笔或少量样本不等于 p95，也不能用空块间隔或验证耗时倒数冒充真实 TPS。端到端五秒目标尚未认证。

### 主网仍未完成

实验限制为 4096 个区块、8 MiB 原始交易历史及其他明确资源上限，日志损坏或满额会拒绝继续，不静默重置。生产数据库、快照／裁剪、长期恢复、网络隐私、主网发行奖励与治理、独立验证者和安全／供应链审计仍是 [主网发布阻断项](docs/PRODUCTION_GATES.zh-CN.md)。**完成本机收付款闭环不等于整个公链项目完成。**

## 构建与验收

统一构建入口为 `scripts/Build-PaymentLab.ps1`，输出 `bin/zevune-crypto`、`bin/zevune-wallet-session` 和 `bin/zevune-paynet`，Windows 带 .exe 后缀。需要固定工具链和对应本机链接器，首次构建涉及依赖下载，不需要 Docker 或 Docker Hub。脚本不自动安装这些工具。

开发者负责回归与 GitHub CI；不要求用户对每个小改动重复安装、查询状态或贴日志。仓库已有的 [整体验收要求](docs/INTEGRATION_ACCEPTANCE.zh-CN.md) 仍有效，不能降低其门槛来声称主网完成。

根 Go、CometBFT Go、Orchard Rust 和 Payment Rust 必须分别测试。根目录 `go test ./...` 不遍历嵌套模块。M5 网络测试必须提供真实 Rust 可执行文件；专用 CI 配置要求该文件存在，不能跳过后算成功。检查报告的明确源码提交及每个平台的实际任务结论。

历史证据：[M2](reports/m2-remote-validation.md)、[M3](reports/m3-remote-validation.md)、[M4](reports/m4-remote-validation.md)。[六份历史原始技术文档](docs/PUBLICATION_STATUS.zh-CN.md) 仍未重新提交，新增规范没有冒充这些原件。

不要将钱包、密码、种子、验证者私钥或运行时日志提交到仓库。参见 [安全说明](SECURITY.md)、[许可证状态](LICENSE-STATUS.md) 和 [第三方声明](integration/orchard/NOTICE.md)。公开源码不等于整个项目已选定开源许可证、依赖审查完成或通过安全审计。
