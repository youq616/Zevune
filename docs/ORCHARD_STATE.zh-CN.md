# Zevune M5/M6：真实验证边界与本地资产状态

这是禁止真实资金的实验模块，不是完整隐私链。原有单机程序和四节点 CometBFT 仍未开放支付；本轮没有迁移旧数据或部署公网服务。

## M5：Go 调用真实 Rust 验证器

`internal/orchardbridge` 传送的是公开的授权交易字节，不是私钥、查看密钥、明文票据或私密见证。Rust `zevune-orchard-worker` 只使用标准输入/输出，没有网络监听、任意命令或私钥上传功能。

程序路径必须是绝对路径，并与受信任构建清单里的 SHA-256 匹配。校验程序文件不是数字签名、远程证明或安全沙箱，也不抵抗恶意本机管理员替换文件。只有少量系统环境变量传给子进程，不传 GitHub token、钱包秘密或代理配置。错误输出不回传交易内容。

握手固定网络、版本和电路指纹。每个响应绑定单调请求编号和完整交易字节 SHA-256，包括证明和签名。错误响应、异常退出、超时或发送后的取消使会话关闭；没有失败后放行或自动切换假验证器。合法格式的无效交易是普通拒绝，不会与执行故障混为一谈。

只有两个至八个动作，最大信封 28,102 字节。Go 只检查结构，Rust 调用上游规范字段/曲线点构造、逐个 RedPallas 签名和单证明验证。原 M4 实验签名摘要未变；它不是经过独立审查的最终交易协议。协议指纹也不认证恶意二进制。

`Authorization.CheckCommittedState` 还需要调用方提供不可变可信账本视图。`CheckedEffects` 不是落盘结果或最终确认，不能绕过提交时的再次验证。当前这一路径尚未连接下述 Rust PoolStore，也没有接入 CometBFT 收付款。

## M6：真正的 Orchard 资产树

`integration/orchard/src/pool.rs` 使用固定依赖 `incrementalmerkletree` 与上游 `MerkleHashOrchard`。资产承诺按交易动作顺序追加，不使用原 Go v0 SHA-256 原型树。花费标识集合、输出集合、最近 64 个不同已提交树根、累计公开费用与高度共同形成确定性的实验状态摘要。

公开的 PoolStore 创建/打开入口只允许空创世状态，没有任意注资或发行接口。真实收付款状态测试在 `cfg(test)` 内提供一次性非空初始承诺，秘密票据和密钥只在测试内生成。测试初始资产不代表实现了发行、储备认证或经济规则。

`prepare` 在状态副本上验证候选区块，不修改磁盘或已提交状态。所有交易只能引用区块开始前已提交的树根；不能引用同一候选区块中途形成的树根。任一交易失败，整个候选不生效。

`commit` 核对候选的基线，重新执行所有真实授权及状态检查，核对结果，追加日志并 `sync_all` 成功后才推进内存。外部调用者不能修改 PreparedBlock 的私有字段；此对象仍不是最终确认凭证。传入的非零 block_id 是应用上下文，不是本模块验证过的签名提交。

## 保存与恢复边界

日志文件持有标准库独占文件锁，以创建新文件或打开已有文件的方式区分，不覆盖已有文件、不替换损坏文件、不自动重置。记录包括公开创世承诺（仅测试内部非空）、完整签名交易、高度、前后状态摘要及校验和。没有个人秘密或解密票据。

打开日志时重新计算真正的 Orchard 树，重新检查每个签名和证明、历史根、重复花费及前后摘要。长度越界、部分记录、错误校验和和不一致结果均拒绝，原文件保持原状。伪造交易后重新计算外层校验和也不能免除密码学验证。

写入或同步失败后实例不可继续使用，内存不推进。但是完整记录可能已经到达操作系统：调用失败不表示记录肯定不存在。恢复时必须重新验证，并与可信共识状态对账。测试模拟该不确定情况，不宣称模拟了真实断电或磁盘控制器行为。

校验和不是防篡改认证。删去完整末尾记录留下一个合法历史前缀，单靠日志不能确定它被回滚。`check_checkpoint` 仅比较调用方提供的可信高度和摘要，尚不是已实现的共识握手/轻客户端。恶意操作系统、管理员、祖先目录替换、文件系统特性与断电目录持久性不在这里的保证范围。

## 容量和性能

实验上限为每块 16 笔、65,536 个输出承诺、10,000 个记录、64 MiB 日志。到限拒绝，不删除历史绕过限制。当前状态副本和集合摘要仍有随状态增长的成本，完整启动重放还需验证历史证明，不是生产级数据库、快照同步或长期运行方案。

验证进程复用公开参数，但本轮没有给出延迟分位数、TPS 或真实网络到账速度。正确性测试通过不构成密码学、侧信道或依赖漏洞审计；公开证明参数不是全网查看密钥。

## 自动验收

根 Go 模块、嵌套 CometBFT 模块和 Rust 模块分别测试。`orchard-bridge` 额外构建真实 Rust 子进程，用同轮真实证明测试输出的公开字节从 Go 验证，并检查损坏证明、签名和密文被拒绝。缺少真实程序或样本时测试失败而不是跳过。

M6 测试覆盖 A→B、落盘重开、B→C、再重开、重复花费拒绝、竞争候选失效、整块原子失败、伪造日志、半条记录、写入故障和合法前缀回滚检测边界。随机输入/截断测试不是 Rust 覆盖引导 fuzz。Windows 和 Linux 的实际测试任务与明确源码提交须按发布报告核对。

用户无需对每个增量再次手工测试。完整交付仍以钱包、真实证明、多节点支付与恢复、网络隐私及明确条件的端到端性能为准。
