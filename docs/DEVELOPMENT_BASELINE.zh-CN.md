# 统一开发基线：Genesis-bound LAB2

本轮收敛到现有 `dev/m12-genesis-domain` 实现，不再新建平行协议分支。选择的运行代码起点为 `cde704157c7edfde9a1bcba7e051eea9f22b930c`，保留旧 `main` 的真实密码学、钱包和共识基础。这里的统一是实验代码基线，不表示正式协议冻结、测试网完成或主网准入。

## 分支处理决定

`dev/protocol-v1-final` 的 `845daa92eea51b1e240e0f05ee2db6d0a18248f4` 新增了独立 Go Context/TransactionV1/GenesisV2/StateRoot/Migration 结构，但没有接入真正的 Orchard 支付。其新 `Version uint32=1` 与原诊断协议 `Version uint16=0` 同包重名，造成编译失败。只改名字可以消除编译冲突，不能把这些结构变成实际密码学或迁移实现。

整合提交明确采用已经接入 Rust 签名、账本重放、钱包和 IPC 的 LAB2 路径，不把那组没有调用方的八个草稿文件带入最终树。旧分支提交作为合并父提交保留，历史不会被强推改写。原 Go 诊断协议、编码和版本常量保持原样；不把实验摘要当作真实 Orchard 根。其他平行 Domain 草稿仍可从原分支审阅，但不并入运行路径。

## 可执行路径

`TestGenesis` → 钱包读取完整可信历史 → 真实 Orchard 授权签名绑定清单摘要 → `ZVORLAB2` → Go/Rust 受限 IPC → 账本按自己的固定域检查 → ABCI 共识 → 原子提交 → 参考账本验证签名头与执行结果 → 钱包重新扫描。

LAB2 域是准确 `ZVTGEN02` 公开测试创世清单的 SHA-256。清单包含独立随机的公开部署标识。交易不能自行选择节点接受的域。密码学检查缓存命中后仍必须检查当前账本许可。此绑定不防止完全复制同一清单的链克隆，也不等于绑定未来所有验证者变更或完整主网治理规则。

## 本轮加固

Go 启动层和配置读取共用 `poolbridge.ValidateTestGenesisFrame`，在启动子进程、创建私有节点目录前检查已固定摘要的清单：允许的 LAB1/LAB2 格式、网络标识、精确长度、分配数量、固定总量和 LAB2 非零部署标识。金额从有限余额逐项扣除，避免累加溢出。读取文件后还核对文件身份。

这只是公开格式预检查。地址/曲线解析、资产开口、输出唯一性和密码学验证仍由真实 Rust 库完成，不能凭 Go 检查成功就发行或入账。单元测试里的结构样本明确不是有效的 Orchard 资产。

真实操作进程测试增加：域字段替换、LAB2 降级为 LAB1、未知协议格式。分别通过实际客户端和直接节点 RPC 验证拒绝，重新同步检查资产根、承诺数、已花费标识与费用不变，然后继续原有真实 A→B→C、加密待发送记录恢复、单节点离线与整网重启。

非零金额工作流在昂贵密码学构建前先编译根 Go 与嵌套 Go 模块，内部旧协议改动也会触发此门槛。不得把测试文件存在当作通过；需要读取准确提交的 CI 结果。

## 兼容与发布边界

旧 LAB1 清单和日志仍按 LAB1 打开，不会因更新程序自动获得新保护。LAB2 使用独立的新测试网络与日志头，错误清单或混用 IPC 版本必须失败；禁止通过改魔数、删日志、删签名状态强行迁移。不会删除用户原有钱包或账本。

当前仍限单机四验证者和无价值测试资产。正式网络/验证者规则、受审查的升级执行器、长期存储、完整在线钱包、网络匿名、端到端性能分布和独立安全审计均未完成。
