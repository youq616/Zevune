# 隐私保护边界与验收要求

本文件对应当前本机实验架构及新增加的创世域绑定，不是“无法监管”的承诺。
目标是账本规则公开可验证、个人支付内容默认加密，开发者没有额外的全网查看密钥。
采用成熟证明组件不自动证明整个链、钱包和网络的隐私与安全。

## 当前公开与私密信息

| 信息 | 当前处理 | 必须保留的边界 |
|---|---|---|
| 交易承诺、花费标识、证明和签名 | 公开以验证账本 | 不是零信息公开；行动数量、长度、时序仍可观察 |
| 手续费、过期高度、链/创世域 | 当前协议公开 | 域标识用于防止误用到其他部署，不隐藏所用网络 |
| 普通付款的收款信息与金额 | 由 Orchard note 加密和证明处理 | 收付款双方和被攻破的终端仍可能知道或泄露信息 |
| 创世测试分配 | 地址、金额及 opening 全部公开 | 仅无价值测试资产，不能当作匿名发行方案 |
| 用户花费密钥、查看密钥、种子 | 钱包本地处理，保存为加密钱包 | Python/操作系统/上游类型副本不具备完整内存擦除保证 |
| 本地网络连接、RPC 请求和时间 | 只限制在本机数字地址 | 尚未实现网络匿名，不防拥有主机权限的观察者 |
| 日志与备份 | 拒绝记录付款私密见证；钱包记录加密 | 文件名、大小、保存时间、旧合法备份回滚等需要独立考虑 |
| 软件包、更新与验证者权限 | 固定提交校验与固定验证者实验 | 未有生产签名更新体系或独立运营证明 |

## 分对手验收，不用一个“匿名”布尔值替代

**普通账本观察者。** 检查全部公开字段与统计特征；不得把隐藏金额本身当成支付关系
无法推断的证明。需要建立可复现的元数据泄露清单，禁止给出未验证的匿名集合数值。

**恶意 RPC 提供者。** 当前参考节点重新执行交易，并核验签名头部和后置状态；
这可拒绝错误内容，但单个提供者仍可扣留新区块。签名有效不证明提供的是全网最新状态。
不能从恶意提供者同时下载创世文件与其摘要，就声称完成独立可信引导。

**掌握部分验证者的对手。** 需要实测投票权阈值、网络分区、审查和重启恢复。
当前同机四进程不是四个独立运营主体，不应据此宣称抗集中控制。

**网络观察者。** 尚无覆盖跨主机传播与查询的隐私实现和测量；未来需独立评审
传播、扫描和同步方案。只使用本机地址是实验隔离措施，不是匿名机制。

**被攻破的终端或知情交易对手。** 不在“密码学隐藏链上内容即可防护”的保证范围内。
钱包口令、收付款明文、屏幕、内存或备份可能泄露。需要专门的终端与备份安全工作。

**开发者或更新发布者。** 当前代码无全局查看密钥，不代表更新渠道已去中心化。
需要冻结协议规则、最小发布权限、可核对构建、可信更新和独立评审；不能把仓库写权限
等同于无法滥用的治理。合法本地查看密钥属于用户，不设置全网解密钥匙。

## 本轮新增保证的准确范围

V2 将交易签名绑定到已固定的完整测试创世清单。改变部署随机标识但保留同样的资产树，
另一部署仍拒绝原交易；修改交易域、删除域以降级，不能产生有效的新签名。钱包恢复、
状态重放和授权缓存命中也必须检查预期域。它解决跨部署误用问题，不增加网络匿名性。

完整复制同一份创世文件就复用了同一个身份，不能自动区分链分叉或完全克隆网络。
旧 V1 不自动获得新保护，必须明确保留为旧实验协议。当前不能作为真实资金网络使用。

## 后续交付门槛

正式网络需要独立的协议与隐私审查、多机故障验收、完整钱包操作、长期存储和容量方案、
明确负载下的端到端速度统计，以及验证者和安全更新规则。本文件不替代六份缺失的历史文档，
也不把这些尚未执行的测试描述为已经通过。
