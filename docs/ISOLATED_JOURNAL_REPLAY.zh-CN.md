# P2 子阶段：共享隔离重放与检查点验证

范围：本机、无价值测试资产。不是日志分段、状态快照、快速同步、主网或绝对无缺陷保证。正式验收需绑定准确提交的测试与独立代理审核，不能根据本说明推断已通过。

## 接续与实际改动

本轮接续 `cd1ecc67730ebe6567dba7fd8fe1e362097870e7` 的检查点备份恢复实现，将此前未推送的隔离重放候选整合到最新代码，而不是用旧版 `open_with_policy` 覆盖新增的 `replay_locked_file` 和只读恢复接口。

原节点已经按记录读取日志。本次解决的是启动和钱包读取维护重复循环、恢复时每块复制完整状态，以及仅导出恢复检查点却收集全部钱包历史这三项问题。

共用私有 `pool::replay::Replay` 的路径：

- 普通节点启动 → `replay_locked_file` → 逐块验证并丢弃块交易副本 → 返回完整重建状态。
- 钱包扫描 → 私有 `replay_history` → 收集到尚未公开的本地历史 → 最终状态与已提交实例匹配后返回。
- 恢复检查点导出 → `verify_committed_history` → 同样逐块验证但不收集钱包历史；仍比较重放前后文件摘要及已提交状态。
- 只读备份验证与仅创建式恢复 → `verify_locked` → 同一个重放器；原句柄及文件锁始终由原调用方拥有，不增加解锁再打开的窗口。

## 状态与失败边界

重放器独占尚未发布的重建状态，读取每条记录前取走 `Option<State>`。只有前置摘要、真实交易执行、后置摘要全部检查通过才放回。任意读取、解析或授权错误都会丢弃重建状态，之后不能忽略错误继续读取或取出合法前缀。

`execute_unpublished` 只用于正常 `execute` 持有的临时副本及重放器拥有的重建状态。它不保证某个块的后半部分失败时已执行前半部分自动回滚，因此不能用于活的已提交状态或提案筛选状态。实时提案、最终执行和 Commit 的原隔离与复核机制保留。

每块仍使用块前已提交的历史根；验证真实 Orchard 授权、固定网络域、到期、双花、重复输出、费用及容量。缓存命中不是当前花费许可。只有实际观察到 EOF 后才能 `finish`；刚好读到捕获长度不算 EOF，额外尾字节必须拒绝。

钱包收集器是私有调用方，部分历史在失败时整体丢弃。检查点导出的丢弃模式也必须重放到准确的当前已提交摘要，不能仅按长度、文件哈希或最后一个记录自报摘要导出可信结果。已有实例遇到重放错误仍停用，但不自动修复磁盘。

## 资源与兼容性

长度、剩余文件字节及记录数量在申请帧内存前检查；帧体使用可复用的有界缓冲区，容量申请失败返回错误。解码仍会复制本块交易；钱包仍收集完整历史，状态摘要仍遍历累计集合。故不能声称全程恒定内存、整体复杂度必为线性或已测得某个速度倍数。

检查点导出不再调用收集全部区块的 `wallet_history()`，但没有跳过验证。测试中的计数器仅存在于测试构建，用来区分逐块状态复制和历史收集路径，不代表实际内存峰值或性能计时。

原 64 MiB 日志、10000 条记录、65536 个承诺和每块16笔交易上限不变。交易、日志、检查点、IPC、签名域、证明电路、发行费用规则及依赖锁不变。旧 LAB1 不被重新标为 LAB2。备份恢复仍是全量原字节复制与真实重放，不含共识数据库或验证者签名状态，不自动启用节点。

## 验证重点

12项重放专项覆盖逐字节短读、Interrupted、所有截断点、尾字节、篡改、重算校验和后的恶意记录、真实错误签名、半块已执行后的双花、错误后置摘要、未观察EOF的finish、错误后再次调用、301个读故障边界和长短帧缓冲区复用。10000条空记录仅是上限边界，不是支付负载测试。

另加4项恢复联调：钱包保留48个块而检查点导出不收集历史；已准备块不受导出影响；多个只读恢复者共存并阻止写者；等长合法替代历史不能替代已打开实例的状态；最后错误记录不能返回先前有效状态或泄漏锁；旧合法备份必须使用它自己的独立检查点。已有真实付款恢复测试增加了导出路径的篡改签名拒绝，不能被热缓存或重算文件哈希绕过。

这些有限反例不是形式化证明。完整旧前缀在旧检查点下仍是有效旧历史，不能证明全网最新。父目录、文件系统和主机仍有信任前提；锁不宣称抵御恶意内核、存储固件或任意并发攻击。不能以作者复核或CI替代不同代理任务的审核，也不能以代理审核代替外部专业安全审计。
