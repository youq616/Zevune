# M9：受约束的本地测试创世与非零金额共识整合

本模块只用于无价值资产的本机实验。它不是主网发行协议、已审计钱包或最大匿名网络；普通启动方式仍不启用支付产品。测试代码已加入，是否通过应查看对应源码提交的 CI 和验收报告，不以本文代替测试结果。

## 分离创世与支付

新增 Rust feature `local-funding-lab`，默认关闭。仅显式编译该 feature 的状态程序支持额外的测试创世文件和 SHA-256 固定值。默认二进制拒绝这些参数，不回退到创建空账本。

`ZVTGEN01` 清单有固定网络标识，最多 16 项，总量必须恰好为 100000 个无价值测试单位。每项公开地址、金额、rho 和 rseed；使用上游 Orchard V2 类型重新构造承诺，检查规范编码、金额总和、重复承诺及重复 rho。清单不是任意承诺列表，不包含私钥、种子或查看密钥。生成随机数失败会停止。

**创世分配公开，包括初始地址与金额。这个决定只用于受控测试，不符合把全部历史资金来源隐藏起来的最终产品要求。** 普通付款继续使用原 Orchard 证明、签名、输入输出守恒和重复花费检查，没有透明转账回退。不能把公开创世清单在后续区块当作发行交易提交。测试手续费累计到原有费用状态，尚无验证者分配或最终经济规则。

创建和重新打开账本都要提供同一个经核验的清单；已有账本不覆盖，缺失文件不自动重建。Go 侧核对文件边界和固定摘要，Rust 再核对实际读取的摘要与完整分配规则。共识创世 AppState 绑定清单摘要，初始 AppHash 绑定相应 Orchard 状态。每个节点必须独立得到同一个初始状态。

本实验保留既有交易签名域与链标识。随机创世承诺可以区分新生成的测试数据，但不是最终跨链重放隔离设计；复制同一创世的实例不能当作彼此独立的生产网络。

## 钱包与多进程

钱包通过经重放校验的本地历史识别自己名下的公开创世记录；正常收款与找零仍使用上游认证解密。多个输入使用真实资产树认证路径。新的 `zevune-funded-scenario` 是固定场景测试驱动器，不是通用钱包 CLI：它生成三个临时加密钱包，秘密保留在 Rust 进程，Go 协调器只接触公开清单、签名交易、区块和合成测试结果。

自动场景拟验收：A 的两笔各 50000 初始记录合并支付给 B 60000、手续费 1000、找零 39000；B 将实际收到的记录支付给 C 40000、手续费 1000、找零 19000。最终余额 39000+19000+40000 加累计费用 2000 必须等于 100000。

付款先通过 WalletStore 保存加密预留和完整签名交易，再返回广播字节；从加密备份重开必须恢复相同交易。共识场景真实启动四个 Go 节点和各自的 Rust 状态进程。客户端独立重放实际区块，验证已知测试验证者集合的提交签名，将每一步计算结果与下一高度签名头的 AppHash 比较，而不是把内存池成功响应当作到账。

还检查一个验证者停止时付款继续、落后者恢复、全部节点关闭后保留签名状态与账本再启动、钱包重开扫描、重复付款拒绝，以及错误创世绑定与篡改交易拒绝。

## 边界

所有节点在同一测试机的 loopback 上运行，四个进程不代表四个独立运营方或 WAN。钱包恢复是持有测试口令的驱动进程释放对象并重开文件，不是物理断电或完整钱包进程崩溃恢复认证。固定场景仍需用户操作入口、独立受信的远程同步和生产存储。

打印的两笔场景用时包括备份、口令派生、扫描、签名头核对与独立全量重放，不是优化后支付路径；只有两笔样本，不能作为 p95、TPS 或 5 秒到账的结论。网络匿名性、侧信道审查与独立安全审计未完成。

原 Go 程序和旧日志不迁移；默认 Orchard 空创世路径保留。测试资产不得出售、充值或连接真实资金。持续集成不得导出测试钱包、口令、种子、解密记录或私密见证。
