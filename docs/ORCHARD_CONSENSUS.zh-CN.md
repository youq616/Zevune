# M7：Orchard 持久化状态与共识连接

开发中，禁止真实资金。此版本增加连接代码和整合测试，不能声称完整钱包、匿名网络、发行规则或主网已经完成。源码进入主分支前须实际通过同一提交的整合测试。

## 连接结构

CometBFT → poolapp ABCI → Go poolbridge → 本机 stdin/stdout → Rust zevune-pool-worker → M6 PoolStore。

每个节点拥有自己的 Rust 进程和日志。初始化必须显式 create；重开必须 open，不会自动补建丢失日志。进程仅处理公开交易和共识块数据，不接收用户密钥、查看密钥或私密见证，不监听网络。二进制 SHA-256 校验不是沙箱或签名分发体系。

Status 只返回已提交状态；Preview 检查但不保存；Finalize 保存待提交结果到内存；Commit 必须引用相同区块完整编码的摘要。Rust 提交仍调用 M6 重新验证、落盘、同步后推进状态；Go 比对返回结果与 Finalize 预期结果。进程通信错误、超时或状态错配不能作为普通交易拒绝而继续运行，未知提交结果不会自动重试。重启由 CometBFT 通过 Info 中的已提交高度/应用摘要进行恢复握手。

## 协议边界

IPC 帧最大 524288 字节，请求含 8 字节标记、单调 64 位编号、操作码和有界数据。回复绑定完整请求 SHA-256 和编号，固定 96 字节状态摘要。单块最多 16 笔，每笔最多 28102 字节。继承 M6 的 10000 条记录、65536 承诺及 64 MiB 日志限制，不自动剪掉数据绕过边界。

PrepareProposal 只检查最多 64 个输入候选并选最多 16 笔，防止无限候选遍历；其尚不存在的区块 hash 使用明确的只读检查标记，此标记不能写入实际共识状态。Finalize 使用真实区块 ID。同一 ID 不足以识别重试：全部有序交易字节必须相同。

网络链标识与实验签名 NETWORK 一致：zevune-orchard-lab-1；没有修改旧 M1/M2 日志、M3 链或原签名格式。不同初始化的测试网不宣称自动获得独立签名域，正式 genesis ID 和升级域绑定仍待协议评审。

## 整合测试目标与局限

带 pool_e2e 标签的测试必须有本轮构建的真实 Rust worker 和真实零金额证明样本，缺少时失败而不是跳过。新四节点网络仅由测试程序在 loopback 初始化，不新增公网支付启动器。每个节点是独立操作系统进程并拥有独立 Rust worker。

空创世没有货币供应，也没有注资接口。因此使用上游真实电路可证明的零金额协议交易验证非空区块：真实授权、入池、传播、区块提交、资产树更新、持久化、全部节点停止后重新启动以及重复标识拒绝。它不是 A 给 B 支付有价值资产，更不能把零金额交易的测试当作完整钱包付款体验。

另开全新 Rust 状态进程重放公共块，对比签名区块头中上一高度的 AppHash，并验证四个节点的真实验证者签名、区块 ID 和验证者集合。单机四进程不是四个独立运营者，也不是跨地域或隐私网络。

单独检查 Finalize 后文件长度和 Info 不变；终止此时的 Rust worker，重开仍是旧状态，重放再 Commit 得到同样摘要。完整 Commit 后重开能拒绝重复交易，缺失日志不重新初始化。该边界测试不是任意写入中断、真实断电或恶意文件系统安全保证。

本轮没有测量端到端支付延迟、TPS 或用户匿名性。原有诊断程序付款仍关闭。完整钱包、受审查交易/创世发行规范、网络隐私、生产存储、升级治理和独立安全审查仍未完成。用户无需对本轮逐项操作。
