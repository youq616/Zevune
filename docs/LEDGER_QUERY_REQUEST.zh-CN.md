# 离线批量查询任务文件 v1

本模块让同一份独立查询依据和1—32个交易ID以固定JSON文件交接、核对和执行，减少反复手工输入。
它是显式CLI，不会自动接管旧桌面；不修改原C25桌面、单遍核心、账本、钱包或密码学。始终NO-FUNDS。

## 文件中有什么

格式`zevune-ledger-query-request-1`，绑定单遍profile、独立ZVARCP01检查点、创世文件签名域SHA256、
批准的原生恢复程序SHA256、有序且互异的交易ID、字面`real_funds_allowed=false`。上限8 KiB，严格
UTF-8和规范JSON，拒绝重复键、未知字段、其它profile、额外空白、非有限数值和不正确的类型。
不修剪、去重或排序交易ID。任务不可变地保留输入顺序。

**不保存账本路径、可执行程序路径、URL、shell命令、密码或自动执行指令。** 同一文件不能为另一
程序自动重新赋予信任。后端摘要按实际平台/构建绑定；Windows与Linux后端不同就需重新明确创建任务，
不能把更换平台视为可以忽略摘要。任务可关联一组交易，应保护文件与终端输出。

## 三个命令

可信Python 3.10+和可信源码目录。创建及检查无需Git、Tk、Rust或原生恢复程序；执行才需批准后端。
根参数`--no-real-funds`必须在子命令之前。所有文件路径必须绝对、不含`..`且不超过4096 UTF-8字节。
父目录应预先存在，禁止链接/reparse父级与非普通文件；任务文件必须只有一个硬链接。

创建全新任务（在仓库根目录PowerShell中）：

```powershell
python .\scripts\ledger_query_request.py --no-real-funds create --destination 'C:\ZevuneTasks\query.json' --checkpoint '<独立256位检查点>' --genesis-sha256 '<独立64位签名域摘要>' --backend-sha256 '<独立64位恢复程序摘要>' --txid '<交易ID一>' --txid '<交易ID二>'
```

只有退出0及完整JSON回执才代表这次创建成功；从回执独立保存`request_sha256`。已有目标即使为空也
拒绝覆盖。任务写入后fsync并回读核对；失败保留部分/完整输出，不删除、不续写、不自动重试。
完整文件可能在确认丢失后留下：另行检查可以证明现存字节符合pin，不能倒推原创建调用成功。

检查收到的文件（不执行）：

```powershell
python .\scripts\ledger_query_request.py --no-real-funds inspect --request 'C:\ZevuneTasks\query.json' --request-sha256 '<独立保存的64位任务摘要>'
```

**不可从收到的文件自算摘要，再把它当独立信任。** 摘要不是签名，不证明作者身份、付款授权或最新
版本；`inspect`只输出固定任务和`execution_performed=false`，不触碰账本或运行后端。

明确执行（路径由本机操作者另外指定，不从任务文件读取）：

```powershell
python .\scripts\ledger_query_request.py --no-real-funds run --request 'C:\ZevuneTasks\query.json' --request-sha256 '<独立保存的64位任务摘要>' --journal 'C:\Zevune\stopped-archive' --backend 'C:\Approved\zevune-pool-recovery.exe'
```

每次run都调用原单遍核心，重新通过原单链接/程序摘要/句柄门槛与原verify-active，然后一次完整记录
定位和前后账本复验；不复用历史成功、不回退旧算法。任务文件在执行前后同时核对字节和身份，同字节
替换文件也算变化。执行中任务变化则整次失败，即使内层查询已经结束，也不输出成功结果。

返回的`result`就是原单遍结果，外层绑定本次任务摘要；没有“已付款”结论。缺席仍不授权重试，当前
高度/广播/结算未知，钱包、收款人/金额和最终性未验证。任务检查本身不改变这些规则。

## 时间、失败与平台边界

原核心自己的300秒预算不变；任务文件的有界前后读取在该预算之外。因此不承诺整个新命令也在300秒
结束，不给原生调用增加预算或重试次数。可信本机和停止任务/账本外部写入仍是前提；无全程锁、跨文件
原子快照、恶意文件系统防护、校验后监控、完整Windows ACL、目录fsync或物理断电安全保证。

正常输出UTF-8 JSON：成功0；失败1；参数错误64；用户中断130。错误采用固定文本，不回显路径或底层
异常。输出写入/flush失败可能留下文本前缀，任何非零退出的输出都不能当有效结果。没有后台执行、
持久调度、网络查询或任何钱包写入。操作系统文件IO可能阻塞，不是硬实时保证。

## 验证与交付

单元层使用真实任务文件、公开未授权账本帧及拒绝型执行，不伪造成功的原生验证器。原生驱动保留完整
旧安装/恢复/单笔/批次/单遍链，在四类真实历史验证任务驱动查询，比较新执行的直接核心结果，检查CLI、
错误任务摘要和真正原生成功后的任务篡改/同字节替换拒绝。修改只发生在测试自有无价值临时文件内。

新双平台工作流保持Rust1.98.1、锁定依赖、20分钟作业与600秒原生监督。测试配置不等于执行通过，
作者复核不等于非作者审核。新文件不混入旧v2-v9或固定10payload包清单。P2/P4整体与真实资金禁令不变。
