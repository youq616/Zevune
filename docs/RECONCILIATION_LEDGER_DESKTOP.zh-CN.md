# 账本绑定复核桌面 v1

这是 C15 `reconciliation_ledger_check.check` 的独立图形入口，不是新的验证器、在线钱包或付款模块。
它将完整信任输入确认、一次原生历史账本复核、结果显示及关闭收尾连接起来。保持 NO-FUNDS。
原轻量文件查看器、命令行账本复核和旧钱包/恢复程序均未改动。

## 启动和七项输入

需要可信 Python 3.10+、Tk、图形桌面，以及独立批准的原 `zevune-pool-recovery` 程序。
在可信仓库根目录启动 Windows PowerShell：

```powershell
python .\scripts\reconciliation_ledger_desktop.py --no-real-funds
```

独立运行源码包使用 `python .\runtime\reconciliation_ledger_desktop.py --no-real-funds`。
Linux 换为相应路径，使用同一入口。普通 `--help` 不导入 Tk，不需显示环境。程序不下载依赖或后端。

填写原对账结果目录、独立报告 SHA256、独立 ZVARCP01 检查点、独立创世文件 SHA256（LAB2 签名域）、
停止写入且与检查点精确对应的活动账本目录、批准的恢复程序绝对路径、独立程序 SHA256。
所有语法、路径和摘要规则沿用 C15。不会从所选目录或程序自行计算摘要并将其当作可信输入。
目录选择器只填路径，不建立信任；所有其他写入者应先停止。不要选择网络共享或不可信文件系统。

## 明确确认，不自动执行

第一步“核对输入”只执行原纯输入检查，完整列出冻结路径、独立摘要、检查点和操作边界，不读钱包
或账本，不启动后端。表单冻结；取消默认获得焦点，Escape 可取消，没有 Return 自动批准。
第二步必须明确点击“确认仅执行账本复核”。取消或确认前更改输入都会撤销本次确认，不启动程序。

任务开始后表单、再次确认、清除输入和取消确认均不可用。同一窗口一次只持有一项任务。
工作线程调用原 C15 检查入口，不访问 Tk；Tk 的更新只在主线程进行。原 `verify-active` 白名单、
程序摘要门槛、原生共享锁/完整授权、两端前后校验及单次300秒预算均保持，不新增超时或重试参数。
这并非允许同时在另一个应用窗口操作同一钱包；操作者仍必须停止外部写入。

检查成功后，仅显示原历史复核说明和该次交易ID。显示前再匹配冻结的报告/检查点/签名域/后端摘要、
高度与账本字节数，并要求所有状态标志具有准确类型和预期值。这是显示防错，不替代原生验证。
工作线程只向有界队列传递不可变文本和ID或固定失败标记，不传递异常堆栈、原始报告或控件引用。

修改任何输入会立即清除旧显示及复制许可；即便程序性修改绕过了禁用控件，旧任务返回后也不会显示。
只有点击“复制本次交易ID”才写入 CLIPBOARD；所有可选文本禁用自动 selection export，包括 X11
PRIMARY。清除界面不清除用户的系统剪贴板。交易ID、回执和源路径可关联本地活动，请保护屏幕。
界面不保存最近路径、报告、配置或密码；没有钱包密码输入。Python/Tk/OS内存擦除不在保证范围内。

## 关闭、线程和计时器失败

关闭请求不强杀原生程序、不假装取消。任务运行时清除显示，禁止新工作，继续主线程事件循环，直到
工作线程明确报告完成且确实退出，再销毁窗口。重复关闭只尝试观察/收尾同一个任务，不重新认证。
等待时界面正常情况下可响应，但不保证 Tk/内核/文件系统故障下有硬实时响应或整项硬截止时间。

采用非daemon线程、准入事件和明确完成事件。`Thread.start` 在实际系统创建线程后仍可能中断；
`ident=None` 不能证明没有线程。启动异常撤回尚未准入请求，同时保留所有权；迟到的线程不执行
被撤回的检查。若已经获准执行则仍等待真正完成。未创建线程却发生启动异常时可能永远没有完成
事件，界面保守停止并提示结束本应用进程；不依据超时伪造完成，也不创建第二项任务。

完成观察回调绑定准确任务和一次性票据；计时器已注册而返回中断时，旧票据失效，迟到回调不能作用于
后来的任务。安排失败撤销显示、保留任务且不自动重试；明确再次点击关闭可继续有限次观察/收尾。
窗口销毁失败时保持closing，允许再次关闭；只有销毁返回后才记录closed。持续Tk失败、操作系统
强制退出、恶意后端子孙进程及全Tcl内部资源回收不在正常关闭保证之内。

## 核验不等于结算

`ledger_replayed` 和 `checkpoint_domain_relation_verified` 仅由原 C15 的真实成功结果进入显示。
这只确认指定历史账本及其与固定报告的签名域绑定，不证明待发送交易已经入账。
不认证钱包、不验证待发送交易授权/纳入、不验证完整创世分配、不认定原恢复调用成功或当前链高度。
广播、结算仍未知，`finality_verified`、`retry_authorized`、`real_funds_allowed` 始终 false。
没有恢复、签名、广播、清预留、自动刷新、自动支付重试或报告导出按钮。

定向测试包含真实OS线程准入/启动中断、完成事件与实际停止、异常脱敏和队列失败。真实Tk检查覆盖

结果交付，不替代验证。所有修改或测试数据只在驱动自有无价值fixture中。

## 前台焦点与默认取消

默认取消指应用窗口内的焦点目标。应用不在前台时，Tk只记住该目标，不应强制抢占其他应用的输入焦点。
自动测试通过控件invoke调用不等于鼠标激活窗口；前台焦点测试先激活测试自有窗口，再保留实际
focus_get断言。另用独立真实Tk应用验证后台确认只记住Cancel且不抢焦点，键盘Return不得确认执行，
Escape取消。产品继续使用原focus_set，不引入focus_force或改变桌面权限；没有跳过Windows测试。

依据：Tk focus与focus -lastfor官方语义。
https://www.tcl-lang.org/man/tcl8.6/TkCmd/focus.htm
