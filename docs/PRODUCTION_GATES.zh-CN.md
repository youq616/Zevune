# Zevune 主网发布阻断项

此清单明确区分“本机无价值测试资产整合版本”与用户最终要求的隐私公链。不是把完成一组测试重新定义为整个项目已经完成。任何未完成项不得通过改变状态文字或关闭验证来解除。

| 门槛 | 当前证据／缺口 |
|---|---|
| 真实密码学 | 已有 Orchard 集成与真实证明测试；实验签名组合、电路使用、密码学依赖与侧信道仍需独立评审 |
| 正确账本与收付款 | M5 接入真实票据树、初始测试供应、手续费销毁、重复花费拒绝；必须以对应提交的 CI 结果确认闭环 |
| 用户自主保管 | 有本地加密种子文件、加密副本恢复与全量重扫；没有助记词、硬件钱包、移动端及完整秘密内存审查 |
| 无全网查看特权 | 未设置全局查看密钥；还需要对所有客户端、发行构建、更新渠道和部署日志独立核查 |
| 网络与元数据隐私 | 尚无 IP 匿名传输或流量关联防护；本机 TCP 联调不能代替这些目标 |
| 速度 | 必须记录冷／热启动、证明、传播、共识、落盘、钱包识别全流程；当前样本不是 p95，不能宣称 5 秒目标达成 |
| 存储与运行 | 实验日志和历史有明确容量上限，满额拒绝；需要生产数据库、经过认证的快照／裁剪、完整断电与恢复测试 |
| 独立验证者 | 四个同机进程不是独立运营者；独立网络部署、拜占庭故障、长程攻击、DDoS 与动态验证者规则未验收 |
| 经济与治理 | 1000000 测试单位和固定销毁费用不是主网方案；发行、奖励、质押／惩罚、升级和应急流程仍未定稿 |
| 供应链与发布 | 固定依赖与测试不等于漏洞／许可证审查；还缺独立审计、可复现发行包核对与发布签名流程 |

整体验收场景按 docs/INTEGRATION_ACCEPTANCE.zh-CN.md：真实钱包两次连续支付、恢复、无支持增发／伪造／重复花费拒绝、多节点一致性、完整延迟与隐私边界。开发者负责自动回归，不要求用户每小步重复测试。

代码生成、证明通过、节点出块和测试资产到账均不等于对“任何人永远无法调查任何交易”的保证。交易参与者披露、终端失陷及充分链外信息的限制不会由上线主网自动消除。
