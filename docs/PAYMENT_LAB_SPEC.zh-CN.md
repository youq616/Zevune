# M5 本机支付整合规范（实验草案，未经独立审查）

目标是打通钱包本地证明、公开交易字节、四进程共识与账本保存；不是主网、绝对匿名承诺或允许真实资金的版本。本规范不代表外部密码学审查已经完成。既有 M2/M3/M4 数据与行为保留，新增模块使用独立数据目录。

## 固定实验规则

链名 zevune-payment-lab-1。使用原 M4 锁定的 Orchard V2 修复电路，不允许调用者传验证密钥或选择旧电路。资产总初始量仅为 1000000 个无价值测试单位。创世包含输出专用 bundle，所有真实花费关闭，净余额必须为 -1000000，所有证明及签名必须有效。创世只在初始化时处理，不存在运行时 mint、管理员充值或发行 RPC。普通交易固定费用 1000，费用销毁，不支付验证者奖励。这些是实验参数，不是已经决定的主网经济规则。

普通交易只能是完整屏蔽 bundle，动作数 2 至 8；创世 1 至 8。普通交易的 value_balance 等于费用，不允许外部池注资。验证历史根、到期高度、全局及块内重复花费与输出、资源上限；不得仅凭证明成功修改状态。

## ZVP1 规范字节

固定顺序：4 字节 ZVP1；kind u8（0 创世／1 转移）；创世标识 32 字节；expiry u64 大端；fee u64 大端；动作数 u8；flags u8（2 创世／3 转移）；value_balance i64 大端；anchor 32 字节；按原始顺序的动作（cv_net32、nullifier32、rk32、cmx32、epk32、enc_ciphertext580、out_ciphertext80、spend_signature64）；proof_length u32 大端及严格匹配上游动作数的证明；binding_signature64。每笔至多32768字节。字段必须通过上游规范解码，禁止额外尾字节。不是 Zcash 整笔交易序列化，也不能用原 Go v0 解码器解释。

签名摘要为 SHA256（固定域 ZEVUNE-PAYMENT-LAB-SIGNATURE 加零字节及版本1、kind、genesis_id、expiry、fee、上游 V5 bundle commitment）。所有元数据为固定长度；动作顺序不可排序。创世 genesis_id=0、expiry=0、fee=0；初始化后 genesis_id 是创世完整规范字节的 SHA256。普通交易签名绑定该标识以隔离不同初始化网络。此组合仍是待独立审查的实验签名规范，不宣称等于 ZIP244。

逐个验证花费签名和绑定签名，再调用上游单个 bundle 的证明验证；共识接受路径不使用本层随机批量接受决策或验证跳过缓存。相同账本、字节和高度必须产生相同结果。参数初始化可复用，但不得用健康检查替代密码学验证。

## 状态与权限边界

Rust 工作进程只接收公开创世、交易和共识元数据；不接收钱包种子、密码、查看密钥、票据明文或成员路径。Go 通过私有 stdin/stdout 管道调用，没有公共证明服务。共识的提案检查不落盘，Finalize 暂存，Commit 同步日志后更新已提交状态；失败后停止继续写入。

钱包在本机生成种子，使用 Argon2id 与 XChaCha20Poly1305 保护种子文件。密码通过隐藏交互或明确的 stdin 方式输入，不作为命令行参数；错误不得回显密钥。只有加密备份，不提供全网查看密钥。钱包重扫已验证公开历史恢复票据和余额；创世信任锚必须来自用户原始网络目录。公开历史本身的合法性验证不等于最终性，需额外核对 CometBFT 签名头及 next-block AppHash。

公开元数据包括交易大小、费用、到期高度、时间／高度、密文与 nullifier。本机网络没有 IP 匿名；加密种子文件不防已失陷终端、恶意更新、弱密码或参与者披露。短测试不是侧信道审查。

## 发布门槛

正向连续两跳支付、真实签名提交、重放／篡改／越权／无支持增发拒绝、失败无部分状态、加密备份重扫、节点与工作进程重启、两平台构建与集成 CI 必须通过才可标为本机整合实验。主网仍需要独立审计、经济规则与独立验证者部署、网络隐私、生产存储、负载测试和正式发布流程。
