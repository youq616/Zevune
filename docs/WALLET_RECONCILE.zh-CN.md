# 付款结果核查与待发送交易恢复 v1

入口 `wallet_reconcile.py`，用于“签名已保存，但应用未收到结果”的本地核查。
它不发起新付款、不广播、不查询远程交易池，也不把本地账本扫描当作共识最终性。
本模块仍为 NO-FUNDS；准确版本、测试和独立审核状态以阶段交付记录为准。

## 1. 两类信任输入必须分开

钱包输入：独立保留的旧回执或精确当前回执、钱包密码、已核验摘要的原钱包后端。
账本输入：独立固定的 ZVARCP01 检查点、ZVTGEN03 创世文件及其 SHA256、已核验的原恢复后端。
不是从本次待检查钱包或报告中自动提取所谓“可信”检查点，也不挑选全局最新状态。

旧回执用于防止换钱包或回滚到其之前；它可以是当前日志的真实祖先，而不仅是当前末端。
先检查完整公开链，再把**调用者提供的旧回执**送入原 Rust op9；原生实现确认祖先关系、
认证最终加密快照并返回实际末端。只重算公开哈希不能代替密钥认证。来源若已整理成新的
日志祖先链，旧回执不再适用，应使用整理时独立保存的新回执，不能绕过检查。

使用前停止其他钱包/账本写入进程。工具使用原逐次后端文件锁、关键步骤前后字节及身份
重查，但没有贯穿 Python 编排的全局事务锁。它依赖可信本机、规范父目录和批准后端。
不得从多个钱包副本同时付款，旧钱包密钥也不会因为生成新副本而失效。

## 2. 只核查当前文件的已认证末端

下面是 Windows PowerShell 示例。从仓库或独立源码目录运行，入口使用 `scripts\wallet_reconcile.py`。Linux 使用相应路径
及不带 `.exe` 的原后端。`$WalletBackend`/`$RecoveryBackend` 是已核验原生程序的绝对路径；
摘要和回执变量来自操作者独立保存的可信记录，密码不得放进参数或环境变量。

```powershell
python .\scripts\wallet_reconcile.py --no-real-funds discover C:\ZevuneData\wallet.journal --pin $OldPin --backend $WalletBackend --backend-sha256 $WalletSha
```

密码通过不回显终端读取，禁止回退到回显输入。成功结果为
`local_tip_authenticated_not_synced`，给出当前文件的已认证回执；同时保持
`history_scanned:false`、`latest_inferred:false`、`retry_authorized:false`。
它不返回余额，不声称待发送状态已对账，更不证明交易未广播或已结算。独立保存返回的回执。

## 3. 在新副本上扫描并恢复原交易

```powershell
python .\scripts\wallet_reconcile.py --no-real-funds recover C:\ZevuneData\wallet.journal D:\Recovery\attempt-001 --pin $OldPin --backend $WalletBackend --backend-sha256 $WalletSha --journal D:\Archive\active --checkpoint $LedgerPin --genesis D:\Archive\genesis.bin --genesis-sha256 $GenesisSha --recovery-backend $RecoveryBackend --recovery-backend-sha256 $RecoverySha --reserve-bytes 67108864
```

目标必须是不存在的新目录，其父目录须已存在。明确输入 `RECOVER-PENDING` 后才询问密码。
不复用空目录、上次失败目录或活动钱包路径，也不能在被检查的账本内部创建输出。

流程为：认证旧回执对应的当前源钱包 → 原恢复后端完整核验账本 → 检查空间 → 独占创建新目录
→ 原 op2 复制完整密文并认证 → 原 op3 仅同步副本 → 按状态选择是否调用原 op5 导出缓存中的
签名交易 → 再扫同一历史并比较完整状态/回执/预留 → 再认证副本与账本、重查全部输入输出
→ 最后创建、同步并回读规范 RECONCILE.json。原源钱包不接受任何同步或签名调用。

可能的成功结果只有：

| 结果 | 含义 |
|---|---|
| `pending_recovered_not_broadcast` | 指定历史扫描后仍有待发送记录，原后端导出了它原先保存的签名字节；未新签名、未广播。 |
| `no_pending_not_settlement_proof` | 副本扫描后没有待发送记录。可能原本就没有、已被该历史收录或已过期，工具不据此区分或声称支付成功。 |

无论哪一种，均保持 `broadcast_status:"unknown"`、`retry_authorized:false`、
`finality_verified:false`、`latest_inferred:false`、`active_wallet_replaced:false`。
网络发送结果、某一交易是否全局最终结算、是否可以重新付款，不由此结果授权。

## 4. 输出与原件

输出目录包含加密 `wallet.journal` 和最后的 `RECONCILE.json`；只有仍待发送时才有 `pending.tx`。
报告记录原独立回执、源末端、副本末端、指定账本检查点和交易编号（若存在），不写密码、种子、
私钥、明文收款地址或余额。报告中的编号和回执仍可关联活动，应当作私有操作资料保管，不上传。

签名交易文件即使没有密码也可能被他人广播；新目录在 POSIX 上使用 0700，但 Windows ACL
仍需操作者在受信位置配置。本模块不声称完整 ACL 隔离或 Python 密码内存安全擦除。
CLI 成功返回报告摘要便于独立留存；此摘要不是签名、最终性或资金安全证书。

源文件及指定账本和创世文件在操作前后完整比较。不删除、替换或激活任何活动钱包。
副本可能按原生同步规则追加一个记录、或因收录/过期清除**副本**里的预留，这不是对原钱包
解除预留或重新支出的许可。后续仅在明确核查后选择单一活动副本；不要并行使用副本和原件。

## 5. 错误、容量与资源限制

错误密码、错误/未来/不在链上的回执、损坏日志、错误网络、错误账本检查点、回滚历史、
已有目标及观测到的并发变化均拒绝。错误可能发生在完整复制或导出之后，留下空目录、
部分或完整文件，甚至完整报告。**不自动删除、截断、补报告、续跑或盲目重试。**
没有收到成功结果不能推断没有写入。没有完整报告也不意味着源钱包的签名记录已丢失。

空间预算包含完整副本加最多一次保存追加、最多 32768 字节交易文件、4096 字节报告以及
显式 reserve。Linux 逐文件按分配单元取整，并计入目录和三个文件共四个 inode；Windows
沿用调用者可用空间及未知分配单元/inode 语义。查询不是预留，元数据、COW、ACL、配额和
其他进程仍可导致后续写入失败。256 条钱包保存上限不变；满钱包若必须追加则安全失败，
保留原件及输出，不自动整理。已接受的整理模块是另一个需要明确确认的流程。

每次钱包调用沿用原有界 300 秒等待，账本核验各自使用既有 300 秒命令期限和清理规则。
本阶段修复共享钱包传输在 Thread 构造失败时遗漏子进程回收的问题：线程构造/启动全部纳入
拥有子进程的异常清理范围，三个流各由其线程关闭。退出共用一次 5 秒窗口，流收尾共用一次
6 秒窗口（保留原三个流各 2 秒的总量），异常 finally 不重新计时，也不在主线程关闭活跃流的锁。
拒绝型真实子进程回归覆盖三个构造位置、三个启动位置和超时；这些测试不模拟成功钱包认证。
没有新增整项硬实时期限，不能承诺总操作只耗时 300 秒或可抢占任意阻塞内核 IO。
钱包文件有界读入（最多约 8.1 MiB），公开账本指纹沿用流式读取；并行操作可能叠加资源成本。

## 6. 测试和交付边界

本模块以准确仓库源码或独立 Python 源码目录交付，不是 v10 二进制程序包或 Windows 安装器。
既有 v9 原生程序包及 v2-v9 精确清单合同保持不变，不要把额外脚本塞进已核验程序包目录。
在独立源码目录中运行本入口，`--backend` 和 `--recovery-backend` 指向另行核验的原生程序绝对路径。
普通 Python 启动不要求 `-B`；作为库导入不改变宿主的缓存策略。

定向测试覆盖旧回执、完整公开链、严格原生响应、非付款结论、空间/上限及缓存/参数脱敏。
真实验证驱动调用原钱包生成测试 note openings，只在未同步的测试钱包第一次扫描前选择 03
活动 profile；全部账本记录、授权、检查点和交易均由原 Rust 生成或验证，不手工伪造成功。
该步骤仅为独立无价值测试建网，不是将用户的已有 02 网络迁移成 03。

真实流程覆盖原签名字节恢复、错误输入、公开哈希重算后仍被 AEAD 拒绝、真实复制/导出成功后
受控丢回复、部分报告写入、空钱包、已收录、过期、低高度回滚及同高度合法分叉拒绝，
以及原钱包/历史字节不变。验证驱动会创建签名
测试付款，产品模块本身没有签名/广播操作。丢回复是受控错误，不是真实断电或进程强杀实验。

未经过本阶段准确 Windows/Linux 原生 CI、非作者独立审核及源码交付目录核验前，不能将候选称为已验收。
仅有共享 Python 钱包传输的异常资源清理修复；操作白名单、请求格式、输出上限、摘要门槛和密码只走 stdin 的规则不变。
没有修改生产 Rust/Go、密码学、钱包或账本格式、限额、sync/锁和旧 CI 测试预算。
Issue #23、P2整体和外部专业安全审计仍未完成，`real_funds_allowed=false`。
