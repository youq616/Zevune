# P2：离线账本容量检查

`zevune-network storage`检查一个**已存在、未被其他进程占用**的节点账本或参考账本。仍限本机无价值资产实验；不是长期存储扩容、磁盘空闲探测、共识最终性或最新状态证明。

## 实际路径

命令核对独立固定的网络配置和资产创世摘要，检查文件类型与大小，然后启动按SHA-256固定的真实Rust worker，以原有`open`模式取得独占锁并完整重放账本。每条记录仍经过现有格式、域、授权、签名和状态检查。随后使用原IPC的Status读取状态，核对检查前后的文件身份、长度和修改时间，再关闭worker并输出报告。没有新增IPC操作或更改握手。

命令不连接RPC、广播、创建账本、提交区块、整理或清空数据，也不读取钱包口令、种子或查看密钥。正在运行的节点账本因独占锁而拒绝；要检查它，需正常停止拥有者，或使用独立的已验证离线副本。不要为了检查删除锁、签名状态或账本。

```text
zevune-network storage --no-real-funds --worker <绝对路径> --worker-sha256 <独立核对的摘要> --config <network.json绝对路径> --config-sha256 <独立保存的摘要> --journal <已有离线账本绝对路径>
```

`--create`、`--endpoint`、`--limit`、`--node`和`--tx`不属于此命令，必须拒绝。缺失/损坏/错误创世账本、运行中的账本或检查时发生普通文件替换/增长均不输出成功报告。失败不自动重试、不修复或截断文件。

## 报告与告警

报告列出已重放的高度、应用摘要、账本字节数、剩余字节、剩余记录和输出承诺槽。计费保持原64 MiB、10000条记录和65536个承诺上限；空记录包含150字节框架，每笔交易另有4字节长度。已提交高度在当前格式中等于块记录数量。报告也检查文件大小至少能容纳头部及该高度的全部空记录框架；不把这些尺寸关系当成密码学验证的替代。

各维度剩余容量低于或等于10%时单独告警；达到记录上限或不足150字节会指出空记录不能再写。少于2个输出槽时指出不能容纳当前协议的最小付款输出数。输出槽耗尽不表示空块不能写，字节、记录和输出维度不能合为一个模糊的健康状态。

`empty_block_fits_limits`只描述记录和逻辑字节上限是否容得下空块。它不授权付款、不保证未来write/fsync成功、不说明实际可用磁盘大小，也不预计还有多少天或多少笔付款。

返回的`scope`固定为`offline_replayed_journal_capacity_not_finality`；`consensus_verified`、`network_accessed`和`real_funds_allowed`都为false。即便记录的付款确有有效签名且重放一致，也没有在本次操作中验证共识提交或网络最新性。应用摘要不是最终性证明。

## 验收与保护边界

普通Go测试检查精确边界、差1字节、计数溢出、三维告警和矛盾的长度/状态输入；这里的合成状态只测试报告计算。实际operator_e2e另用真实Rust worker和Orchard付款检查初始化账本、付款落盘后大小、独占锁拒绝、缺失文件不创建、错误创世与损坏记录拒绝，以及成功和失败后文件字节不变。原四节点测试保持不变并另行回归。

同一主机上有特权的攻击者可在检查之后替换文件，或伪造相同长度与修改时间；前后元数据检查不是恶意OS防御、锁的跨副本协调或长期快照认证。运行worker使用原有可追加文件句柄，但此命令只请求状态，不调用任何写入操作。文件访问时间可能由操作系统更新，不承诺文件系统元数据完全不变。

本阶段必须收到针对准确候选提交的独立代理审核结果并核对相关CI后才能合入。该检查不完成P2的分段日志、快照、长期容量或生产存储验收，不提高任何限制，不迁移用户数据。

## 独立留存的准确检查点

恢复检查可同时传入`--expected-height`与`--expected-app-hash`，在原真实重放之后要求准确的最后高度及状态摘要匹配。旧但合法的副本、同高不同状态会被拒绝；这不验证检查点自身的可信性，也不支持较早检查点的后继证明。未传参数的旧容量检查仍可使用，并明确输出`expected_checkpoint_matched:false`。详见[检查点约束](STORAGE_CHECKPOINT.zh-CN.md)。
