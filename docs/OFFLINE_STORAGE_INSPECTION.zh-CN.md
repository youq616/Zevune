# P2：离线账本容量检查

`zevune-network storage`检查一个**已存在、未被其他进程占用**的节点账本或参考账本。默认报告协议容量；显式传入 `--disk-reserve-bytes` 时，另行查询操作系统的可用磁盘空间。仍限本机无价值资产实验，不提供长期存储扩容、共识最终性或最新状态证明。

## 实际路径

命令核对独立固定的网络配置和资产创世摘要，按配置中固定的 storage profile 打开已有账本，然后启动按 SHA-256 固定的真实 Rust worker，以原有 `open` 模式取得独占锁并完整重放账本。每条记录仍经过现有格式、域、授权、签名和状态检查。旧单文件 profile 使用 Status 并核对前后文件身份、长度和修改时间；`active_segments_v1` 使用原有 IPC4 容量查询，报告已重放活动目录的状态、逻辑字节、段数和尾段长度。worker 正常关闭后才返回容量报告。本选项不增加 IPC 操作或更改握手。

命令不连接RPC、广播、创建账本、提交区块、整理或清空数据，也不读取钱包口令、种子或查看密钥。正在运行的节点账本因独占锁而拒绝；要检查它，需正常停止拥有者，或使用独立的已验证离线副本。不要为了检查删除锁、签名状态或账本。

```text
zevune-network storage --no-real-funds --worker <绝对路径> --worker-sha256 <独立核对的摘要> --config <network.json绝对路径> --config-sha256 <独立保存的摘要> --journal <已有离线账本绝对路径>
```

`--create`、`--endpoint`、`--limit`、`--node`和`--tx`不属于此命令，必须拒绝。缺失/损坏/错误创世账本、运行中的账本或检查时发生普通文件替换/增长均不输出成功报告。失败不自动重试、不修复或截断文件。

## 报告与告警

报告列出已重放的高度、应用摘要、账本逻辑字节数、剩余字节、剩余记录和输出承诺槽。旧单文件 profile 保持 64 MiB、10000 条记录和 65536 个承诺的上限；活动 profile 保持 1 GiB、1000000 条记录、65536 个承诺和 2048 段的上限，单段至多 1 MiB。活动目录的逻辑字节包括独立 genesis 和记录帧，不是文件系统已分配空间。空记录包含 150 字节框架，每笔交易另有 4 字节长度。已提交高度在当前格式中等于块记录数量。报告也检查逻辑字节至少能容纳头部及该高度的全部空记录框架；不把这些尺寸关系当成密码学验证的替代。

各维度剩余容量低于或等于10%时单独告警；达到记录上限或不足150字节会指出空记录不能再写。少于2个输出槽时指出不能容纳当前协议的最小付款输出数。输出槽耗尽不表示空块不能写，字节、记录和输出维度不能合为一个模糊的健康状态。

`empty_block_fits_limits` 描述记录和逻辑字节上限是否容得下空块；活动 profile 还检查段数已满时尾段是否仍能容纳该帧。它不授权付款、不保证未来 write/fsync 成功、不说明实际可用磁盘大小，也不预计还有多少天或多少笔付款。

旧单文件的 `scope` 为 `offline_replayed_journal_capacity_not_finality`，活动目录为 `offline_replayed_active_segments_capacity_not_finality`；`consensus_verified`、`network_accessed`和`real_funds_allowed`都为false。即便记录的付款确有有效签名且重放一致，也没有在本次操作中验证共识提交或网络最新性。应用摘要不是最终性证明。

## 显式磁盘空间预警

在原命令后增加 `--disk-reserve-bytes 1073741824`，表示把 1 GiB 作为预警阈值；它不预留、分配或写入这些空间。该选项只属于 `storage`，支持旧单文件和活动目录，可与准确检查点参数同时使用。阈值须为规范十进制整数，范围为 1 至 18446744073709551615；空值、0、负数、前导零、溢出和重复参数均在读取配置之前拒绝。

显式检查成功后新增 `disk_space` 对象。`available_bytes <= reserve_bytes` 时 `low_space:true`，低空间仍返回完整报告并成功退出；自动化应读取此字段决定是否告警。`space_reserved` 始终为 false。操作系统查询失败、平台不支持、目标身份变化或关闭失败均返回错误，不把未知空间写成 0 或“空间充足”。输出写入失败也返回非零状态，可能已写出部分 JSON，调用方应同时核对进程状态和完整 JSON。

| 字段 | 含义 |
| --- | --- |
| `disk_space.scope` | Linux 为 `linux_f_bavail_bytes`，Windows 为 `windows_caller_available_bytes` |
| `disk_space.available_bytes` | 随后的系统查询观察到的可用字节，不是协议剩余容量 |
| `disk_space.reserve_bytes` | 操作者给出的预警阈值 |
| `disk_space.low_space` | 可用字节是否小于或等于阈值 |
| `disk_space.space_reserved` | 固定 false，没有空间预留 |

未传选项时完全省略 `disk_space`，原两个库 API 和 `storage-copy` 保持原行为。协议 `warnings` 和 `empty_block_fits_limits` 的定义不变。系统查询时点、路径与配额语义详见[磁盘预警设计](DISK_SPACE_WARNING.zh-CN.md)。

## 验收与保护边界

普通Go测试检查精确边界、差1字节、计数溢出、三维告警和矛盾的长度/状态输入；这里的合成状态只测试报告计算。实际 operator_e2e 使用真实 Rust worker 和 Orchard 付款检查初始化账本、付款落盘后大小、独占锁拒绝、缺失文件不创建、错误创世与损坏记录拒绝，以及成功和失败后文件字节不变。本轮保留原四节点真实付款、整网重启及签名/重放断言，并在该场景中新增显式磁盘检查。

同一主机上有特权的攻击者可在检查之后替换文件，或伪造相同长度与修改时间；前后元数据检查不是恶意OS防御、锁的跨副本协调或长期快照认证。运行worker使用原有可追加文件句柄，但此命令只请求状态，不调用任何写入操作。文件访问时间可能由操作系统更新，不承诺文件系统元数据完全不变。

本阶段必须收到针对准确候选提交的独立代理审核结果并核对相关CI后才能合入。该检查不完成 P2 的快照、长期容量或生产存储验收，不提高任何限制，不迁移用户数据。

## 独立留存的准确检查点

恢复检查可同时传入`--expected-height`与`--expected-app-hash`，在原真实重放之后要求准确的最后高度及状态摘要匹配。旧但合法的副本、同高不同状态会被拒绝；这不验证检查点自身的可信性，也不支持较早检查点的后继证明。未传参数的旧容量检查仍可使用，并明确输出`expected_checkpoint_matched:false`。详见[检查点约束](STORAGE_CHECKPOINT.zh-CN.md)。
