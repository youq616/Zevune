# 真实授权验证结果的精确字节缓存

这是进程内的性能优化，不是新的密码算法，也不是账本许可缓存。禁止真实资金。

## 保持的验证语义

`AuthorizationVerifier` 仍自行构建固定 Orchard 验证密钥。每次调用先进行完整、有界、规范的交易解码。只有某一组完整字节的所有花费签名、绑定签名和真实证明都已经通过检查，才可能记录成功结果。

命中同时比较 SHA-256 摘要和完整字节，即使测试强制制造相同摘要，不同字节也不能命中。没有接受调用方的成功标记、导入缓存、磁盘缓存、可选电路、跳过验证开关或失败结果缓存。新进程、新验证器的缓存为空。锁损坏返回错误，而不是返回成功。

容量为 64 项，先进先出。单项字节数不超过 28102，保存的交易字节最大合计 1798528 字节，不含容器和分配器开销；验证期间仍有解码等临时分配。缓存只保存公开签名交易，不保存种子、查看密钥、金额明文或证明见证。

## 不能被缓存替代的检查

付款是否过期、历史根是否属于当前可信账本、花费标识是否已经使用、输出是否重复、区块高度、费用累计、候选区块原子性和磁盘提交仍由现有状态机重新检查。预执行修改缓存不会修改账本。缓存命中不是到账、最终性或允许重复花费的证据。

由于固定的签名和证明验证只依赖交易字节及固定协议参数，复用该检查不会因为当前账本变化而授权另一笔花费。未来更换协议参数或验证密钥时必须重新构建验证器，不得复用旧缓存。

## 测试与性能边界

新增测试覆盖完整字节匹配、强制摘要碰撞、容量淘汰、重复插入、长度限制、8 线程并发；真实证明测试覆盖冷验证、32 次复用及金额上下文、密文、承诺、签名、证明被修改后的拒绝。另以真实非零金额交易验证缓存热状态下的双花、原子性、过期、错误历史根和重启恢复。

`AUTH_CACHE_SAMPLE` 仅记录一次首次授权验证和 32 次重复授权调用。它不包含证明生成、网络、共识、落盘或收款同步，不能换算成 TPS 或端到端 p95。测试不以“机器必须达到某个微秒数”作为正确性门槛。

时序差异、内存访问和进程活动并没有被隐藏；此优化不提供网络匿名性或侧信道安全证明。外部审查和生产压力测试仍未完成。
