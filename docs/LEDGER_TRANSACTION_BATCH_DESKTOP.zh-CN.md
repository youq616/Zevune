# 批量历史交易核查桌面 v1

本模块是 C22 批量查询的独立 Windows/Linux 图形入口，不改批量核心、单笔查询、原生验证器或原桌面。
流程为五项独立依据＋逐行交易清单 → 完整冻结确认 → 一个非daemon工作任务 → 整批结果。
始终 NO-FUNDS；历史纳入不是当前结算，缺席不授权重复付款。

## 启动及输入

需要可信 Python 3.10+ 和 Tk。实际核查另需独立批准的单链接原生恢复程序，以及已停止写入且与独立
检查点精确对应的本地账本。不要把新文件混入旧 v2-v9 或固定10文件源码安装目录。

```powershell
python .\scripts\ledger_transaction_batch_desktop.py --no-real-funds
```

填写账本目录、完整 ZVARCP01 检查点、创世文件 SHA256 签名域、批准程序路径与独立 SHA256。交易清单
每行一个64位小写十六进制ID，1—32项互异，保持输入顺序。接受LF或CRLF及一个可选末尾换行；不接受
空白行、前后空格、重复、大小写修复或Unicode分隔符，不静默截断/去重/排序。处理上限2112字符，
读取文本前检查长度；这不代表任意巨量粘贴不会占用Tk自身内存。没有文件导入、持久设置或自动安装。
独立摘要不能从待验证程序或账本自行计算后赋予信任。

点击“核对输入”只做纯输入校验，展示全部依据和带序号的完整ID清单，不读文件或启动后端。默认取消；
回车不会直接启动查询，Escape取消确认，不抢占其他应用焦点。只有明确确认才启动原批量核心。

## 整批结果及显示边界

原C22先执行一次新的 `verify-active` 原生重放，再为每个ID完整扫描，最后复查全体文件。仍是N次扫描，
不是单遍索引；沿用同一300秒预算。这里没有新增记录解析器、验证缓存、重试或预算续期。
大型归档可能在预算内无法完成32项，失败必须是整批失败，不把未完成项当作缺席。

显示前另行核对所有返回字段、精确类型、检查点与程序摘要、一次重放/完整扫描标志、计数、ID顺序。
每项位置复用原单笔桌面的严格显示校验，任何一项错误使整个批次不显示有效结果。这是显示边界检查，
不是模拟原生验证。传回主线程的显示文本和查询ID元组不可变，不缓存原结果字典或异常对象。

“复制本批查询ID”需要明确点击，按原顺序复制全部查询ID（包括缺席项），不是付款凭证或批次报告。
所有可选择文本关闭自动选择区导出；不会在点击查询或选择文字时擅自更新X11 PRIMARY/系统剪贴板。
清除显示不清空其他系统剪贴板历史。ID、路径和公开回执可能关联交易，应保护本机、屏幕和剪贴板。
不需要或显示钱包密码、种子、私钥、地址、金额或交易原始字节。

## 编辑、异步任务及关闭

多行文本通过Tk修改通知使结果失效，并在核对、确认、复制、观察完成时同步检查实际文本。即使程序性
编辑后通知事件尚未执行，也不能用旧清单启动查询或复制旧结果。确认时已经冻结完整请求；运行中编辑
不会启动第二个批次，原任务完成后其迟到结果被丢弃。不会一边运行一边显示部分“成功”。

复用原任务准入等待、启动中断归属、完成事件且真实线程退出、一次性计时器票据和重复关闭逻辑。
界面线程不执行重放，工作线程不调用Tk。不以 `ident=None` 推断系统没有创建线程；未准入请求可撤回，
已运行任务不能伪装成取消。任务运行时关闭只登记退出并等待，正常收尾后才销毁窗口。持续启动不确定、
Tk失败或无完成信号时保守停止并提示结束应用进程，不偷偷重试、重新获得预算或开启第二线程。

操作系统阻塞及原生清理可能超过墙钟预算，不保证硬实时终止、强制取消或任意异常下正常退出。前后
文件核验不是跨文件原子快照、全程锁或恶意文件系统防护，仍需可信主机、解释器、程序及停止其他写入。
不提供Windows完整ACL、物理断电或查询后持续监控保证。原状态/容量/格式/密码学/同步锁/包合同不变。

## 测试及验收

纯显示数据只在 `present` 函数边界测试，不注入工作线程冒充原生成功；线程/UI路径使用真实拒绝任务，
包括实际OS线程启动窗口中断、完成事件早于退出、计时器登记中断、重复关闭、多行通知尚未送达和新旧
桌面并存。原型测试结果不是原生付款或历史验证证据。

新原生驱动保留完整C22安装/恢复/单笔/批次流程，在四类真实历史执行实际GUI查询、错误摘要拒绝、
32项结果及显式复制、真实迟到结果丢弃与关闭等待。成功结果必须来自原Rust，不设置生产故障开关。
