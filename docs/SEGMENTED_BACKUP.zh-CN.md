# P2：检查点绑定的不可变分段备份

范围：本机、无价值测试资产。将现有公开账本的**原始字节**拆成固定大小的备份段，验证时跨段逐条重放，恢复时仅创建新的原格式日志。不是活动节点的分段日志，不是状态快照、裁剪、快速同步或完整验证者恢复；原有64 MiB、10000条记录和承诺容量上限不变。

## 真实调用路径

`zevune-pool-recovery pack` → 已验证的 `RecoveryArchive::pack_new` → 不可变段文件和清单 → `SegmentedArchive::verify` → 共用的头部解析和隔离 `Replay` → 原有真实 Orchard 授权及状态规则。

`verify-segments` 直接按段流式读入重放器，不需要先合成为临时大文件。`restore-segments` 先重放验证源，再向全新文件复制，通过持有锁的目标句柄执行正常日志恢复验证，最后再次检查源。成功输出的检查点和日志字节与分段前完全相同。

## 格式和信任

每段固定1 MiB（末段可较短），按顺序命名 `segment-000000.bin` 等，最多64段。边界允许穿过旧日志记录；它只是备份字节分片，不能把某段当作单独有效的账本。

`MANIFEST` 使用二进制 `ZVPSEG01`：

| 位置 | 字段 |
|---|---|
| 0–7 | 魔数 |
| 8–127 | 原120字节 `RecoveryCheckpoint` |
| 128–131 | 固定段大小，大端u32 |
| 132–135 | 段数量，大端u32 |
| 136起 | 每段：长度大端u32 + SHA-256，共36字节 |

清单最多2440字节。段数量和每段长度从**独立保留的原检查点**精确推导；清单不能自行选择路径、容量、数量或另一检查点。缺失、多余、重排、截断、链接/非普通文件、内容损坏和清单尾部数据均拒绝。

先检查每段长度与摘要及拼接后的整体摘要，再完整执行所有记录，核对创世身份、高度和应用状态，最后再检查原字节。即使攻击者重算段摘要、清单和外部校验和，错误签名或错误后状态也不能跳过真实重放。文件哈希只用作完整性绑定，不是代码签名、共识证书或最新高度证明。

## 写入与失败

`pack` 的输出目录必须不存在；不创建父目录，不覆盖、删除或修复旧文件。每段使用原子仅创建模式及独占文件锁，写入并同步后，最后创建并同步清单。Unix上还同步目录与其父目录。**清单存在不等于成功**，必须运行完整验证；失败可留下未完成的目录，也可能在完整写入后丢失成功回复。不得自动重试或删除重建。

新建归档在返回对象存活时仍持有原写者锁，通过这些原句柄验证；不解锁重开来绕过Windows文件锁。关闭后重新打开使用共享只读锁，可同时存在多个读取者，遵守锁的写者被拒绝。每个归档最多65个文件句柄，另持有1个目录句柄（合计最多66个）。这里的锁不是恶意操作系统或不合作写者的安全屏障。

恢复仅创建新文件；失败可留下部分或完整目标。恢复到归档内部会破坏其严格文件集合，所以写入前解析父目录别名并拒绝。原归档和原日志不删除、不退休；恢复后必须独立决定哪个副本继续使用，不能同时启用两个具有同一验证者身份的节点。

父目录、操作系统、文件系统和存储硬件仍须可信。不保证抵抗任意恶意路径替换、瞬时修改后还原或真实断电；Windows没有获得与Unix目录同步完全相同的承诺。这里不备份CometBFT数据库/WAL、密钥、最后签名高度或钱包，不能自动将恢复结果启用为验证节点。

## 操作入口

使用现有 `zevune-pool-recovery` 可执行文件，不增加依赖、不修改原五文件交付包。所有命令要求绝对路径和 `--no-real-funds`：

```text
zevune-pool-recovery pack --no-real-funds --source <原日志> --output <不存在的归档目录> --checkpoint <独立保留的240位十六进制检查点>
zevune-pool-recovery verify-segments --no-real-funds --source <归档目录> --checkpoint <检查点>
zevune-pool-recovery restore-segments --no-real-funds --source <归档目录> --output <不存在的新日志> --checkpoint <检查点>
```

原 `checkpoint / backup / verify / restore` 行为保留。程序不联网、不读取钱包密码、不输出私密数据。成功仍明确标记 `finality_verified:false`、`validator_ready:false` 和 `real_funds_allowed:false`。

## 验收边界

测试覆盖1 MiB真实跨段/跨记录重放、清单长度与计数炸弹、原字节恢复后继续提交、读锁/覆盖拒绝、段或清单损坏、目录发布前和发布后丢失确认、恢复半写入/丢失确认、以及真实付款恢复后再次花费与双花拒绝。恶意签名测试重算所有普通哈希，避免在错误层提前拒绝造成假阳性。7200个空块的跨段测试只证明存储边界，不是付款负载或TPS成绩。

本说明不是测试执行记录。验收需准确提交的Linux/Windows结果、作者冻结差异后的复核和不同代理的独立审核。P2仍未完成活动账本分段、状态快照与长期容量扩展。

## 读取错误后的行为与真实跨段付款

分段读取实例遇到非 `Interrupted` 错误后永久失效，后续非空读取不再访问任何段。临时中断保持可重试，空缓冲区读取不推进游标。外层 `Replay` 原本也会丢弃失败重建；这次是底层读取的纵深防护，不表示原接口会接受失败历史。归档显式重新验证仍会建立新读取实例，不自动修复或跳过损坏段。私有读取器的泛型只用于标准 `Read` 边界测试；生产调用仍使用已持锁的 `File`，没有模拟验证器或新公开输入接口。

新增专项覆盖各段起点、段内和段尾的一次性读错误，错误后再次读取，临时中断与短读，以及“读满所需字节后仍有额外尾字节”的拒绝。进一步用真实 LAB2 零金额授权交易跨越实际 1 MiB 边界，检查原字节恢复、恢复后继续提交和重复交易拒绝；非零金额恢复后再次花费由保留的原真实付款测试单独覆盖；修改第二段中的真实签名并重算所有普通哈希仍须被真实授权拒绝。填充空块只用于定位分段边界，不计为真实支付吞吐量。跨段密码学样本不冒充非零金额支付；完整非零金额跨段压力样本单独试验，不加入每次执行的基础回归负载。

以上描述是实现与测试范围；是否执行通过以准确提交的验收记录为准，不能据此宣称零缺陷、网络匿名或生产存储已完成。

Windows 的目录构造只读配置使用不可变绑定；Unix 的 `0700` 配置仅在对应平台的局部可变绑定中执行。修正了 Windows 严格静态检查中的 `unused_mut`，没有关闭 `-D warnings`，也没有扩大文件写权限或更改创建目录行为。

## 归档路径与已验证句柄绑定

重新校验不能只验证打开时的旧文件句柄，却把成功结论归给已被替换的路径。实现保留归档目录句柄，在文件摘要检查前后同时核对目录及清单/各段的当前路径。Unix比较设备号与inode；Windows归档文件和目录句柄取消DELETE共享，在打开期间阻止通常的重命名/替换，关闭后可以显式移动并重新打开。文件内容仍需原有摘要及真实授权重放验证，身份检查不替代它们。

恢复在创建新文件之前先检查归档路径绑定，因此不能把被移动的原归档与同名替代目录混淆，绕过目标不得位于源归档内的检查。检测到替换会失败，保留所有现存文件；不删除新文件、不修复原目录，也不自动改用当前路径的另一个文件。重新打开即使字节相同仍须完整验证并使用原独立检查点。

此机制针对可观察的持久替换，不宣称抵抗检查间瞬时替换再还原、恶意父目录/别名变化、文件系统或内核欺骗。旧合法检查点仍可认证旧数据，不证明最新高度。Windows新增行为必须在原生环境验收；Linux测试不能替代该步骤。
