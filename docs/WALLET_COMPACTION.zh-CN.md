# 钱包日志整理：创建新文件，不覆写旧文件

范围：P2 的有界钱包存储增量，不是生产账本扩容、协议升级或主网验收。沿用 `ZVWJNL01`、256 条记录上限、现有密码派生和加密算法。所有操作只用于无价值测试资产。

## 解决的问题

旧日志达到 256 条后可以按完全相同的历史恢复，但不能继续保存新的检查点。现在 `WalletStore::compact_copy_new` 将已认证的钱包快照和完整待发送交易重新加密到一个全新、单记录的日志中，恢复 255 条可追加记录额度，而不是把容量常量调大或直接删除旧记录。

本地控制台增加 `compact` 操作（IPC 操作码 10，恰好两个绝对路径字段：源文件与目标文件），要求显式提供源日志的**当前**回执；仅是旧祖先回执也会拒绝整理。源文件保持原字节。目标必须不存在，不覆盖、不原地截断、不自动迁移。

顺序：核验源文件和当前回执 → 保留完整快照及签名字节 → 创建新日志身份 → 写入并同步文件 → 在支持的平台同步父目录 → 通过已持有的文件锁句柄重新读取 → 认证解密并逐字节核对快照和 outbox → 再次核验源文件 → 返回新文件及新回执。

整理不生成新支付证明、不重新签名、不更换网络域、不调用网络、不解除预留。读取待发送交易时仍执行原有真实授权验证。新钱包恢复后仍是未同步状态；必须重新验证历史才能报告余额或继续付款。

## 操作（开发者参考，不要求用户反复验证）

```text
python scripts/zevune_wallet.py --no-real-funds --backend <可信后端> --backend-sha256 <独立核验的程序摘要> --pin <当前源日志回执> compact <源钱包绝对路径> <不存在的目标钱包绝对路径>
```

前端要求输入 `COMPACT` 并使用隐藏密码输入；口令不进入命令行、环境变量或回执。源文件容量可先通过 `storage` 检查。从不可信文件自行取得摘要，不构成独立回滚保护；沿用原来的独立回执信任要求。

成功返回 `result: compacted_copy_not_synced`，`source_retained: true`，`requires_rescan: true`，以及 `source_receipt`、新的 `receipt` 和一条记录的 `wallet_storage`。不返回余额、到账状态或新交易标识。前端核对这些字段和两份回执，异常回复不能被解释为可再次付款。

将新回执独立保存，后续明确选择新文件，并按原可信历史同步。旧文件保留为离线备份，不要让两个副本同时作为活动钱包。原进程中旧 `WalletStore` 在成功交接后停用，但**旧文件并未被撤销**，其他进程仍可能打开它；文件锁不是跨副本锁，无法撤销已经复制的密钥。

## 回执与故障边界

整理产生新的日志 ID 和从 1 开始的新代数，旧回执不属于新日志祖先；用旧回执打开新文件必须失败。返回的回执对是可信本地操作的交接记录，不是从目标文件就能独立验证的跨日志谱系证明。目标文件本身不保存原日志的全部记录；旧文件承担旧历史留存。新日志后续仍遵守原有回执祖先检查。

目标创建、写入、同步、认证或源文件复查失败时，不报告成功、不截断源文件、不删除目标。失败可能留下半条记录，也可能已经完整写出目标但丢失确认；因此不能自动重试覆盖或假定目标不存在。先检查两个文件、保留原始证据并明确选定唯一活动副本。整理不是签名交易取消机制。

Windows 文件同步执行，但没有声称与 Unix 父目录同步相同的目录持久化保证。正常文件锁依赖受信本机和私有数据目录，不抵抗恶意主机、存储固件、磁盘克隆或文件被事后替换。参考 Rust 官方 File 和 OpenOptions 文档：
- https://doc.rust-lang.org/std/fs/struct.File.html
- https://doc.rust-lang.org/std/fs/struct.OpenOptions.html

## 必要回归

覆盖：精确回执与旧祖先拒绝、目标已存在/源文件自身/目录拒绝、源文件损坏与不可用拒绝、半写入及完整写入后丢确认、源字节不变、目标锁、新回执重新打开、未同步余额拒绝。完整容量测试通过真实加密 writer 填满 256 条记录，恢复并整理真实待发送付款，再核对字节相同；确认后继续下一笔真实付款，重复花费仍被账本拒绝。

Python 前后端还需实际联调，而不是仅测试假的回复。文件整理的成功不能代替多节点共识、最新状态、端到端性能或完整 P2 存储验收。
