## 保护目标和资产

目标是让公开节点验证支付规则，同时不向节点或开发者提供花费密钥、查看密钥、种子、明文支付见证或全网解密权限。链上证明、加密钱包、本机通信限制、用户确认和离线文件校验分别保护不同边界，不能互相替代。

重点资产：可花费资金与防双花状态、钱包秘密和精确pending字节、独立网络身份与恢复回执、验证者签名状态、构建/发布来源、用户明确批准的操作，以及交易关联元数据。当前只允许无价值实验资产。

## 对手与当前覆盖

| 对手/故障 | 当前防线 | 未解决或不承诺 |
|---|---|---|
| 恶意交易/错误域/重放 | 原真实Orchard、签名域、状态与提交重查 | 全克隆创世和分叉区分、主网经济攻击 |
| 恶意RPC提供者 | 固定信任配置、法定票权签名头、完整重执行和后置状态匹配 | 全局最新状态、动态验证者引导、抗全部隔离攻击 |
| 文件损坏/错版本/普通并发替换 | 有界严格解码、独立摘要/回执、前后字节与身份复查 | 恶意内核/文件系统、时间戳恢复、跨文件原子快照 |
| 崩溃/超时/丢失回执 | 原同步/锁、未知结果保留、pending精确恢复、新目标不覆盖 | 任意硬件掉电、完整目录持久性或跨平台ACL保证 |
| 被替换的程序/依赖 | 独立程序摘要、固定来源和依赖、受控构建 | 摘要等于签名、所有许可证已审核、最终制品供应链无风险 |
| 本机窥探/界面陈旧状态 | 密码隐藏输入、通知与操作边界同步、显式复制、工作线程所有权 | 键盘记录、终端截屏、交换区、恶意解释器、剪贴板历史、绝对内存擦除 |
| 网络端点或全局流量观察者 | 目前只有本机回环RPC限制 | 网络隐私未实现；不能声称隐藏IP、时序或端点关联 |

法定票权联盟可阻断推进或破坏可信链假设，四个进程不等于四个独立主体。三台等权节点在线的实验只能在既定票权/网络条件下解释，不能宣称抵抗任意投票权攻击。

## 明确公开与关联信息

公开创世分配包含地址、金额和note openings，不是匿名发行。交易可暴露承诺、nullifier、anchor、密文、动作数量、长度、费用、到期高度、排序和时序。节点、收发对手和端点日志仍可能关联行为。任务/报告/交接包包含查询ID和独立摘要，hex编码不是加密，哈希和隐藏显示不是零知识隐私。

当前离线查询的“纳入”只指指定已验证历史中的精确字节；缺席不证明其他分叉或较新高度没有该交易。mempool接收、文件一致和恢复成功均不是支付最终性。任何未知结果不允许自动重签、清除预留或生成第二次付款。

## 已选择的实现方向（尚未交付）

P5优先采用成熟Tor v3 onion服务与本机SOCKS客户端，域名交给代理处理，按钱包操作隔离连接；隐私模式代理失效时明确失败，禁止隐式直连/DNS或透明付款回退。服务身份与账本可信头分开验证，不把Tor连接成功当成链认证。无需用户再次选择这一工程方向，但改变依赖/后端前仍须独立设计审查与测试。

必须测试广播、同步与查询都经过所选隐私路径，包括失败、重连、代理认证、连接复用、DNS以及日志。不能仅用“没有网络请求”的离线测试代替网络隐私验收。Tor本身不是抵抗全局关联、恶意终端或知情交易对手的绝对保证。实现版本、参数、分发许可和实验配置须固定后再验收，当前状态仍为not_implemented。

## 验收和残余风险

P5需要可复现端点/时间关联实验、数据流/日志清单、无回退回归和性能分布；最终协议/密码学/隐私由独立专业审查覆盖。不能把本威胁模型写成现有隐私实现的证明。仓库 `PRIVACY_BOUNDARIES.zh-CN.md`、`SECURITY.md` 与原测试边界继续有效。

外部依据：Tor官方SOCKS扩展说明远端解析和stream isolation；仅用于上述设计方向，不表示Tor项目审查了Zevune。见 `SOURCES.md`。
