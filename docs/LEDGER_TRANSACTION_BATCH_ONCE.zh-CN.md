# 单遍批量历史交易核查 v1

新增独立CLI把同一检查点下的1—32个交易ID合并到一次记录定位扫描。每次仍先执行一次原
`verify-active`完整原生重放，然后核对完整记录、独立布局摘要以及前后文件身份。不新建证明系统、
授权缓存或常驻索引。NO-FUNDS，不允许真实资金。

## 使用与兼容

需要可信Python 3.10+、独立批准的单链接原生恢复程序、停止写入的本地归档及独立检查点/签名域。
重复提供`--txid`，顺序保持；零项、重复、格式错误或超过32项整批拒绝，不排序、去重或修剪。

```powershell
python .\scripts\ledger_transaction_batch_once.py --no-real-funds --journal 'C:\Zevune\stopped-archive' --checkpoint '<独立256位检查点>' --genesis-sha256 '<独立64位签名域>' --backend 'C:\Approved\zevune-pool-recovery.exe' --backend-sha256 '<独立64位程序摘要>' --txid '<64位交易ID一>' --txid '<64位交易ID二>'
```

追加`--text`输出中文，默认UTF-8 JSON。格式为`zevune-ledger-transaction-batch-once-1`，明确不同于
旧批次格式。旧单笔、旧批次及所有桌面的输入/输出语义保持；**桌面尚未切换到单遍入口**。
原单笔公开段扫描器抽取为共享`scan_segment_many`，原`scan_segment`保留原返回合同。
没有两套生产记录解析器，也不在生产代码中全局替换函数。

## 一次扫描不等于只读一次磁盘

一次新的真实原生重放仍是成功的必要条件。定位扫描中，每个记录段只解析一次，每条交易只计算
一次SHA256，以最多32项的集合匹配；保留最多32个位置，使用原1MiB段缓冲。定位阶段从原N次完整
扫描降为一次，与ID数无关；前置指纹、原生重放、末尾指纹仍分别读盘，不省略这些安全检查。
集合成员查询的平均工作量近似O(1)；总体记录扫描随账本字节增长，输出随请求数增长。不能把
“32次定位读取降为1次”说成端到端32倍加速、交易吞吐增加或已通过原生十万块增长验收。

完整保留原帧长度、校验和、连续高度、状态哈希衔接、规范物理轮换、末端状态和独立ZVARLY01布局
检查。即使全部ID已经找到，也必须检查到末尾。请求交易多次出现、尾损坏、同字节换文件或查询
期间修改输入均使整批失败，不返回有效的结果前缀。未找到与失败严格区分。

预检、原生重放、扫描及末尾检查共享300秒单调时钟预算，不续期、不重试、不接受扩大预算参数。
系统IO和原进程清理可能阻塞更久，不承诺硬墙钟截止。结果最多64KiB，输出成功同时要求退出0，
短写/flush错误产生的前缀不能当成完整结果。错误1、参数64、中断130。

## 结果

`results`逐项内容与原批次一致；`query_count`、`included_count`、`absent_count`相互一致。
`native_replay_count=1`与`history_scan_count=1`只在完整成功后输出；空账本也算一次完整的空遍历。
`scanned_records`、`scanned_transactions`是实际定位扫描的历史总数，不按ID重复累计。

纳入只意味着精确交易字节在指定已验证历史中存在，不验证收款意图/金额/当前链或共识最终性。
缺席不授权重复付款。钱包、收款人/金额、finality、retry、可携带证明、真实资金标志仍false，
当前高度null、广播与结算unknown。查询ID可能关联交易，应保护本机终端与进程参数。

## 验证边界

单元测试使用未授权公开记录，核对多ID与原查询的一致性、真实段读取/交易哈希次数、跨段边界、
全部ID命中后的坏尾、重复位置、大小/布局/文件身份和失败路径，不伪造成功原生回执。
新native驱动保留原安装/恢复/批次全流程，另对四类真实历史逐项比较两入口，验证32项仅一次原生
调用和一次记录段解析、CLI JSON/中文、坏账本和真实原生成功后/扫描后变更拒绝。准确候选的测试
执行与审核结论单独记录，工作流存在不等于验收通过。

只修改共享公开扫描器，不改Rust/Go、原密码学、格式、容量、锁、依赖、旧工作流或固定包清单。
输入需停止外部写入、主机和父目录需可信；没有跨文件原子快照、恶意FS防护、完整ACL、断电或持续
监控保证。P2/P4整体及Issue23/37不因该优化自动完成，主分支合并和真实资金准入不是本模块权限。
