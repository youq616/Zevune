# P2：节点、钱包历史与备份的统一账本重放

范围：无价值测试资产的本机实验。接续 `f4a4741` 的共享隔离重放及检查点备份恢复，统一头部和 EOF 检查；不是节点快照、快速同步、日志分段或生产级长期容量交付。

## 实际接入路径

`PoolStore::open_with_policy → replay_locked_file`、`wallet_history`、`RecoveryArchive::open/copy_new` 共用 `pool/replay.rs`。后者仍通过持有锁的同一文件句柄验证，不能为方便重放而解锁并重新打开文件。保留检查点导出的逐块丢弃模式，不为校验额外收集钱包完整历史。备份的文件摘要与检查点比较、正常启动的独立创世配置、钱包历史的最终已提交摘要比较分别保留，不用一个解析器替代这些不同的信任条件。

共用的头部读取器只接受原有 LAB1/LAB2 魔数、固定网络摘要和有界承诺数量，LAB2 域不得为零。先检查记录数量、精确长度和剩余文件大小，再为头部承诺和记录缓冲区申请有界容量；解析头部本身不提供资产授权。实际承诺解析和逐笔证明/签名仍由原有状态机完成。

## 状态所有权与失败行为

恢复过程只持有一份尚未公开的重建状态，按顺序检查每个记录的前状态、交易和后状态。`next_block` 在开始任何读取或执行之前取走内部状态；任何读取、解码、授权、双花或状态摘要错误都会丢弃该重建，不能捕获异常后跳到下一条记录。中间块只允许内部收集，钱包必须等整个文件验证结束并与原已提交状态匹配，才返回历史。

读到最初捕获的文件长度不算完成：必须再验证真正 EOF。额外尾部字节和读取错误都拒绝；操作系统返回 `Interrupted` 时重试，不把临时中断视为文件结束，也不直接报告成内容损坏。原备份摘要读取的最后一次 EOF 检查也使用这一规则。

私有 `execute_unpublished` 只能用于这种可整体丢弃的重建，或正常 `execute` 自己持有的临时副本。正常 `prepare/commit` 仍先复制已提交状态，失败不得改变活跃账本；增量提案筛选继续逐笔原子检查，不能用会部分修改重建的函数代替。区块内可信根始终取自区块前已提交状态。

## 减少的工作与仍然保留的成本

旧节点与钱包各维护重放循环，并在恢复每块时复制完整账本集合。现在重建过程不再每块复制这些集合，帧读取复用一个有上限的缓冲区。测试构造完整 10000 条空记录窗口，验证重放未调用整状态复制路径；正常准备交易仍调用该路径，以维持已提交状态隔离。该计数只存在于测试构建。

这不是实测到账速度、证明速度或 TPS。摘要计算仍扫描有关状态集合；钱包历史仍收集受限完整历史，备份仍全量复制并真实重放。保留 10000 条日志记录、64 MiB 日志、65536 个承诺和每块 16 笔等当前上限；没有扩容或裁剪防双花信息。

## 兼容与反例测试

保留交易、签名域、检查点、日志、IPC、共识和依赖锁。旧 LAB1 不自动变成 LAB2；原文件不转换、截断或修复。备份失败可能留下部分或完整新目标的规则不变；此功能也不备份或恢复验证者最后签名状态。

专项覆盖：两种头部格式及逐字节截断、未知网络/版本/零域、超大计数、短读取与临时中断、缓冲区长帧后短帧、301 个记录读取故障位置、提前 finish、检查结束时仍有尾部、有效交易之后再发生双花、重算普通校验和后的坏签名、虚假后置状态，以及真实恢复后继续支付。备份专项确认导出检查点、验证归档、复制目标和重新打开均使用共享重放，且不修改原字节。

恢复后只证明输入记录在指定规则下有效，并不自动证明全网最新性或共识终局性。完整合法旧前缀需要独立可信检查点检测回滚；文件锁和校验不能替代可信操作系统、目录与磁盘。故障注入不是任意断电安全保证。

本说明不代替准确提交的 CI、独立代理审核或外部安全审计。P2 全模块仍在开发中。
