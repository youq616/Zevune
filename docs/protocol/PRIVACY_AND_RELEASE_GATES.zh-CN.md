# 隐私边界与整合交付门槛

本文件是基于当前代码新增的说明，不是六份历史缺失文档的“恢复副本”。不把完整性哈希、网络域标识、测试通过或成熟密码库等同于整个新链已经审计。

## 可验收目标，而不是绝对不可追踪承诺

目标是：账本正确性公开验证，个人付款内容默认加密，开发者不保留全网查看密钥。网络域隔离只防止特定跨网络交易重放，不隐藏网络连接、不消除交易元数据，也不会把资产来源的法律性质改变为“干净”。本版本不是主网。

| 对手或观察面 | 当前范围 | 明确没有保证的部分 |
|---|---|---|
| 被动读取公开链上数据 | 真实 Orchard 证明和普通付款密文；不提供全局查看密钥 | 时间、交易字节长度、动作数量、公开费用、花费标识、承诺和区块顺序仍是公开数据 |
| 错误网络或版本 | V2 核心通过域绑定签名、账本初始化及加密钱包状态拒绝串用 | M11 已发布网络入口仍是 V1；V2 尚未激活到完整网络；重复使用同一描述符不能区分两个实例 |
| 恶意区块或 RPC 服务 | 既有本机工具验证签名头部和实际重放结果后才落盘 | 单一服务可扣留数据；签名历史不证明是全网最新状态；动态验证者和公网隔离攻击尚未验收 |
| 窥视网络流量的人 | 目前限制同机 loopback 实验，未实现网络匿名 | IP、连接时间、流量形态及收款查询关联尚未被隐私网络层解决 |
| 有钱包副本或旧备份的人 | 加密、认证、固定 KDF 参数；独立检查点支持回滚检测 | 弱口令、被攻破设备、密码/密钥内存副本、同一钱包多副本并用、操作系统入侵没有全面保护 |
| 控制验证者或更新分发的人 | 本机固定验证者与明确测试权限；没有解密所有支付的后门 | 独立运营、投票权集中、升级治理及签名发布尚未完成；不能以“没有查看钥匙”证明无人能干预网络 |
| 收付款对手和外部业务记录 | 普通付款协议不要求把私钥、查看密钥或私密见证交给服务端 | 对手主动公开交易信息、线下身份与业务记录关联无法由链本身全面阻止 |

上述表是工程边界清单，不是对抗所有能力对手的形式化安全证明。

## 当前协议工作与停止线

新增 V2 域描述符固定了实例身份、测试资产创世摘要和一组不可变规则指纹；签名、状态及加密备份均明确绑定该域。测试要求两个网络的初始资产根完全相同但域不同，证明拒绝来自域校验/签名而非偶然的树根不同。旧交易和旧日志不自动升级。

这一步没有修改 Orchard 电路，也不把自定义摘要包装称为独立审计。V2 真实钱包与存储已实现，但完整共识/IPC/操作入口激活仍是下一项工作，不能把核心库完成当作全网启用。

## 三个交付层次

1. **本机实验版**：保留 M11 可重现的真实付款、节点、存储和恢复；禁止真实资金。
2. **完整测试网版**：明确版本和独立配置的协议激活；多机网络；贯通的钱包流程；长期存储；公开元数据与网络隐私评估；端到端延迟分位数及故障测试报告。
3. **主网候选版**：在上一层基础上完成经济/验证者/升级规则、安全分发、依赖与许可盘点、独立审查和整改。未满足项不得改写为 true 或“项目结束”。

当前不需要用户重复安装和逐项验证。代码测试使用无价值临时资产与合成口令；验证者密钥、钱包、种子、查看密钥、解密数据不得进入仓库、CI 产物或报告。只允许输出证明已经验证过的公开交易字节和非秘密描述符用于编解码交叉核对。
