# P2/P7：真实存储 Commit 内部计时

基线：PR #24 合并提交 `60b87fdb73c19288cff09aee9e63ef2a70c6bc32`。
本文件是实验合同，不是已验收、安全审计或生产就绪声明。准确候选及验收结果以阶段 PR 为准。

## 范围

Issue #23 的原 Windows 十万块超时原因仍未知。PR #24 定位到空块 Commit 调用组占主要累计耗时，
但该组包括 IPC、状态执行、文件系统检查和同步。本阶段增加 **测试进程内真实 PoolStore** 的内部计时。
它不是给原 Go→worker IPC 的同一次运行做内部剖析，不能直接从两次不同实验的差额推断 IPC 成本。

所有采集代码及调用点使用 `cfg(test)`。非测试构建没有计时模块、公开采集 API、环境开关、
额外 IPC 消息或输出；没有为生产钱包/worker 增加故障开关。原证明验证、重复执行、帧预算、
文件锁、目录/身份检查、文件同步、状态发布顺序均保留。计时结果不参与状态规则。

新增实验不替代原十万块增长验收，原工作量、20分钟场景、25分钟Go、40分钟作业预算不变。

## 计时范围及失败处理

13个不嵌套阶段分别是：预检、重复状态执行、编码完整帧、追加边界检查、尾段身份及轮换判断、
必要的新段准备、定位写入偏移、write_all、文件sync_all、必要的目录sync、写后身份检查、
账本长度元数据发布、外层状态发布。轮换与非轮换提交分别聚合。

文件同步一项是 Rust `File::sync_all` **整个调用**的时间，不是磁盘设备内部单独的刷盘时间。
目录同步是现有 `Directory::sync` 调用，沿用各平台已有实现与保证，不因计时名称扩大保证。
整个 Commit 总时间还包含采集本身的开销、阶段间代码；阶段累计和必须不大于该总时间。
固定数组只保存次数、累计和最大纳秒，不保留所有事件，不制造p95或支付TPS。

线程局部记录器只有明确建立 Session 的测试才启用；不同测试线程不会混合。Session和Attempt不能
跨线程移动；会话编号防止旧句柄的析构污染新会话。每次至多1000001次尝试，每段时间至多1小时；
单调时钟失效使报告无效，未知失败时长为null。该边界不是对原场景超时的放宽。

只有原函数全部成功、状态和长度已发布、即将返回原Ok时才记录 accepted。完成文件sync、
完成append或Finalize不能代表该Commit已经被API接受，更不能代表共识最终性。
失败尝试的已完成阶段不混入成功提交聚合，只保留最后失败的公开高度、未完成阶段、已完成阶段位图及
可观测经过时间。错误或无回执都不推断磁盘有/无完整记录，绝不自动重试、截断或修复。
采集顺序、缺项或重复项异常使valid=false；即使真实API成功，也不得把无效采样当有效性能证据。

## 真实等价控制及回归

专用原生实验在默认1MiB分段策略下执行8192次真实提交，在第2和6991块使用真实Orchard付款。
付款有效期按当时钱包历史设置，重复支付拒绝在付款后、到期前检查。两次默认大小的段创建/轮换
必须实际发生。付款后核对余额、费用，再用相同创世和完全相同的签名字节，在未启用记录器的
另一个真实存储中执行相同8192块。两边Summary、容量及关闭所有句柄后的逐文件字节必须一致。
最后完整重开计时存储、提交8193并再重开核对，关闭句柄、显式清理后才输出完整结果。

这是顺序执行的正确性控制，不是随机化的性能A/B，也不是默认worker与测试构建的性能比较。
额外实验自身总预算600秒（每块间及最终检查，不能打断阻塞的OS调用）；原生作业20分钟硬上限。
实验辅助入口普通发现时ignored，但专用CI使用准确名称显式运行。缺少profile文件即验收失败，
不能把零项匹配的cargo成功当作实验执行。原常规库测试仍运行所有未忽略用例。

反向测试包括陈旧预备候选的Stale拒绝、原有四个测试专用追加中断点，以及采集漏记、重复、
会话隔离、时钟异常。四个中断点沿用现有cfg(test)注入，并非真实ENOSPC或物理断电；全部错误
仍按原实现处理。对完整写入但未同步的重开成功，只说明当前OS可见字节，不声称断电持久性。

## 有界公开证据

CI先保存setup.json，绑定准确head/checkout/tree/platform/run/attempt，最多2KiB。
完整实验最多创建一次profile.json，最多16KiB；只包含固定schema的计数、时间和通过的正确性标记。
无地址、密码、种子、密钥、交易字节、原始错误或私有路径；CI只上传这两个固定文件。
使用create_new不覆盖旧报告；证据失败令测试或校验失败。文件存在或JSON声明完整都不替代准确CI
作业最终成功，缺少最终文件也不能宣称完成。机器强杀、panic或宿主丢失可能只保留setup。

解析器拒绝缺项、重复JSON键、非法数字、额外字段、错误阶段或计数、重叠累计、身份变化及文件越界。
故障记录用于失败诊断，不由成功实验的验收解析器接受。临时目录仍假设可信本地父目录和OS，
没有新增恶意文件系统、Windows ACL、真实磁盘满、物理断电或长期多机保证。
