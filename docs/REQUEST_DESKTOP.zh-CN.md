# 离线收款请求桌面工作台 v1

`request_desktop.py` 是 Windows 优先、同时支持 Linux 图形会话的请求创建与检查界面。它直接复用
已验收的 `payment_request.py`，不另造请求格式、地址算法或密码学。它不是完整钱包界面：没有密码、
钱包路径、余额、手续费、签名、广播、自动付款或网络同步控件。NO-FUNDS 和原有生产就绪标志不变。

## 1. 启动和运行环境

需要 Python 3.10+、Tk 支持和真实图形会话。本阶段交付独立源码模块，不是独立 Windows 安装程序；
不安装依赖、不启动节点或付费服务。使用已核验的准确仓库源码，在仓库根目录运行：

```powershell
python scripts/request_desktop.py --no-real-funds
```

帮助命令 `--help` 不需要 Tk 或显示器。
可用 `python -m tkinter` 手动检查 Python 的图形支持；缺少图形环境时本工具报错退出，不自动改用一个
未核验的替代实现。Linux 需要桌面会话；CI 用 Xvfb 测试实际 Tk，不以缺 DISPLAY 为成功或跳过。
macOS、本机高对比模式/全部辅助技术及所有 DPI/缩放组合没有获得本模块验证。

## 2. 网络输入与信任

窗口顶部选择可信本地创世文件，输入**另行保存的创世 SHA256**。不从所选文件自动填入“可信”摘要，
不从请求内部自行推断网络。路径必须绝对、规范；符号链接、reparse point、错误格式和超限文件沿用
原实现拒绝。字段限制长度并拒绝控制字符和双向文本控制符，不悄悄修剪地址、金额或摘要。

应使用原 `network-address` 流程获取并核对 LAB2 收款地址。公开校验和和网络标签不认证收款人，
独立摘要也不是数字签名；同一创世的克隆/分叉不能仅靠标签区分。不要把同一不可信目录中的摘要文本
当作独立信任来源。文件路径仍由操作系统处理，本工具不探测远程挂载是否可信；请用可信本地目录。

## 3. 创建收款请求

在“创建收款请求”页填写收款地址、正整数测试金额、到期区块高度和**不存在的新文件路径**。
金额以原整数单位解释，不按小数、法币或币种价格自动换算。有效期是区块高度，不是日期；离线界面
不查询当前链高，也不会显示“仍未到期”的保证。原金额、高度和请求大小限制保持不变。

点击“核对后创建”出现真正的确认窗口，逐项显示冻结的网络、完整地址、金额、高度、目标和明文提醒。
默认焦点在取消按钮。确认期间输入和操作按钮禁用，重复事件不会启动第二次操作；即使字段经外部
程序修改，版本检查也会拒绝使用改变后的意图。外部文件变化仍由原创建函数重新检查。

明确确认后才调用原 `create_request`，以仅创建模式写入相同规范 `.zvrequest`。已有文件不会被覆盖，
包括在弹窗打开后才由另一进程创建的文件。创建成功只表示**明文请求已保存，未签名、未付款**。
返回请求摘要，应通过可信渠道单独保存或交给付款人；文件内的 nonce 不提供链上单次支付防护。

## 4. 检查已有请求

在“检查已有请求”页选择文件，并输入另行取得的请求 SHA256。使用顶部独立网络输入，点击只读检查。
结果显示地址、金额、到期高度、请求摘要和固定限制：仅公开字节一致性检查、收款人未认证、未查询链高、
不保证单次使用、未付款。错误摘要、网络错配、重复字段、非规范 JSON、尾随/截断及文件变化继续拒绝。

界面读取使用原 `inspect_request`，没有后端选择或密码输入，不调用原 `prepare_request`。需要签名时，
退出本界面并另行使用既有付款请求命令，重新核对输入、手续费及钱包回执；GUI 不生成“允许付款”令牌。

## 5. 显示状态、隐私和异常

任何输入编辑都会清除先前成功结果、明文展示和可复制摘要；切换页面时已有结果也清除。检查失败先
移除旧结果，避免拿旧的“通过”标记解释当前文件。结果只是上次操作的观察，不持续监视磁盘变化。

只有明确点击“复制摘要”才写系统剪贴板，且只复制请求摘要，不自动复制地址、金额或原文件；系统
剪贴板历史可能保留它。“清除界面输入”不删除文件、不清除系统剪贴板，不承诺 Python/Tk 内存擦除。
文件选择器、操作系统最近访问记录、屏幕截图和远程桌面可能记录路径/明文，工具不能替操作系统撤销。

不自动保存表单、路径、最近文件或日志。源码入口在普通 Python 启动时不产生 `__pycache__`，
库导入不改变宿主解释器的策略。输入错误和意外 Tk 回调异常只显示固定信息，不向控制台输出原始
异常、请求内容或私密参数。窗口显示本来就包含明文意图，应避免录屏和公开直播。

文件写入或同步失败可能已留下部分或完整请求。界面保留输出，不删除、截断、覆盖、补写或自动重试；
提示操作者核对。取消确认前没有文件写入，但写入开始后关闭窗口或系统中断不等于回滚。文件大小虽
有界，调用仍在主 Tk 线程同步执行；慢盘/网络文件系统/阻塞内核 I/O 可使界面暂时无响应，不声称后台
任务、硬超时或强制中断安全。不存在工作线程或并行钱包操作。

## 6. 验证与程序包

头部无图形测试覆盖冻结意图、原格式往返、错误摘要/数字/网络、确认后输入变化、已有目标和部分写入
保留、意外命令行参数脱敏及 原发布合同兼容。独立 GUI 验收直接创建 Tk 窗口、操作真实输入框/按钮和模态
确认，包括取消、重复进入、字段变更、源变化、旧结果清除、窗口关闭和显式复制。公开合成字段测试
不是密码学认证，通过状态始终不带认证或付款含义。

另一原生验收以真实 Rust 钱包/创世/地址为输入，通过实际 GUI 生成请求并用旧 CLI 核验；再由测试
驱动在界面之外通过原钱包签名并恢复相同 pending 字节、交易编号和 available=0 预留。GUI 从未取得
密码/钱包路径。原生缺失或 Tk/显示不可用必须失败，不能用零项、跳过或替代验证器通过验收。

本模块不改变现有 v9 原生程序包及 v2-v9 精确校验合同。不要将额外脚本放入已核验的旧程序包目录；
旧校验器仍应拒绝额外文件。以仓库源码运行，或使用本阶段独立的Python源码目录；不是新的原生程序包。
没有新增第三方运行库，
Tk 是 Python 可选组件，不打包 Tcl/Tk、本机字体或 Python 安装器。没有修改原 Rust/Go、钱包/请求格式、
密码学、授权缓存、文件同步/锁、依赖锁、容量或既有 CI 预算。准确版本审核和平台运行结果以阶段PR为准。
这只完成 P4 的离线请求图形入口，不表示完整 Windows 钱包、在线同步、网络隐私、P2/P4整体或真实资金
验收完成；Issue #23 和 `real_funds_allowed=false` 保持。
