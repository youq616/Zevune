# 批量历史交易核查 v1

本模块为同一个独立检查点下的1—32个交易ID提供批量查询。每批重新运行一次原生 `verify-active`，
再复用原单笔完整扫描器依次查询所有ID，最后核对整个归档仍未改变。保持原钱包、账本、密码学、
后端、单笔CLI和桌面全部不变，不覆盖上轮并行本地C21候选。仍为NO-FUNDS。

## 使用

从可信源码目录运行；需要Python 3.10+、独立批准的单链接原生恢复程序和已经停止写入的本地账本。
沿用独立ZVARCP01检查点、创世文件签名域SHA256及程序SHA256，重复提供 `--txid`，结果保持输入顺序。
不从收到的文件自算摘要来赋予信任，不自动选择“最新”，不支持远程查询、钱包密码或自动安装。

```powershell
python .\scripts\ledger_transaction_batch.py --no-real-funds --journal 'C:\Zevune\stopped-archive' --checkpoint '<独立256位检查点>' --genesis-sha256 '<独立64位创世文件摘要>' --backend 'C:\Approved\zevune-pool-recovery.exe' --backend-sha256 '<独立64位程序摘要>' --txid '<交易ID一，64位小写十六进制>' --txid '<交易ID二，64位小写十六进制>'
```

追加 `--text` 输出中文；默认UTF-8 JSON。交易ID必须互异且完整，拒绝空集合、重复项、超上限和任何
格式错误，不静默去重、截短、修剪或排序。API接收list/tuple并冻结成tuple；先验证整批再接触文件。
一个ID也可使用。第33次CLI参数直接拒绝；没有扩大容量或更改协议限制。

## 工作与失败语义

一次成功必须包含：批准程序的原单链接/摘要/句柄门槛、一次真正原生重放、严格原生回执、每个ID的
完整原扫描（含命中后的尾部、独立布局摘要）、最终全体字节/身份/目录项复验。任何一项失败使整批
失败，不能输出“前几笔成功”的有效批次，不把错误变成“未找到”。没有跨调用验证缓存或授权缓存。

使用同一个300秒单调时钟预算覆盖预检、原生重放、各ID扫描和末尾复验；不因下一笔获得新预算，
没有自动重试或延长预算参数。操作系统IO及原进程清理可能超出墙钟时间，超预算不能报成功；
不承诺硬实时终止。

`batch_complete=true` 表示本次全部ID完成，`native_replay_count=1` 是本次调用的次数，
`history_scan_count=query_count` 则明确是逐ID完整扫描。它**不是一次扫描建立索引**；复用已有解析器
避免另造账本读取规则，但读盘和公开帧校验成本为O(ID数量×账本大小)。每次使用原1MiB段缓冲，最多
保存32个结果，不建立常驻索引。大型归档可能在既定300秒内无法完成32项，此时整批失败而不是降级。
没有测量或承诺吞吐提升倍数；收益是减少同一批次重复的原生授权重放。

返回的 `results` 为输入顺序，逐项包含txid、历史纳入与否、状态、位置及后续记录数。纳入/缺席计数
相加等于query_count。`scanned_records_per_query` 与 `scanned_transactions_per_query` 是每次完整
扫描的记录数，不是整批重复累计数；历史区块不是共识确认，缺席也不授权重复付款。

钱包认证、收款人/金额、共识最终性、支付重试和可携带证明标志始终false；当前链高度null，广播和
结算unknown。它只核对指定历史中的精确交易字节，不证明现在已付款、收款意图正确或别处未纳入。
原生验证失败后不复用以前的成功结果；文件检查通过也不能替代本次重放。

成功0；检查失败1；参数错误64；用户中断130。完成但全部缺席仍退出0，消费者须读取各项状态。
正常结果上限64KiB，成功输出只写一次；输出介质短写或flush失败可能留下字节前缀，因此必须同时
要求退出码0，不能把前缀当完整结果。工具不主动创建报告文件，不记录输入路径或秘密到错误提示。
交易ID作为命令行参数及输出会出现在本机进程/终端环境，应保护本机和终端记录。

## 测试与边界

单元测试只使用明确未授权的公开记录帧验证批次输入、顺序、完整扫描和拒绝路径，不注入成功的
密码学验证器。新原生驱动在不修改原安装/恢复/查询driver的前提下观察四类真实历史；每批计数原
verify-active调用及所有扫描的同一个deadline，比较与独立单笔查询结果一致，验证32项批次、CLI
JSON/中文以及第一笔后变更、最后一笔后变更均不产生部分成功输出。原10恢复场景和6追加检查保留。
双平台工作流使用固定Rust1.98.1、锁定原依赖和原20分钟/600秒预算，没有降负载或放宽断言。

使用前停止其他写入并信任解释器、操作系统、原生程序及父目录；没有跨文件原子快照、全程锁、
恶意文件系统防护、完整ACL、物理断电、校验后监控或最终性保证。新模块不混入旧v2-v9和固定10文件
源码交付清单。原并行本地候选不覆盖已验收远端。项目P2/P4整体、Issue23/37及真实资金禁令不变。
