# P2.4：完整重放后生成的备份高度索引

开发候选，禁止真实资金。已有不可变分段备份、文件/目录身份修复继续保留。本模块连接 `zevune-pool-recovery`，不是只有类型定义；不改变原清单、交易、签名、日志、检查点、IPC 或容量常量。

## 先校验，再返回导航

`SegmentedArchive::open_indexed` → 私有文件打开器 → 与 `verify` 共用的 `replay_checked` → 原 `Replay`/真实 Orchard 授权 → 最终检查点与前后文件字节/路径身份核验 → `VerifiedIndex`。

普通 `open` 同样必须经过原完整验证，不返回未经校验对象。索引构造只在本地保存逐块元数据；任一记录、最终 EOF、状态摘要或最后文件检查失败，整个索引丢弃，不能先输出有效前缀。`build_index` 对已经打开的归档也重新验证，不复用旧文件成功结论。没有反序列化或接受外来索引的接口，备份恢复和活跃账本不接受索引作为授权。

索引保存整个原日志记录的起始字节、精确长度、覆盖的首尾分段、段内偏移，以及该块前后的应用摘要。偏移由重放器已经消费的帧位置取得，不相信外部提供的高度/偏移。交易无需复制到索引中。高度0属于创世头而不是区块记录，查询高度0或超出已验证 tip 均拒绝。

## 修正此前方案中的分段假设

现有备份每段1 MiB，边界可以切开记录甚至交易。分段没有天然的独立起止状态，不能强行给每段分配互不重叠的连续区块高度，也不能以某段末尾半条记录计算所谓状态根。本索引以**完整区块记录**为基本单位，明确报告它覆盖的所有段。

例如，44字节的空创世头之后，每个空块记录为150字节。高度6991的记录从1048544开始，到1048694结束；前32字节在分段0，后118字节在分段1。索引须同时返回两个分段，不能只返回一个段就声称找到了完整块。该空块示例只说明存储定位，不是支付吞吐量数据。

`before_app_hash` / `after_app_hash` 来自真实完整块执行，不是新的 Segment Root，不是共识签名或快照。原清单已经有顺序、精确长度、每段哈希和独立检查点；这次不增加一套重复且可由攻击者自行重算的“信任哈希链”。旧合法检查点仍可以认证旧历史，不证明全网最新。

## 已实现的操作

```text
zevune-pool-recovery index --no-real-funds --source <归档绝对路径> --checkpoint <独立保存的240位小写十六进制检查点>
zevune-pool-recovery locate-height --no-real-funds --source <归档绝对路径> --checkpoint <检查点> --height <1至当前tip>
```

`index` 返回完整 JSON 索引报告；`locate-height` 返回准确的一条记录。两者都先完整校验归档，程序不创建或改写文件，不向归档目录添加 `INDEX`，不污染原有严格文件集合。高度要求规范十进制表示，拒绝负数、零、前导零、加号、空白、溢出和超出 tip。

JSON 格式为 `zevune-backup-index-1`，包含完整原检查点、创世头字节数、1 MiB段尺寸、全体记录数和记录数组。记录字段为 `height / offset / length / first_segment / last_segment / first_segment_offset / last_segment_end / before_app_hash / after_app_hash`。首尾段编号从0开始，`last_segment_end` 是尾段中的排他结束偏移；恰好结束于段边界时等于1048576，而不是后一个不存在分段的0。

成功保留 `replay_verified:true`，并明确 `finality_verified:false / validator_ready:false / real_funds_allowed:false`。报告全部构造成功才输出，最大缓冲区5 MiB；stdout 写入失败返回非零退出。报告只是检查时的历史导航元数据，之后改变路径不会使报告自动失效；任何后续恢复仍走正常实时校验。

没有实现持久索引导入、`verify-index`、跳过历史的随机状态恢复或增量备份。不要把 stdout 报告放进原归档内部，也不要把报告当恢复输入。未来若增加缓存格式，仍必须有明确失效和重新验证规则。

## 成本、边界与测试

第一次打开建立索引仍需完整文件检查和真实重放；同一已生成的 `VerifiedIndex` 中，由于高度从1连续到tip，查询直接按数组下标定位，时间复杂度O(1)、无文件I/O。每次独立运行 CLI 都重新验证，不承诺CLI启动、全量恢复、证明生成或到账更快。索引至多10000项；现有64 MiB账本、每块16笔等限制不变。状态摘要仍有累计集合遍历成本。

覆盖两种创世头、空历史、高度上下界、非法元数据、7200个真实空记录跨1 MiB边界、恰好位于边界的末字节、全部高度位置一致性、有效前缀之后的错误后置状态、重算普通哈希的真实坏签名和原付款双花拒绝。命令行回归校验输出字段、错误参数、目录不变和损坏源拒绝。故障读取、路径替换和原非零付款/跨段证明回归保留。

这些是测试范围，不是执行结果或审核结论。准确源码的测试输出、作者冻结后复核和独立代理意见应分别记录。Linux自测不代表Windows原生验证；作者复核、CI、代理审核均不等同于专业外部安全审计。

上游读取语义依据：Rust `Read::read_exact` 对短读与 Interrupted 的处理，以及真实EOF不等于已读长度；详见 https://doc.rust-lang.org/std/io/trait.Read.html 。
