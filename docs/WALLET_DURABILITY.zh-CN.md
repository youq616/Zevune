# 钱包保存、待发送交易与恢复（M8.1）

本模块仍是无价值测试资产的本机实验，不是完整钱包应用或主网。用户无需重复安装、手工测试。首次加入的源码须以对应提交的真实 CI 结果验收；本文件不是测试结果。

## 接口与支付边界

Rust 接口为 `wallet::vault::store::WalletStore`。它持有排他文件锁和只读钱包视图，不暴露可修改的内部 Wallet。`prepare_payment` 本地生成、校验真实证明后，把私密状态和完整签名交易写入同一个加密日志记录并检查 `sync_all` 的结果，成功后才返回 Payment。没有 HTTP、联网、自动广播、任意发行或跳过验证开关。

`sync` 仅接受现有 PoolStore 重新验证得到的历史，不能把远程节点返回的任意余额当作可信状态。恢复后的钱包需重新扫描才能显示余额或取回待发送交易。`pending_payment` 返回保存过的同一组交易字节，不重新选择资产或再次签名；网络超时本身不会解除预留。已确认花费或已确认高度超过交易有效期，才由现有同步逻辑释放/清除待发送状态。

M8 原始 Wallet 仍是低层内存 API；保存后返回的顺序由新的 WalletStore 接口保证，不能宣称所有未来调用方式天然获得相同保证。

## 文件格式与资源限制

`ZVWJNL01` 头包含固定网络摘要和随机日志标识。每个固定长度记录包括顺序号、前记录摘要及加密状态。加密使用已有上游 Argon2id/XChaCha20-Poly1305 组件。日志头、序号、前记录摘要通过附加认证数据绑定，不只依赖可被重新计算的 SHA-256 校验和。

加密明文固定填充到 32 KiB，包含种子/检查点/资产预留与签名交易；不会明文写出金额、私钥或待发送交易字节。文件长度、更新时间和记录数量仍能被本机文件观察者看到。固定长度不是网络匿名性保证。

每个记录 32948 字节，头 72 字节；最多 256 个记录，总上限 8434760 字节。打开时有界扫描公开校验链，只对最后一个记录执行密码派生与认证解密；最后记录的认证前驱摘要绑定整个历史前缀。同步同一个检查点且状态没有变化时不新增记录。达到容量上限后不自动删除旧记录或静默重置；压缩迁移尚未实现。

已有 620 字节的 `ZVWLT001` 备份结构和无额外绑定的认证语义保持不变。新日志不能被当作旧快照打开。导入旧快照必须创建新文件；旧快照保存了预留但不含待发送字节时返回明确的 MissingOutbox，不擅自释放资产。新 `backup_new` 复制完整加密日志，包含待发送字节且拒绝覆盖已有文件。

## 故障语义

任何写入/同步失败使当前 WalletStore 不再提供钱包视图、待发送交易或继续写入。写入失败不能被解释为磁盘一定没有记录：模拟“完整写入同步后确认丢失”的情况下，重开需要按完整记录重新判断。中途只有半条记录则拒绝打开，不自动截断修复，不回退旧快照并继续付款。

操作前检查文件链与本进程记住的已保存摘要。`StoreReceipt` 是本地文件历史检查点，不是区块最终性证明。只有将它保留在独立可信位置，才能检测完整旧日志被回滚；没有外部检查点时，合法旧前缀仍可能通过验证。旧检查点可以认证合法后续记录，不要求永远锁死在旧末尾。

## 操作系统与未实现保证

文件排他锁用于协作进程间互斥。目录必须可信、权限适当；这不是恶意本机管理员防御，也不能消除目录替换、硬链接或文件系统时序竞态。Unix 新文件模式为 0600 并尝试同步父目录；Windows 检查文件同步，但没有实现等效的目录同步和专门 ACL 配置。不能据此宣称任意断电恢复。

多个备份副本的锁相互独立，不允许把备份当作多设备并发钱包。口令缓冲区随实例保留至释放，采用 Zeroizing 管理；上游中间副本、换页、核心转储及被攻陷设备的内存擦除不在保证中。

所有故障注入仅在 `cfg(test)` 编译范围。运行代码没有开放故障或模拟验证开关。测试用非空创世仍只存在于私有测试代码中；四节点网络仍是 M7 零金额交易范围，非零金额多节点整合尚未完成。

## 验收范围

新增测试针对排他锁、重开、备份不覆盖、完整旧前缀、改写校验链后的认证失败、部分写入、确认丢失、长度及填充边界、旧快照导入，以及真实付款的加密待发送恢复。实际结果须查本提交 CI，测试耗时不代表付款 p95 或 TPS。

上游接口依据：Rust std::fs::File 的 try_lock/sync_all 文档；RustCrypto chacha20poly1305 0.10.1 的 Aead/Payload 接口。没有引入新的密码算法、证书、依赖版本或全网查看密钥。
