# 离线证据包接收桌面 v1

C32为C31交接包提供接收端流程：独立摘要核验、完整清单确认、明确还原到新目录，以及对已有目录的
独立只读核验。不是钱包恢复、任务执行、自动安装或发送端打包界面。全部旧CLI、桌面和格式保持不变。

## 启动与操作

需要可信Python 3.10+及Tk，不需要Git、Rust、原生后端或钱包密码。仓库根目录启动：

```powershell
python .\scripts\ledger_query_bundle_receive_desktop.py --no-real-funds
```

独立源码包将scripts换成runtime。四项输入：操作、包绝对路径、独立保存的包SHA256、目标目录绝对路径。
操作必须明确选择：`unpack`创建全新目录；`verify-directory`只读核验已有目录。选择包只填路径，不读取、
不计算可信摘要；目标路径需要明确输入，所有父目录应已存在。包必须位于目标目录之外。

点击核验清单后，只读取完整包并检查目标存在性及父目录，不写文件。确认页显示原包路径/摘要、目标、
所选操作、全部最多32个文件的编号名称/类型/字节数/摘要/查询ID数量。默认取消；回车不直接执行。
包里包含完整公开查询资料，十六进制不是加密；清单显示摘要和数量，不显示全部交易ID。

明确确认后只启动一项非daemon工作任务。还原使用原C31 `unpack`，目标已有空目录也拒绝；核验使用原
`verify_directory`，不删除/补齐/修改任何文件。结果回执逐字段严格匹配原包清单，布尔与整数不得互换。
复制按钮只复制当前已核验包摘要，不复制本机路径，不自动打开目录、任务、查询或钱包。

## 确认与失败边界

用户确认绑定核验时的包字节/文件身份及目标父目录；只读目录核验还绑定该目录自身身份。开始执行前
再次复核，操作结束后继续检查审核时的包、目标父目录及已核验目录。即使包内容相同，新文件身份也
要求重新审核。原C31仍负责还原阶段的字节/身份/完整清单及独占创建，本层不另写解包或JSON解析器。

所有输入在确认、发布结果、复制时重新同步，绕过变量通知也不能复用旧确认。运行中修改输入撤销显示，
但已明确启动的操作仍会完成原路径的写入/核验，不能把失效显示当作写入被取消。错误提示始终提醒
保留新目录及可能的部分文件；不自动回滚、续装或重试。完整残留可明确选择verify-directory另行核验，
成功只代表当前字节匹配，不证明过去某次还原调用正常结束。相同包也不能复用旧任务执行权限。

显示的“还原调用完成”来自本次原函数正常返回；核验模式不推断过去操作。若最后回执/显示失败，文件
可能已经完整存在。原目录/文件保护、原件存在性未验证、签名未验证、账本未重放、禁止真实资金等
C31标志均保持。成功后的文件变化不持续监控，复制的是本次观察到的包摘要，不是签名或付款凭证。

## 线程、关闭与限制

复用现有LedgerJob的准入、启动中断撤回、完成事件与实际线程退出双条件，以及原计时回调票据管理。
不修改共享模块全局函数。工作线程不调用Tk；只有明确确认才开始还原/核验。关闭等待原任务实际退出，
不强杀线程；重复关闭只能恢复同一任务的观察。未知启动状态或持续Tk错误可能需要结束本应用进程，
不能保证任意异步异常下资源全回收。强行退出可能留下部分写入，必须保留并独立核验。

核验清单阶段在主线程同步读取最多1,100,000字节的包；文件系统阻塞可能暂停GUI，不承诺硬截止。
确认后的写入/核验在工作线程，但操作系统IO本身仍可能长期等待。本模块没有新增原生执行预算。
沿用可信本机/解释器/目录且停止外部写入的前提；无全程锁、跨目录原子快照、恶意文件系统/时间戳恢复
防护、目录fsync、完整Windows ACL或物理断电保证。POSIX权限请求和文件fsync均由原实现执行。
