# 核查桌面离线校验安装器 v1

这是 `inspector_source_bundle.py` 的后续模块：从已收到的固定源码目录安装到一个全新目录，
不需要 Git、Rust、Tk、联网或钱包。只复制经过独立清单摘要核验的字节，安装完成后再次核验。
它不覆盖旧版本、不运行安装脚本、不自动启动桌面、不注册服务、不修改 PATH 或注册表。
这是 NO-FUNDS 源码安装候选，不是原生安装器、签名发布、安全审计或真实资金使用授权。

## 安装前的输入

使用可信 Python 3.10+。从可信来源取得两份工具文件 `inspector_source_install.py` 与
`inspector_source_bundle.py`，将它们放在同一个可信工具目录。不要运行收到的待验证目录中自带的
所谓校验器。工具和解释器自身、操作系统、目录父级必须可信；使用前停止源和目标的其他写入。

收到的输入目录必须是原 `zevune-inspector-source-1` 格式：九份 Python 运行源码、原桌面指南、
一个 `INSPECTOR-SOURCE.json`，不多不少。每个 payload 上限512 KiB，总计4 MiB，清单32 KiB；
本模块不改变这些限制。输入是已解包的目录，不直接解压 ZIP/TAR，也不下载缺失文件。

同时独立取得40位小写完整源码提交号和64位小写清单 SHA256。不能从收到的清单自行算摘要，
再把它当作独立信任依据。清单摘要不是代码签名；源码提交、树和文件的来源仍依赖可信构建过程。
校验器不向 GitHub 查询，也不证明清单声明的 Git 历史成员关系。校验不是代码已经获准执行。

## 两个命令

在可信仓库根目录的 Windows PowerShell 中：

```powershell
$source = 'C:\ZevuneReceived\inspector-source'
$target = 'C:\ZevuneInstalled\inspector-test-v1'
$commit = '<独立确认的40位小写源码提交号>'
$pin = '<独立取得的64位小写清单SHA256>'
python .\scripts\inspector_source_install.py --no-real-funds install --bundle $source --destination $target --source-commit $commit --manifest-sha256 $pin
```

源和目标必须是绝对路径，UTF-8表示不超过4096字节，不接受 `..`。目标父目录预先存在，目标目录
本身必须不存在；已有空目录、文件或悬空链接也不覆盖。目标不能位于源目录内部。
目录和父级不能是符号链接或 Windows reparse point；payload 必须是单一硬链接的普通文件。
Linux 命令相同，换用绝对 POSIX 路径。安装只用 Python 标准库，不调用 Git 或原生后端。

成功输出一行 JSON；必须同时检查正常退出码0。`installed:true` 只表示本次新目录复制完成并通过
校验，不表示已注册系统软件、已启动桌面、可使用真实资金或通过独立审查。`accepted`、
`real_funds_allowed`、`automatic_launch`、`payload_executed` 和 `code_signature_verified`
保持 false。工具不从清单推导“最新版本”，操作者必须明确指定受信任的版本。

再次验证已安装目录：

```powershell
python .\scripts\inspector_source_install.py --no-real-funds verify --bundle $target --source-commit $commit --manifest-sha256 $pin
```

此命令不修改目录、不导入其中代码、不运行 Git/Tk/后端；也不宣称该目录一定是本安装器创建的。
所有参数采用完整名称，不接受缩写；`--no-real-funds` 必填。返回码：成功0，失败1，参数错误64，
用户中断130。错误采用固定提示，不回显路径、参数值或底层异常。无自动重试。

## 数据与失败语义

安装前完整验证外部摘要和固定文件集合，随后再次按原清单的长度、SHA256与Git blob ID捕获
有界字节及文件身份。全部捕获成功后才创建目标；源的正常变更或错误摘要不能留下“成功安装”。
写入使用仅创建模式，完整处理短写，每份文件执行原有fsync。原始清单逐字节最后写入，不生成
替代清单，不重新赋予信任。源在复制期间、写入清单前以及末尾重复核对；最后完整核验目标，
并检查源的元数据没有在目标核验期间变化。目标目录替换被检测后停止，不删除替换后的目录。

POSIX 新目录请求0700、新文件请求0600；Windows权限遵循原创建API和父目录，**不声明完整ACL
加固**。不更改已有源文件或旧安装的权限。原路径/句柄元数据分别核对各自基线，保持原Windows
兼容规则。普通路径身份复查不是全局锁、跨目录事务或抵抗恶意操作系统/文件系统竞态的保证。

任何失败保留已经创建的目标，不删除、不覆盖、不自动续装。清单尚未完整写入时，原校验器通常
不能验证该目录；若故障发生在完整写入之后，可能留下能够独立校验的完整副本，**这仍不等于
发生错误的那一次调用成功**。需要保留记录并明确重新核验，不能依据一个“成功”文本片段判断。
本模块没有目录fsync、物理断电安全、磁盘空间预留或整项硬截止时间保证。

安装后的变更不受本次校验保护；执行前须重新核对所需来源、验收状态与后端。产品安装器不自动
执行任何源码。另行启动核查桌面仍需要Python/Tk及独立核验的原钱包后端，具体边界见原桌面指南。
共享源码继续包含原有命令行能力；只读约束针对核查桌面入口，不是所有共享脚本都失去了写入接口。
不将新源码塞进原v2-v9精确文件清单目录；这些旧包合同完全保持。

## 测试与验收

`test_inspector_source_install.py` 使用真实Git构建的源码fixture、真实文件和CLI进程，覆盖
创建/复验、篡改、错误版本、已有目标、目录替换、链接、短写、写入/同步失败、末尾源/目标变更、
中断及异常脱敏；不替代任何钱包密码学认证。故障注入只制造错误或并发变更，不产生接受型后端。

`check_inspector_source_install.py` 是显式测试驱动，不是产品安装器。它在临时目录构建、通过
真实CLI安装和复验，然后仅删除自己创建的输入fixture，以证明安装目录可以独立运行。测试进程
严格绑定全部九个运行模块来自安装目录，执行原真实Tk回归，之后逐字节复验。传入 `--backend`
时再执行原六组真正钱包认证/预留保持场景；不传入时明确记录原生部分未执行。
新Windows/Linux工作流必须传入原后端；既有工作流和预算不改。

沿用C9对C8交付工作流路径检查的修复：Git路径比较统一使用 `as_posix()`，不删除依赖断言；
本模块继续运行Windows路径表示回归，它在Linux也可执行，但不替代真实Windows原生验证。
本候选需准确提交的双平台原生CI和非作者独立复审；作者复核、代码已实现和CI配置不等于验收。
Issue23、Issue37、P2/P4整体状态不因本模块而关闭，`real_funds_allowed=false`。

接口依据：Python官方 pathlib（PurePath.as_posix、is_relative_to）、os（lstat/open/fsync）文档。

## 与接续基线整合

本模块接入时保留 C9 的全部路径表示与恢复超时测试修复，不用上轮 C8 上的单行修复覆盖它们。
安装集成驱动在运行界面前逐字段核验真实 CLI JSON 回执，提交、树、清单摘要、所有安全标志和
类型必须与独立构建结果一致，拒绝重复键、额外字段、缺失及超长输出。该核验不是钱包认证替身。
测试子进程显式使用 `-I -S -B`，分别隔离环境/用户路径、禁用 site 启动和字节码写入；在导入
原运行模块前核对这些标志。仍须信任解释器、标准库、本机与原生后端，不把隔离参数称作安全沙箱。
这些参数仅用于集成测试，不改变用户正常启动命令或原钱包桌面代码。
