# P2：有界账本容量预检查

状态：阶段候选，需独立代理审核。仍是无价值测试资产的本机实验，未完成长期存储、日志分段或快照扩容。

## 修复的问题

基线`3d01ce1`在正式`commit`中才检查64 MiB日志上限，`prepare`与提案筛选不检查该字节容量。于是候选可能通过预执行，之后在写盘前因既有容量上限被拒绝。此检查虽避免了越界写入，却把可预知的失败推迟到了更后的共识调用阶段。

本次把**已有的逻辑日志上限**放到共同的容量计算函数中，在预执行和提案筛选时使用，正式提交仍重复检查。它不是磁盘剩余空间查询，也不能承诺未来的write/fsync成功。

## 精确计费

既有日志块记录的固定开销是150字节：4字节记录长度、114字节固定正文、32字节校验和。每笔交易除原字节外还占4字节长度字段。因此：

```text
新的日志长度 = 当前长度 + 150 + Σ(4 + 交易字节数)
```

减法均检查下溢，交易数量/大小仍受原上限约束。编码器输出与容量预测在提交前再比较，出现偏差时拒绝而不写入。空区块也必须能够容纳150字节，不会把空候选当作没有任何存储成本。

提案筛选分别保留两个预算：ABCI传入的纯交易字节预算、实际日志记录预算。每个候选只有通过真实授权及全部状态检查后才扣除预算；无效签名、重复花费或过大的候选不会占用后续有效候选的额度。仍只查看最多64个候选、最多选择16笔，位图索引保持不变。

## 验证方法与限制

测试构建允许把一个存储实例的容量**调低**，在真实临时文件上触发边界；运行构建没有此字段、没有相关命令或环境变量，也不能藉此提高64 MiB上限。真实付款测试使用现有Orchard证明与签名，不用合成哈希替代。

新增测试覆盖精确边界、差1字节、每交易4字节长度开销、空块、非法长度/数量、溢出、正式提交重复检查、拒绝后状态及文件不变、实际付款筛选、落盘、重开与重复花费拒绝。降低容量的测试不等于真实填满64 MiB，不等于操作系统磁盘满或实际断电试验。原磁盘错误处理和真实证明检查保持。

交易/日志编码、签名域、费用和已提交状态摘要没有更改。本次会提前拒绝超过既有日志上限的候选，不能将这种调用时机变化说成所有新旧节点组合都已通过共识兼容验收。没有开放新IPC操作或公共RPC。

到达上限后仍需要停止该有界实验网络；本次不让节点越过10000条记录、65536个承诺或64 MiB上限，也不通过删除历史恢复运行。日志分段、可信快照及长期增长仍是后续P2工作。
