# P2：经过真实重放校验的离线账本备份与恢复

状态：本机、无价值测试资产的开发功能。它复制现有完整账本，**不是状态快照、快速同步、裁剪或账本扩容**。旧交易、日志、IPC、共识规则及容量常量不变。

## 实际入口

`zevune-network storage-copy` / `Network.CopyStorageAtCheckpoint` 使用已有固定 Rust worker。备份和恢复是同一项仅创建新文件的操作：备份时从已有账本复制到新备份文件；恢复时从备份复制到新的工作账本。不在原文件上修复、截断或覆盖。

```text
zevune-network storage-copy --no-real-funds --worker <真实worker绝对路径> --worker-sha256 <可信摘要> --config <network.json绝对路径> --config-sha256 <独立保存的配置摘要> --journal <源账本绝对路径> --output <尚不存在的目标绝对路径> --expected-height <独立保存的准确高度> --expected-app-hash <独立保存的准确AppHash>
```

检查点两个参数必须同时提供；高度0是明确的创世检查点。空参数、缺失、重复、错误网络和未知格式拒绝；本命令没有 `--create`、RPC或签名功能。源文件和目标的父目录必须存在，路径须为规范绝对路径。目标已经存在（包括符号链接、目录或源文件本身）一律拒绝。目标所在文件系统必须支持硬链接，不支持时失败，不退化为可能覆盖文件的操作。

## 发布顺序与故障行为

1. 源文件使用真实 Rust worker 获取现有独占锁、完整重放，并与调用者的准确 Height + AppHash 比较。源文件正被节点持有时失败。错误源或错误检查点不创建目标。
2. 关闭源 worker 后，在目标父目录下创建私有随机临时目录，将完整文件有界地流式复制到新临时文件。检查文件身份、长度、修改时间、SHA-256以及文件同步结果。源文件不写入、不改权限。Windows独占锁使源 worker 与复制读句柄不能同时使用，因此本操作**不宣称跨越复制阶段持有源锁，也不是热备份**。
3. 对这个实际临时副本再次启动真实 worker，完整解析、验证所有证明/签名和状态转换，再次匹配调用者独立保存的检查点。第一步检查或文件校验和不替代这一轮验证。即使攻击者修改交易后重算记录校验和和文件摘要，也不能跳过真实重放。
4. 复核副本字节和源元数据之后，以不覆盖的硬链接将**独立临时副本**发布到目标名。它不是把原账本硬链接到备份名；修改恢复文件不会改变原账本或备份。目标名不会先出现一个正在逐步写入的文件。与其他进程同时争用同一目标名时，不覆盖先存在的目标。
5. Linux等适用平台同步目标父目录。Windows只报告实际执行的文件同步，`directory_synced:false`，不伪造等同于Unix目录同步的保证。仅删除本操作自己的两个精确临时路径，不删除目标或用户数据。进程被强杀仍可能留下 `.zevune-copy-*` 临时目录，不能把这些文件当作已完成备份。

发布动作发生后，目录同步、取消或输出失败都会被视为结果不确定。部分文件系统可能执行了元数据操作却丢失确认；因此非“已存在”类型的发布错误也不能被解释为目标必定不存在。错误情况下不输出成功报告，不删除目标、不自动重试。保留原账本及独立检查点，对目标执行 `storage --expected-height ... --expected-app-hash ...` 核验后再决定如何使用。

## 检查点与保证范围

检查点应来自此前可信验证并独立保存的状态，而不是从待恢复文件读取后原样传回。它验证准确状态，不保证全网最新性、祖先关系或独立共识；较旧的合法完整前缀和比准确检查点更新的文件同样不匹配。备份文件的SHA-256是完整性标识，不是代码签名或共识证书。

结果包含高度、AppHash、字节数、文件摘要和实际同步状态。`expected_checkpoint_matched:true` 表示此次源与实际副本均匹配了给定检查点；`consensus_verified:false` 与 `real_funds_allowed:false` 始终保持。密码、私钥、查看密钥、钱包待发送预留都不进入命令或备份内容。

**只备份应用账本不等于完整验证者灾难恢复。** 本工具不复制 CometBFT 共识数据库、验证者密钥、节点密钥或签名历史；尤其不得用旧签名状态恢复同一验证者密钥或同时启动两个签名实例。参考账本恢复后可继续按原受验证同步流程使用；验证者恢复还需单独的共识/签名状态一致性流程，本阶段不提供。

测试包括真实A→B后复制、从备份恢复为另一个文件、拒绝重新花费、继续真实B→C、重开状态一致；错误检查点、旧前缀、既有目标、活跃文件锁以及改签名后重算校验和的副本拒绝。普通文件系统测试中的字节样本不被当作有效Orchard资产。短时测试、文件同步和代理审核不代表任意硬件断电安全或独立机构审计。

目标目录及其祖先、内核、存储固件和当前用户环境仍是信任前提；元数据比较不保证抵御恶意主机的同长度/同时间戳替换。正常文件复制不是隐私传输机制，也不解决长期增长或网络匿名。

上游语义依据：Go `os.Link`、`File.Sync`（https://pkg.go.dev/os）；Microsoft `CreateHardLinkW`（https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createhardlinkw）。文件系统不支持要求的操作时拒绝，不改用覆盖式重命名。
