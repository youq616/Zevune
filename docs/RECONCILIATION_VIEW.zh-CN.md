# 付款对账结果查看器 v1

本模块补齐 P4 中“恢复结果如何核对和查看”的入口。它读取已有 `wallet_reconcile.recover` 输出的
目录，不创建钱包、不再次恢复、不签名、不广播、不清除预留，也不会自动重试支付。支持命令行
JSON/中文文本与 Windows/Linux Tk 桌面。始终 NO-FUNDS，不允许真实资金。

## 使用的独立输入

需要恢复结果目录、恢复成功时通过独立渠道保留的 `report_sha256`、独立账本检查点和网络摘要。
不要从待核验目录自己计算报告摘要并赋予信任。检查点采用原 ZVARCP01 完整256位小写十六进制
字符串，网络和报告摘要均为64位。目录必须为绝对规范路径，禁止链接/reparse父级与文件。
工具从可信仓库单独运行，不复制到旧v2-v9包或原固定10文件源码交付目录中；原精确清单不变。

```powershell
python .\scripts\reconciliation_view_desktop.py --no-real-funds
```

桌面填写四项输入后点击“核验并查看”。没有密码、后端或自动付款入口。选择文本不会自动接管
X11 PRIMARY；交易ID只有显式点击复制按钮才写入剪贴板。输入修改立即使旧结果失效；失败也清除
旧结果。关闭和清除显示不删除文件，不擅自清空系统剪贴板。输出回执和交易ID可能关联钱包，请
保护屏幕、终端输出和剪贴板记录；不输出种子、私钥、余额、地址、支付金额或交易原始字节。

命令行可供本地自动化读取：

```powershell
python .\scripts\reconciliation_view.py --no-real-funds --directory 'C:\Zevune\recovered-result' --report-sha256 '<独立64位摘要>' --checkpoint '<独立256位检查点>' --genesis-sha256 '<独立64位网络摘要>'
```

添加 `--text` 输出中文说明，默认输出JSON。正常成功需要退出码0；错误1、参数错误64、中断130。
普通 `--help` 无需 Tk/显示环境。Python 3.10+；桌面另需Tk。没有安装额外第三方库。

## 核验内容和状态含义

先完整检查所有字段，再读取上限4 KiB的原 `RECONCILE.json`。核对独立摘要、规范JSON、重复字段、
精确字段集合和字面布尔标志，绑定外部检查点/网络，检查报告高度与回执代数关系。目录只能包含
`RECONCILE.json`、`wallet.journal`，以及报告明确pending时的 `pending.tx`。

钱包继续使用原 ZVWJNL01 公开链核验：原72字节头、32948字节记录、最多256次保存。既检查副本
精确末端回执，也检查报告中的独立祖先和源末端确实在该公开链中。对交易文件检查原上限32768
字节、原LAB2头/网络及完整文件SHA256。只读取原头40:48的到期高度，不另造Orchard解码器。
前后重读字节和文件身份，末尾核对精确目录项、各文件元数据与父目录链；普通变更使本次核验失败。

“保留待发送文件”只表示文件集合与固定报告一致，广播和结算仍未知。“没有待发送文件”不能区分
已在历史中入账、已到期或本来没有交易；绝不显示“已付款”。到期比较仅针对报告绑定的**历史检查点**，
不是当前链高度。同高尚未超过到期高度，与原pool的 `< height`规则一致；若文件早于检查点到期，
只给警告，不授权重签或清除预留。没有文件时不猜测到期原因。

机器结果固定保留 `wallet_authenticated=false`、`transaction_authorization_verified=false`、
`ledger_replayed=false`、`finality_verified=false`、`retry_authorized=false`、
`settlement_status="unknown"`、`current_chain_height=null`、`real_funds_allowed=false`。
原报告中的source_retained是历史记录，不被升级为本次实际检查原钱包还存在；对应新标志为false。
**本模块不解密钱包、不验证交易签名/证明、不读取或重放账本，不证明原恢复操作曾成功退出。**
即便某次失败调用留下了完整可核验文件，它也只能通过本次文件检查，不能据此倒推原调用成功。

## 运行边界

只接受操作者选择的可信本地文件目录；应停止其他写入，不使用远程共享、映射网络盘或不可信主机。
没有应用级网络查询接口；操作系统文件系统仍可能阻塞。桌面采用同步的有界文件读取，不创建后台
线程或嵌套事件循环，因此磁盘阻塞时界面也会等待，不承诺硬实时截止或强制取消。输入总量上限
沿用原钱包和交易格式；没有全局锁、跨文件原子快照、恶意竞态防护或校验后持续监控。

原钱包生产代码、后端、原对账格式和旧安装/打包清单均未修改。本模块不自动认可已有候选、不合并
main，也不解决P2/P4整体、Issue23/37或网络隐私。

## 验证

纯测试使用明确标为未加密/未授权的公开帧，只验证格式和文件一致性；不能当作钱包认证成功替身。
真实Tk覆盖显示、错误清空、输入失效、显式复制、X11选择区和拒绝重入。原生驱动先调用完整不变的
原Rust恢复测试，再读取实际生成的pending/empty/included/expired四种结果，并验证新增桌面、交易
篡改拒绝和文件字节不变；不替代任何原验证器。新双平台CI重建原钱包/worker/recovery，预算保持
20分钟作业、600秒原生监督。执行结果必须对应准确候选；配置存在不等于执行通过。

JSON重复字段拒绝依据Python `object_pairs_hook`，Tk调用语义参照官方文档：
https://docs.python.org/3/library/json.html
https://docs.python.org/3/library/tkinter.html#threading-model

## 命令行编码

JSON和中文文本的正常CLI输出均显式使用UTF-8字节，重定向到文件或管道时不依赖Windows系统
代码页；消费者应按UTF-8解码。嵌入调用传入无buffer的文本流时沿用该文本流策略。写入或flush失败
仍返回失败；不能只凭部分输出判断成功，必须同时核对正常退出码0。源码检查显式按UTF-8读取，
不通过更换runner默认编码或跳过Windows绕开检查。cp1252重定向与源码默认编码回归在各平台执行。

## 检查点承诺与签名域不是同一个摘要

ZVARCP01的8:40字段是账本状态的创世承诺，来自原PoolStore状态；`genesis_sha256`是原创世文件的
SHA256，也是LAB2交易的签名域。两者分别由调用者独立提供，并与固定报告逐项核对，不要求互相相等。
交易头必须匹配创世文件摘要，不能替换为检查点创世承诺。本查看器不读取创世文件或重放账本，不能
另行证明这两个独立输入的协议关系；输出明确 `checkpoint_domain_relation_verified=false`。
普通测试刻意使用不同值，原生测试也要求真实恢复fixture覆盖这种区别。完整报告摘要仍必须来自
独立信任渠道；任何替换检查点、报告网络或交易签名域的单边变化继续被拒绝。
