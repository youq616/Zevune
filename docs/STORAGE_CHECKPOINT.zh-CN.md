# P2：离线账本检查的独立检查点约束

本功能接续离线容量检查。仍限无价值资产实验，不扩容账本，不导入快照、不裁剪历史，不替代共识验证或生产存储审计。

## 为什么需要独立保存检查点

一个较旧但完整的合法账本副本，可以通过全部交易签名、状态和日志校验。仅检查文件能否重放，不能判断它是不是调用者原本要恢复的版本。现在允许在检查前提供独立保存的**准确高度和应用状态摘要**；两者都匹配才输出成功报告。

实际路径为：命令参数检查 → 独立固定的网络配置/创世/worker核对 → 原独占锁和真实Rust完整重放 → Status → 文件前后检查及worker关闭 → 高度与AppHash精确匹配 → 容量报告。没有根据候选文件自行生成“期望值”，也不向不可信服务端索取检查点。Go接口按值复制检查点，不能在重放期间被调用者改写。

```text
zevune-network storage --no-real-funds --worker <worker绝对路径> --worker-sha256 <可信摘要> --config <network.json绝对路径> --config-sha256 <独立保存的摘要> --journal <已有离线账本绝对路径> --expected-height <准确高度> --expected-app-hash <独立保存的64位小写十六进制摘要>
```

两个新增参数必须同时提供。高度必须是无符号规范十进制，在当前0至10000范围内，`0`是明确的创世检查点，不代表未启用检查；前导零、正负号、空白、十六进制形式和超限值被拒绝。摘要必须是非零的64位小写十六进制字符串。输入长度在解析前受限；重复参数、空参数及其他命令使用这两个参数均拒绝。

`InspectStorageAtCheckpoint`是相应Go调用入口。参数验证在配置读取、进程启动和账本访问前完成。普通`InspectStorage`保持不要求检查点的旧行为，仍不声称知道数据最新性。

## 返回语义

带检查点且匹配时新增`expected_checkpoint_matched:true`；未传两个参数时明确输出`false`。此布尔值只说明与调用者给定值相等，**不认证调用者给定值本身**。不匹配时返回失败，不输出部分容量或成功JSON，不修复、截断、创建或改写账本。

以下字段的原语义保持不变：`scope:offline_replayed_journal_capacity_not_finality`，`consensus_verified:false`，`network_accessed:false`，`real_funds_allowed:false`。合法证明、摘要相等和容量充足都不是本次操作中的共识最终性或支付许可。

检查的是**准确的最后状态**，不是“高度至少达到某值”，也没有证明新账本继承较早检查点。因此，更新的合法账本对旧检查点同样返回不匹配。该限制是显式的；不能为了接受更新文件而静默忽略摘要或降低为高度比较。

检查点应在已信任的验证流程中事先留存，并与待检查副本分开保存。例如，独立验证过的参考账本同步结果可用于留存准确高度和应用摘要，且仍须保留其网络配置身份。直接从同一未验证文件读取高度/摘要，再拿来检查该文件，并不能防回滚。应用摘要在现有账本实现中绑定创世身份和完整状态；本功能不更改其计算。

## 测试与限制

普通Go测试覆盖规范解析、两参数配对、创世高度、最大高度、超限、错误或零摘要、更新/过旧/同高不同状态、容量矛盾、取消和未提供检查点的明确输出；合成状态仅用于边界测试，不当作真实账本。

`operator_e2e`通过真实命令和真实Rust worker验证：创世精确匹配、真实付款后的精确匹配、旧完整合法副本在无检查点时可重放但对新检查点被拒绝，以及同高度不同本地区块历史被拒绝。后一场景使用相同真实Orchard付款和不同本地区块标识，不是部署或攻击真实共识分叉。损坏日志仍被完整重放拒绝，不能凭摘要输入跳过密码学验证；成功和失败后检查文件字节不变。

没有修改Rust、电路、签名域、共识、IPC、交易编码、日志格式、容量上限或钱包预留。尚未实现分段存储、快速快照恢复、跨机器同步或网络匿名。文件锁不协调不同副本；旧检查点也不能代表全网最新状态。恶意操作系统、检查之后替换文件和攻击者同时替换副本与独立信任记录仍在保护边界之外。
