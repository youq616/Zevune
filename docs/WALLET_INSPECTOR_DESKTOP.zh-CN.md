# 只读钱包核查桌面 v1

入口 `scripts/wallet_inspector_desktop.py`。它把已验收的祖先回执认证与容量检查接入 Windows/Linux
图形界面，不是完整在线钱包。仅调用原钱包后端的 **op9**：不扫描历史、不查询余额、不读取/导出
待发送交易、不签名、不广播、不恢复、整理或修改钱包。本模块仍为 NO-FUNDS。

## 启动与独立信任输入

需要 Python 3.10+、Tk 和图形桌面，以及独立核验过的原 `zevune-wallet-local` 程序。
Windows 从仓库或独立源码目录启动：

```powershell
python scripts/wallet_inspector_desktop.py --no-real-funds
```

Linux 命令相同，原生后端没有 `.exe`。不安装依赖、不联网下载，不自动寻找或运行未经批准的后端。
`--help` 不需要 Tk/显示环境；缺少 Tk 或桌面时正常启动会报错，不静默退回命令行密码输入。
源码独立交付，不增加 v10 原生包，不改变 v2-v9 精确清单。不要把新脚本塞进已核验的旧程序包目录。

表单需要：现有钱包绝对路径、独立保存的旧祖先回执或当前回执（144小写十六进制字符）、批准后端
绝对路径及独立 SHA256、明确的磁盘保留字节、预计保存次数（1—256）、记录预警余量（0—255）。
保留量可明确填写0，没有隐式默认资金/容量策略；默认保存1次、预警余量16仅是显示初值。

全部字段先作纯语法/数值/Unicode检查，才允许打开密码窗口，不读取文件以猜测“可信”回执或摘要。
路径与可显示字段拒绝控制/格式字符、孤立代理及行/段分隔符；保留可见Unicode，不保证排除全部
相似字符混淆。路径另检查UTF-8字节限额；原后端继续验证规范路径、文件身份与摘要。

## 确认、密码与执行

点击“核对输入并开始只读核查”后，真实模态窗口完整展示冻结的路径、回执、后端摘要和容量策略。
取消默认获得焦点，Escape和关闭窗口都取消；没有按回车自动同意。输入密码后明确点击确认。
密码保持原控制台的16—1024个UTF-8字节范围，不修剪/正规化，不将长度称为密码强度。

密码框遮蔽字符，禁用正常复制/剪切及选择导出，允许密码管理器粘贴。提交、取消或无效密码后清除
输入框，不保存在表单、结果、日志、配置或最近文件。传给原生程序仍仅走stdin，不进argv或环境。
Tk、Python、剪贴板管理器和操作系统可能保留内存副本；**不保证密码内存擦除或抵抗本机恶意软件**。
输入的源路径、回执及结果也可能被屏幕捕获，应在可信设备与受控桌面操作。

一次只运行一个只读任务。工作线程不访问Tk、不持有控件回调，完成后只向有界队列投递不可变结果
或固定失败标记，异常对象和堆栈不回传UI/日志。主线程以定时器轮询，不能在事件回调里无界join。
原生调用由既有摘要门槛、请求界限和进程清理约束；没有新增后台定时监控、周期任务或自动重试。

执行顺序：原 `authenticate_descendant` 把**外部祖先回执**送入原Rust op9认证当前末端；再以这个
已认证末端调用原 `wallet_health.inspect`，仅通过op9重新认证与容量采样。两次之间及末尾核对
同一源文件完整字节、身份与父目录，避免将不同版本的身份和容量混成一个结果。没有全程全局锁，
使用前必须停止其他写入。身份重查不是针对恶意主机的原子性保证。

## 结果及失效规则

显示已认证回执、保存记录数/剩余次数、文件字节、调用者可用空间采样、采样时间和容量告警。
保存次数不是付款笔数；“本次未触发容量预警”不是“钱包安全”“写入一定成功”或付款授权。
保留既有容量分类与磁盘语义，不采集余额、地址、交易、种子或私钥，不将app hash或本地文件
认证称为最终性。历史未扫描，全局最新、广播结果、结算结果和未来可用空间均未由此确认。

修改任一输入立即清除结果与可复制回执。运行中禁用输入和重复启动；即便程序性输入修改绕过
控件禁用，修订号变化仍使迟到结果被丢弃，不会冒充新输入的结果。出错不会展示旧的“通过”。
“复制回执”必须明确点击，仅复制当前有效结果；不自动复制、不导出报告。清除UI不会擅自清除
系统剪贴板，操作者需要管理剪贴板历史和独立保存回执。
所有可选择输入、冻结确认文本、结果文本和输出回执均禁用自动 selection export；Linux/X11 上
仅选择文本不应接管 PRIMARY 选择区。明确点击复制回执仍只更新 CLIPBOARD，不自动清除其他
剪贴板内容。回归同时检查跨平台控件属性及 Linux 实际 PRIMARY 所有权；不把 Windows 跳过
X11 专项当作该平台执行了 X11 验证。

## 关闭与失败语义

密码窗口在创建任何Tk控件之前，先将空的生命周期对象登记给主窗口。窗口初始化失败、模态等待被
中断，或刚确认密码后等待调用报错时，统一撤回密码引用、清除输入并销毁本次窗口及其局部抓取；
异常路径不启动认证任务、不把遗留密码留给下次操作。若无法确认窗口已销毁，界面保持禁止新操作，
给出固定提示，允许关闭时再次清理本窗口；仍无法关闭时须结束应用进程后重开，不自动开第二个密码
窗口。该处理不声称安全擦除解释器内存，不释放其他窗口的抓取，也不操作已有系统剪贴板。

密码窗口阶段关闭主窗口会取消且不启动认证。任务运行期间关闭只登记退出请求，清除结果并禁止
新操作；窗口保持响应，等**本次任务真正结束**才退出。没有假装取消已运行的原生调用，也不悄悄
让工作线程在界面退出后继续服务。工作线程非daemon，正常退出不依赖强制解释器终止。

线程启动异常另有保守处理：`ident=None` 不能证明系统没有创建线程。工作线程先等待准入信号；
启动失败时撤回尚未交付的密码/意图，迟到的线程只能返回失败，不执行认证。界面仍保留这项启动
记录，禁止第二次任务；只有工作线程明确报告完成后才恢复操作或正常关闭。异常如果实际发生在
系统创建线程之前、因此永远没有完成信号，界面会明确要求操作者结束应用进程后重开，**不自动
重试、不以等待超时伪造“没有任务”**。这是罕见启动状态不确定时的保守停止，不是正常关闭时限。
已经获准的只读调用可能仍在运行，仍需等待其真正收尾。取消未准入请求不等于强制取消原生调用。

窗口关闭等待可能较长：两次认证各沿用原逐调用300秒等待及有界清理，文件摘要/系统IO也可能
阻塞；没有整项硬实时保证。操作系统强杀、断电或恶意后端子孙进程不在正常关闭保证内。程序
不开写入接口，强杀也不自动转换成“认证通过”，下一次需重新核验全部输入。

## 验证和未覆盖边界

定向测试覆盖完整纯语法校验、Unicode和字节界限、隐藏密码长度、固定op9白名单、只拒绝的实际
工作线程和异常脱敏。真实Tk测试覆盖模态取消、密码清除、剪贴板、修订失效、异步事件循环、
重复操作拒绝、构造/启动失败、模态等待中断、部分窗口构造与清理失败及等待关闭，不以这些UI测试冒充密码学认证。针对Python线程启动
边界的测试使用真实OS线程：暂停bootstrap在登记ident之前，并中断父线程的启动等待，检查界面
仍持有任务、关闭等待、迟到线程不执行已撤回的认证。测试会恢复并回收该真实线程，不注入成功认证。

独立真实后端驱动创建无价值测试钱包和签名付款，实际操作密码控件并调用原Rust，核对三档告警、
旧祖先认证、错误密码/摘要/回执拒绝、完整签名字节与预留不变、迟到结果失效、验证后文件变化拒绝
以及真正关闭收尾。签名、扫描和用于测试的字节修改只发生在驱动构造的私有fixture内，产品模块
没有这些接口；正向认证不使用接受型替代后端。

原Rust/Go、加密原语、日志格式、限额、同步/锁、依赖锁、既有工作流和原v9打包合同均不改变。
Windows/Linux准确候选原生CI和另一代理独立审核完成前只能称候选，不能先标记验收。
操作系统ACL、恶意文件系统竞态、物理断电、强制Windows配额和密码内存安全擦除未获本轮证明。
Issue #23、P2/P4整体及外部专业安全审计保持未完成，`real_funds_allowed=false`。

设计依据为现有 `WALLET_RECONCILE.zh-CN.md`、`WALLET_HEALTH.zh-CN.md` 及实际原生接口。
没有引入新密码学。Python官方事件循环/线程资源语义参考：
