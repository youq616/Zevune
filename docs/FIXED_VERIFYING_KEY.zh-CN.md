# 固定公共验证密钥的进程内复用

本合同补充活动归档的验证器生命周期，保持
[活动归档合同](ACTIVE_ARCHIVE_V1.zh-CN.md)和
[精确字节授权缓存](AUTHORIZATION_CACHE.zh-CN.md)的授权与状态边界。
这是固定上游参数的生命周期优化，仍为 NO-FUNDS 实验环境。

## 动机与范围

活动检查点导出、归档验证和复制中的每次完整重放都新建
`AuthorizationVerifier`。旧实现每次也重建同一固定电路的公共验证密钥。
新增归档测试的原生日志显示数分钟额外耗时，源码中重复初始化与此相关；
这不是性能采样对全部耗时的归因。本变更保留所有重放和测试，单独复用公共密钥。

只调整 `wire::AuthorizationVerifier` 使用的固定密钥；不替换 Orchard、
电路、签名算法、证明格式、交易规则或状态机，不接受调用方提供的密钥。
既有证明生成和其他独立校验路径的密钥生命周期不在本变更范围内。

## 不变量

1. `wire` 模块私有的 `OnceLock<VerifyingKey>` 只调用
   `VerifyingKey::build(crate::CIRCUIT)`。当前编译期常量保持
   `FixedPostNu6_2`，依赖锁定版本保持不变。没有外部输入、版本选择开关、
   文件导入或网络获取，也没有其他电路的备用密钥。
2. 每个 `AuthorizationVerifier::new()` 取得该已初始化密钥的只读静态引用，
   同时新建自己独立、为空的 `VerifiedCache`。只复用公共电路材料；不共享
   验证器、成功结果缓存、账本状态、交易字节、见证或钱包数据。
3. `verify` 的顺序保持：完整规范解码、该实例的精确字节缓存检查、全部花费
   签名、绑定签名、上游真实 proof 验证，最后才在该实例记入成功字节。
   每个新实例的首次授权仍真正执行这些密码学检查。账本状态规则继续独立检查。
4. 活动导出、每次显式验证及复制中的源／目标／末次源完整重放保持原调用次数，
   每次仍有新验证器和空缓存。重算 layout pin 后的坏签名仍须拒绝为
   `Authorization`；公共密钥复用不能把旧缓存命中变成新归档的授权证据。
5. 初始化只构建固定上游密钥，不回调本模块的验证器或共享密钥获取函数，避免
   重入初始化。初始化 panic 向调用方传播，不能返回成功或备用验证器；若上层
   捕获 panic，未完成的单元仍不含可使用密钥，后续初始化仅可重做同一固定构建。
6. 密钥作为只读公共材料保留至进程退出；不承诺最后一个验证器释放时归还该内存。
   新进程独立初始化。多线程共享须由实际锁定版本的 Rust 类型约束及原生编译确认，
   不使用 unsafe、可变静态对象、自制同步或全局授权缓存。
7. 将来若改变电路版本，必须重新审核常量与存储单元的绑定。当前实现不提供多版本
   容器，不能在同一个已初始化单元内更换参数或复用旧授权缓存。

## 验收

保留当前全部测试函数、真实付款／证明 fixture、回执失败检查、锁／路径／故障
覆盖、三次生产重放、工作流、并行配置和原有时间预算；不以删除调用换取通过。
既有测试中关于“每个验证器新建密钥”的文字应改为“新实例保持空授权缓存”，
既有断言不得删减。

新增有意义的真实授权回归应核对：正确固定版本的同一只读密钥可由并发创建的
验证器使用；一个实例真正验证有效 fixture 后，其他实例仍无其缓存条目，随后
也须实际验证并独立记入；修改签名或证明的字节仍拒绝且不进入成功缓存。
不使用伪接受器、合成成功条目或耗时阈值代替这些断言。若未单独在新进程竞争首次
初始化，不宣称测试覆盖了冷启动竞争；标准同步原语的语义与实际并发使用分别说明。

对新的准确候选重新做非作者代码审核及双平台完整原生矩阵。此前候选的成功、取消
和重跑均保留为历史，不转作本候选通过。原生耗时只能作为本次执行观察，不能据此
承诺吞吐、归档峰值内存、外部安全审计或生产可用性。

上游参考：此处查阅的 [Orchard VerifyingKey API](https://docs.rs/orchard/latest/orchard/circuit/struct.VerifyingKey.html)
页面标为 0.15.5，说明显式电路版本及 Send／Sync；
[Rust OnceLock](https://doc.rust-lang.org/std/sync/struct.OnceLock.html)
说明一次初始化和 panic 行为。文档说明不替代锁定依赖的实际编译与项目回归。
