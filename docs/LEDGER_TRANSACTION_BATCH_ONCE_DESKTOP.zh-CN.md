# 单遍批量历史核查桌面 v1

本模块把 C24 单遍查询接入独立桌面入口。原 C23 批次桌面保留原 N 次定位及旧结果格式，
不会静默切换算法。新模块不新增钱包、密码学、账本格式或记录解析器，始终 NO-FUNDS。

## 使用

需要可信 Python 3.10+、Tk、独立批准的单链接原生恢复程序及停止写入的本地账本。

```powershell
python .\scripts\ledger_transaction_batch_once_desktop.py --no-real-funds
```

填写账本目录、独立 ZVARCP01 检查点、创世文件签名域 SHA256、原生程序路径及独立程序 SHA256，
逐行填写 1—32 个互异交易 ID。沿用 LF/CRLF 和单个末尾换行规则，不自动修剪、排序或去重。
所有依据应独立取得，不能从待核验文件自行算摘要来赋予信任。完整核对页默认取消，
只有明确确认后才启动一项非 daemon 任务；回车不执行，Escape 取消，不强制抢占其他应用焦点。

一次新的原 verify-active 重放之后，执行一次完整记录定位；前后归档指纹仍另行读盘。
单遍不表示全流程只读一次磁盘，也不承诺固定提速倍数。整批共享原300秒预算，不续期、不重试；
磁盘阻塞及原进程收尾仍可能超过墙钟时间，不保证硬实时终止。

## 显示合同与兼容

仅接受 zevune-ledger-transaction-batch-once-1，history_scan_count 必须为精确整数1。
旧格式、True 冒充整数、未知或缺失字段、乱序/错ID/计数不一致或不完整结果均拒绝。
公开结果必须绑定确认的检查点、签名域、程序摘要和每一个交易 ID。

新显示边界先验证单遍专有字段，再在私有元数据副本上复用原逐行/范围校验器。
这个投影只是元数据校验，不执行第二次查询，不返回或展示伪造的旧格式结果，也不能证明授权。
输入字典不改变，UI只保存不可变的显示文本和ID元组。旧/新显示类型不能交叉获得复制许可。

原批次窗口仅增加三个有原默认行为的扩展点：核对说明、任务创建、显示类型。
新窗口覆盖这些扩展点，不替换共享全局。两种窗口可以并存，各自调用原N遍或新单遍核心。
输入事件同步、任务准入、启动中断持有、实际线程退出、计时器票据、关闭及复制均复用原方法。

没有找到只是指定历史中缺席；原生错误/超时/输入变化是失败，不能混为缺席或部分成功。
历史纳入不是当前共识最终性、结算、收款人或金额证明，后续记录数不是确认数。
钱包认证、收款人/金额、最终性、支付重试和可携带证明标志保持false；当前高度未知，
广播和结算unknown。没有生成付款凭证或可独立转交的纳入证明。

## 操作与失败

确认、接收结果和复制前都同步实际多行内容，即使 Modified 通知尚未处理也不能使用旧清单。
运行中禁止第二任务；错误或输入变化撤销整批旧结果。关闭等待真实任务退出，不假装中止原生调用。
启动状态不确定或计时器失败仍持有原任务，明确关闭可以继续观察，但不会重新执行。
若无法确认完成或Tk持续失败，操作者可能需要结束应用，不以超时伪造已退出。

所有可选择控件禁用自动selection export。明确复制只复制原顺序查询ID，包含缺席项，
不代表重新验证或支付授权。清除或关闭不删除输入文件，也不清空系统剪贴板。
公开回执和交易ID可能关联钱包，应保护屏幕和剪贴板记录。

无密码、签名、广播、恢复、清预留、输入写入、自动安装、持久设置、后台轮询或联网接口。
新目录不得混入旧v2-v9或固定源码清单。源码摘要不是代码签名。
需可信本机/解释器/程序/父目录并停止外部写入；不承诺原子快照、恶意文件系统防护、
全程锁、完整ACL、物理断电或校验后持续监控。P2/P4整体及真实资金禁令不变。

## 验证与验收

单元测试的合成公开元数据仅用于present()，不注入工作线程冒充原生成功。
真实线程检查仅执行原缺失文件拒绝或故障注入，覆盖实际OS bootstrap中断和实际退出。
真实Tk检查完整复用旧窗口场景并补充新旧批次窗口隔离、单遍说明和显示类型拒绝；
旧GUI回归也必须保留，确保默认扩展点不改变既有行为。

新原生驱动运行C24完整安装/恢复/单笔/旧批次/单遍测试链，在四类真实恢复历史使用新窗口。
计数实际verify-active及段解析，要求一次重放和每段一次定位；另检查32项、明确复制、
错误摘要、真实结果迟到失效和关闭等待。原20分钟作业及600秒原生监督不改变。
代码实现与测试配置不是验收；需准确版本的非作者审核与双平台原生执行，不自动合main。

依据为原ledger_transaction_batch_desktop.py、ledger_transaction_batch_once.py及
reconciliation_ledger_desktop.py的实际调用合同，没有引入新协议。
